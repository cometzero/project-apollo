## 3. 남은 이슈와 판단 보류

| 이슈 | 현재 상태 | 종료에 필요한 근거 |
|---|---|---|
| Silicon fidelity | NOT_ESTABLISHED | 대상 CPU/SoC 정보, calibration과 분리된 validation workload, 실측 counter/traffic 비교 |
| 최종 제품 사양 | UNDECIDED | Throughput/latency, 동시 workload, resident memory, PPA/cost 목표 |
| 후보 A/B의 scenario 안정성 | PARTIAL | 후보별 warmup·length 및 필요한 robustness 검사. Baseline gate의 자동 전이 금지 |
| CPU4 baseline 수렴 | Warmup gate PASS, length NOT_RUN | 다음 세션에서 length 측정 |
| Pool1 held-out | Raw pair VALID, convergence 미확립 | Baseline/channels8 각각 warmup·length. 동일 kernel의 footprint 검증임을 유지 |
| L3/SLC 후보 | Warmup FAIL 보존 | 원인 분리와 사전 선언한 재진입 조건. 임의 tolerance 완화 금지 |
| P6 uncertainty | Config-only 검증 | 최종 후보 선택 정책에 따라 latency/network/DRAM 가정 변경의 guest 실행 및 순위 확인 |
| 환경 통제 | Capture PARTIAL, policy NOT_EVALUATED | 필요한 제품 환경 정책 정의와 해당 배치 검증. 현재 kernel은 NO_HZ_FULL 미지원 |
| External IP | CONDITIONAL_NOT_TRIGGERED | NPU/DMA 등 실제 연결 및 traffic envelope 요구가 생길 때 별도 구현·검증 |
| 최종 evidence 통합 | 미완료 | Campaign/inventory/cases/comparison/decision/replay 연결과 전체 requirement audit |

IRQ capture protocol PASS가 모든 kthread의 배치, interrupt-free ROI 또는 WCET를 보장하지 않는다.
4/8-frame 측정으로 p99나 worst-case bound를 주장하지 않는다. Orin reference도 A720AE/Zena
silicon 성능, 안전성 또는 ISO 26262 qualification의 근거로 전용하지 않는다.

[41개 requirement 중간 audit](completion-audit-20261031.md)의 집계는 VERIFIED 12,
PARTIAL 23, 조건부 5, terminal acceptance 미완료 1이다. 이는 **이전 중간 audit의 분류**다.
후속 raw/gate PASS가 추가됐지만 전체 requirement 범위의 재심사를 끝내지 않았으므로
최종 완료율로 해석하거나 개별 완료 결과만으로 자동 승격하지 않는다.

## 5. 권장 후속 작업 순서

1. **진행 중인 두 결과 회수:** terminal 상태를 확인하고 fresh raw/config/model/workload
   검증 receipt를 추가한다. CPU4 warmup 네 gate가 PASS일 때만 준비된 frames8 policy를 실행한다.
2. **Pool1의 네 convergence endpoint:** `V/pool1-convergence/`의 준비된 policy를 사용한다.
   Baseline/channels8 각각 warmup PASS 후 length로 진행한다. 작은 관측 부호 변화의 안정성을 판단한다.
3. **후보 acceptance와 재진입 결정:** A=channels8, B=mesh1GHz의 P5·held-out 결과를
   비교하고 필요한 자체 수렴을 확보한다. 실패·미확립 후보는 근거와 함께 보류하거나 제외한다.
4. **P6 targeted controls:** 후보가 선택되면 `C/reports-v4/robustness-policy.json`에 따라
   uncertainty controls를 수행한다. Config-only PASS를 workload robustness로 대체하지 않는다.
5. **최종 report/replay:** 완료 case를 inventory에 통합하고, 비교·결정·제외 이유와 input
   revision을 연결한다. 41개 ID 및 번호 밖 deliverable을 다시 audit한다.
6. **제품 의사결정 단계:** 목표와 PPA 자료가 확보되면 탐색 결과를 최소 충족안/여유안/제외안으로
   재평가한다. 자료가 없으면 제품 판정을 UNDECIDED로 유지하되 실험 결과는 재사용한다.

추가 연구로는 실제 application trace/대표 kernel 확대, PMU를 이용한 Orin reference 보강,
대상 silicon 확보 후 별도 calibration/validation, 외부 accelerator traffic 모델을 고려할 수 있다.
현재 synthetic CPU workload의 결론을 확대하려면 필요한 작업이며, 이미 완료된 성과로 포함하지 않는다.

### 실행 시간 개선 후보

Baseline CPU4는 ROI 종료 후에도 guest output·환경·IRQ capture와 종료 처리에 상당한
host 시간이 들었다. 다음 작업에서는 ROI 계산 비용과 사후 수집 비용을 별도로 계측하고,
동일한 evidence contract를 유지하면서 중복 수집 축소나 ROI 밖 실행 경로 최적화를 검토한다.
검증 항목 삭제, 실행 중 CPU model 임의 변경 또는 partial output의 PASS 처리는 대안이 아니다.
이번 실행에는 이러한 최적화를 적용하지 않았다.
