##### K1.2.19 Reserved values in System and memory-mapped registers and translation table entries

Unless otherwise stated in this manual, all unallocated or reserved values of fields, or combinations of fields, with allocated values within AArch64 System registers, memory-mapped registers, and translation table entries behave in one of the following ways:

- The unallocated value or values maps onto any of the allocated values, but otherwise does not cause CONSTRAINED UNPREDICTABLE behavior.
- The unallocated value or values causes effects that could be achieved by a combination of more than one of the allocated values.
- The unallocated value or values causes the field or fields to have no functional effect.

> #### Note
>
> These constraints are identical to those for the equivalent AArch32 definitions, as given in [Reserved values in System and memory-mapped registers and translation table entries](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K1-Architectural-Constraints-on-UNPREDICTABLE-Behaviors/-K1-1-AArch32-CONSTRAINED-UNPREDICTABLE-behaviors/-K1-1-34-Reserved-values-in-System-and-memory-mapped-registers-and-translation-table-entries?lang=en#ceghghji).

Unless otherwise stated, when a direct write of a System register or memory-mapped register writes an unallocated value to a field, if that value is unallocated in all contexts then a subsequent read of the field returns an UNKNOWN value.
