# ​D11.5.1 Stage 1 Base Permissions

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-5-Stage-1-permission-model/-D11-5-1-Stage-1-Base-Permissions>

##### D11.5.1 Stage 1 Base Permissions

I MDFXL
:   The permissions encodings that permit [Guarded Control Stack data access](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-3-Procedure-returns?lang=en#mdterm_gcs_data_access) can only be configured when stage 1 translation uses the Indirect permission scheme.

I BVLMP
:   For translation regimes that apply to EL0 and a higher Exception level and where a Guarded Control Stack is being used for privileged execution, unprivileged data accesses do not write to such a Guarded Control Stack. For more information, see [Stage 1 permissions](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-4-Memory-access-control/-D8-4-1-Stage-1-permissions?lang=en#mdsec_stage_1_permissions).

I ZZMLZ
:   For translation regimes that apply to EL0 and a higher Exception level and where a Guarded Control Stack is being used for privileged execution but also accessible by any of unprivileged Data read accesses or unprivileged Instruction accesses, such a Guarded Control Stack is accessible by privileged [Guarded Control Stack data access](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-3-Procedure-returns?lang=en#mdterm_gcs_data_access) irrespective of the value of PSTATE.PAN. For more information, see [Stage 1 permissions](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-4-Memory-access-control/-D8-4-1-Stage-1-permissions?lang=en#mdsec_stage_1_permissions).

I LGRYM
:   Some cache maintenance operations require specific data access permissions in order to not generate a Permission fault. The PrivGCS and UnprivGCS permissions are not data access permissions, and therefore some cache maintenance operations might generate Permission faults if they target a page configured for Guarded Control Stack accesses. For more information, see [MMU faults generated by cache maintenance operations](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-15-Memory-aborts/-D8-15-3-MMU-faults-generated-by-cache-maintenance-operations?lang=en#mdsec_mmu_faults_generated_by_cache_maintenance_operations).

S DBWHS
:   EL0 Guarded Control Stack pages are expected to use:

    - UnprivRead as 1, UnprivWrite as 0, UnprivExecute as 0 and UnprivGCS as 1 in S1UnprivBasePerm.
    - PrivRead as 1, PrivWrite as 0 or 1, PrivExecute as 0 and PrivGCS as 0 in S1PrivBasePerm.

    EL0 Guarded Control Stack pages are generally accessible from EL1, enabling management from EL1. If PrivWrite is 0, then EL1 software should use the [`GCSSTTR`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-170-GCSSTTR?lang=en#isa_gcssttr) instruction to manage the EL0 Guarded Control Stack.

S GRGDT
:   EL1 Guarded Control Stack pages are expected to use:

    - UnprivRead as 0, UnprivWrite as 0, UnprivExecute as 0 and UnprivGCS as 0 in S1UnprivBasePerm.
    - PrivRead as 1, PrivWrite as 0, PrivExecute as 0 and PrivGCS as 1 in S1PrivBasePerm.

    Management of EL1 Guarded Control Stack pages is possible from EL1 by using the [`GCSSTR`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-169-GCSSTR?lang=en#isa_gcsstr) or [`GCSPUSHM`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-165-GCSPUSHM?lang=en#isa_gcspushm_sys) instructions.

S YNDKX
:   In a translation regime that applies to EL0 and a higher Exception level, the higher Exception level software cannot use unprivileged store instructions that perform non-[Guarded Control Stack data access](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-3-Procedure-returns?lang=en#mdterm_gcs_data_access) to manage the Guarded Control Stack pages of EL0. The higher Exception level software should use privileged store instructions or [`GCSSTTR`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-170-GCSSTTR?lang=en#isa_gcssttr) instead.

S HKJXY
:   In a translation regime that applies to EL0 and a higher Exception level, the higher Exception level software can make use of [`GCSSTR`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-169-GCSSTR?lang=en#isa_gcsstr) and [`GCSPUSHM`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-165-GCSPUSHM?lang=en#isa_gcspushm_sys) instructions to manage the Guarded Control Stack pages of the higher Exception level.

    In a translation regime that applies to only one Exception level, software can make use of [`GCSSTR`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-169-GCSSTR?lang=en#isa_gcsstr) and [`GCSPUSHM`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-165-GCSPUSHM?lang=en#isa_gcspushm_sys) instructions to manage the Guarded Control Stack pages of the current Exception level.

    Note: The [`GCSPUSHM`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-165-GCSPUSHM?lang=en#isa_gcspushm_sys) instruction executes as a NOP when the Guarded Control Stack is [Disabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack/-D11-2-1-Enabling-the-Guarded-Control-Stack?lang=en#mdterm_gcs_disabled) at the current Exception level. The [`GCSSTR`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-169-GCSSTR?lang=en#isa_gcsstr) instruction is functional even if the Guarded Control Stack is [Disabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack/-D11-2-1-Enabling-the-Guarded-Control-Stack?lang=en#mdterm_gcs_disabled) at the current Exception level.

S MQRCG
:   When PSTATE.PAN is 1, in a translation regime that applies to EL0 and a higher Exception level, the higher Exception level software can use unprivileged load instructions that perform non-[Guarded Control Stack data access](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-3-Procedure-returns?lang=en#mdterm_gcs_data_access) to manage the Guarded Control Stack pages of EL0.

    Example:

    ```
    ;At EL0
    BL                ;produce a GCS store operation
    SVC #0x0          ;exception to EL1 and PSTATE.PAN is set to 0b1
    MRS x0,GCSPR_EL0
    GCSB DSYNC
    LDTR x1,[x0]      ;read GCS contents of EL0
    ```
