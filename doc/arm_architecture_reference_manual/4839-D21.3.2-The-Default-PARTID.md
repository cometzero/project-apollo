# ​D21.3.2 The Default PARTID

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-3-Partition-Identifiers--PARTIDs-/-D21-3-2-The-Default-PARTID>

##### D21.3.2 The Default PARTID

R QKQCF
:   The *Default PARTID* number, in each [PARTID space](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-2-PARTID-spaces?lang=en#mpam_partid_spaces), is 0.

R CQXMC
:   In the following scenario, the MPAM PE attempts to map the *Default virtual PARTID*:

    - When no valid mapping exists for a PARTID that is *treated as virtual*.

      See [PARTID virtualization](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-3-Partition-Identifiers--PARTIDs-/-D21-3-1-PARTID-virtualization?lang=en#mpam_partid_virtualization).

    In each of the following scenarios, the MPAM PE Requester sends the *Default physical PARTID* as part of the [MPAM information bundle](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-1-About-MPAM/-D21-1-2-MPAM-information-bundles?lang=en#mpam_mpam_information_bundles):

    - When the [MPAM enable control](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-1-About-MPAM/-D21-1-6-The-MPAM-enable-control?lang=en#mpam_mpam_enabled_control) is 0, meaning MPAM is disabled.
    - When the MPAM version implemented is any other than v1p0, the request is from Secure state, and [MPAM3\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-4-MPAM3-EL3--MPAM3-Register--EL3-?lang=en#reg_aarch64_mpam3_el3).SDEFLT is implemented and is set to 1. See [Effect of the MPAM3\_EL3.{SDEFLT, FORCE\_NS} controls on MPAM PE Secure state execution](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-5-Effect-of-the-MPAM3-EL3--SDEFLT--FORCE-NS--controls-on-PE-Secure-state-execution?lang=en#mpam_effect_mpam_el3_sdeflt_force_ns_on_pe_secure_state_execution).
    - When a PARTID is an *out-of-range virtual PARTID* and the choice of CONSTRAINED UNPREDICTABLE behavior is to replace it with the Default physical PARTID. See [Behavior when a PARTID is out-of-range](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-9-MPAM-errors/-D21-9-1-Behavior-when-a-PARTID-is-out-of-range?lang=en#mpam_behavior_when_a_partid_is_out_of_range).
    - When no valid mapping exists for the Default virtual PARTID. See [Behavior when a valid mapping does not exist for a PARTID that is treated as virtual](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-9-MPAM-errors/-D21-9-2-Behavior-when-a-valid-mapping-does-not-exist-for-a-PARTID-that-is-treated-as-virtual?lang=en#mpam_behavior_when_a_valid_mapping_does_not_exist_for_a_partid_that_is_treated_as_virtual).

I XCZMJ
:   > #### Note
    >
    > The MPAM architecture permits SoC designers to make non-MPAM Requesters label every request to the memory system with the Default physical PARTID.
