# ​D20.2.2 PE error propagation

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-2-PE-error-handling/-D20-2-2-PE-error-propagation>

##### D20.2.2 PE error propagation

I NTXKV
:   The program-visible architectural state of the PE, referred to as the PE state, includes:

    - General-purpose, SIMD&FP, and SVE registers.
    - SME and SME2 registers.
    - System registers.
    - Special-purpose registers.
    - [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).

R XMBNW
:   An error is consumed by the PE by any of the following:

    - An instruction commits the corruption into the [PE state](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-2-PE-error-handling/-D20-2-2-PE-error-propagation?lang=en#mdterm_pe_state).
    - The error is on an instruction fetch and the corrupt instruction is committed for execution.
    - The error is on a translation table walk for a committed load, store, or instruction fetch.

I HVFKW
:   For a PE, [Error propagation](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A1-Introduction-to-the-Arm-Architecture/-A1-7-Reliability--Availability--and-Serviceability/-A1-7-3-General-taxonomy-of-errors?lang=en#mdsec_error_propagation) applies to the propagation of [Detected error](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#glossdef_detected_error) by the PE between the [PE state](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-2-PE-error-handling/-D20-2-2-PE-error-propagation?lang=en#mdterm_pe_state), and any other [PE state](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-2-PE-error-handling/-D20-2-2-PE-error-propagation?lang=en#mdterm_pe_state) or memory.

    Note: *Memory* includes structures that cache the contents of memory, such as an instruction cache, data cache, or TLB.

R VGXBJ
:   An error is propagated by the PE by one or more of the following occurring that would not have been permitted to occur had the fault not been activated:

    - Consumption of the corrupt value by any instruction, propagating the error to the target(s) of the instruction. This includes:

      - A store of a corrupt value.
      - A write of a corrupt value to a System register, Special-purpose register, or [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate). Infecting a System register state might mean that the PE generates transactions that would not otherwise be permitted.
    - Any operation occurring that should not have occurred, including:

      - A load, translation table walk, or instruction fetch that would not have been permitted, including those from hardware speculation or prefetching.
      - A store to an incorrect address, or a store that would not have been made or not permitted.
      - A direct or indirect write to a Special-purpose or System register that would not have been made or not permitted.
      - Assertion of any signal, such as an interrupt, that would not have been asserted.
    - Any operation not occurring that should have occurred.
    - Causing the PE to take an imprecise exception, other than an [Error exception](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-3-Generating-error-exceptions?lang=en#mdterm_error_exception) in response to the error itself. For more information, see [Definition of a precise exception and imprecise exception](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-4-Exceptions/-D1-4-1-Exception-entry-terminology?lang=en#mdsec_definition_of_precise_exception_imprecise_exception).
    - The PE discarding data that it holds in a modified state.
    - Any other loss of required uniprocessor semantics, ordering, or coherency.

I RMZNK
:   In [RVGXBJ](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-2-PE-error-handling/-D20-2-2-PE-error-propagation?lang=en#vgxbj), *not have been permitted to occur* means that the observable behavior of the PE is a deviation from the [correct service](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A1-Introduction-to-the-Arm-Architecture/-A1-7-Reliability--Availability--and-Serviceability/-A1-7-2-Faults--errors--and-failures?lang=en#mdterm_correct_service) of the PE, as defined by the architecture. Deviations from the normal behavior of the PE implementation that would otherwise be permitted by the architecture are not deviations from correct service.

    > Example D20-4
    >
    > A PE takes an [Error exception](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-3-Generating-error-exceptions?lang=en#mdterm_error_exception) asynchronously as follows, in program order:
    >
    > 1. A load returns a corrupt value from a first location to a general-purpose register.
    > 2. The PE suppresses a store of the register to a second memory location. In particular, the location is not updated and so retains its previous value.
    > 3. The Error exception is taken.
    > 4. At the point when the Error exception is taken, the ordering constraints imposed by the architecture have not been violated, in particular those relating to the observability of the store at step 2.
    >
    > Although the error has not been propagated, the PE state is not consistent with the PE having executed all of the instructions up to the point when the Error exception is taken, and so it would be unlikely that software would be able to [recover execution](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-4-Taking-error-exceptions?lang=en#mdterm_recover_execution).

R NQDWB
:   An error [propagated by the PE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-2-PE-error-handling/-D20-2-2-PE-error-propagation?lang=en#mdterm_propagated_by_pe) is silently propagated by the PE only if all of the following are true:

    1. The propagation is not part of the required operation of the PE in taking an [Error exception](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-3-Generating-error-exceptions?lang=en#mdterm_error_exception) generated by the error.
    2. The propagation is not part of the required operation of the PE executing an [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction that [synchronizes](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_synchronized_by_ese) the error.
    3. The error is not [signaled](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A1-Introduction-to-the-Arm-Architecture/-A1-7-Reliability--Availability--and-Serviceability/-A1-7-3-General-taxonomy-of-errors?lang=en#mdterm_ras_signal) to the consumer as a [Detected error](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#glossdef_detected_error) or [Deferred error](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#glossdef_deferred_error).
    4. Any of the following are true:

       - The corrupt value is held in other than the general-purpose, SIMD&FP, SVE, SME, and SME2 registers.
       - The error is propagated by an instruction in program order before either taking an [Error exception](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-3-Generating-error-exceptions?lang=en#mdterm_error_exception) generated by the error or executing an [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction that [synchronizes](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_synchronized_by_ese) the error, and is propagated to outside of the general-purpose, SIMD&FP, SVE, SME, and SME2 registers.
       - The error is propagated other than by an instruction that consumes the corrupt value as an input operand but otherwise behaves correctly.

I BRBFF
:   In [RNQDWB](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-2-PE-error-handling/-D20-2-2-PE-error-propagation?lang=en#nqdwb), item 4 means that after taking the [Error exception](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-3-Generating-error-exceptions?lang=en#mdterm_error_exception) generated by the error, or an [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb), propagating an error by, for example, storing the corrupt value to memory, is not considered as silent propagation of the error by the PE.

    > Example D20-5
    >
    > A PE takes an [Error exception](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-3-Generating-error-exceptions?lang=en#mdterm_error_exception) in response to a load that returns a corrupt value to a general-purpose register. The error is not silently propagated to outside of the general-purpose registers before the Error exception is taken.
    >
    > Neither of the following are considered silent propagation of the error by the PE:
    >
    > - Taking the Error exception causes the [ESR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#esr_elx), [ELR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#elr_elx), and [SPSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#spsr_elx) registers to be updated. This is part of the required operation of the PE.
    > - After taking the Error exception, software stores the contents of the general-purpose register to memory, and this is not [signaled](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A1-Introduction-to-the-Arm-Architecture/-A1-7-Reliability--Availability--and-Serviceability/-A1-7-3-General-taxonomy-of-errors?lang=en#mdterm_ras_signal) to memory as a [Deferred error](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#glossdef_deferred_error). This happens in program order after the exception is taken.
    >
    > The error is not silently propagated by the PE.

    > Example D20-6
    >
    > Further to [Example D20-4](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-2-PE-error-handling/-D20-2-2-PE-error-propagation?lang=en#ex_mdex_rmznk_ex), if either of the following example additional operations occur between 2 and 3, then the PE has silently propagated the error:
    >
    > - A second store to a third location is performed by the PE, and the architecture requires that the first store is ordered-before the second store. For example, the second store is a store-release operation. In this case, the PE violates the external ordering constraints for the two stores, and the error is silently propagated to any observer of the second store.
    > - A second load from the second location returns the previous value, and a second store writes that value to a third location. In this case, the PE violates the requirements of the [Coherence-before](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-3-Ordering-requirements-defined-by-the-formal-concurrency-model/-B2-3-1-Basic-definitions?lang=en#chddhccb) relation because the second load cannot be Coherence-before the first store. The error silently propagates to any observer of the second store.
    >
    > If instead of the PE suppressing the store at 2, the PE poisons the second memory location, and in the second example propagates that poison through the second load and second store, then the error is not silently propagated.

R DTRFQ
:   The features that a PE includes to prevent silent propagation of an error are IMPLEMENTATION DEFINED.

    > Example D20-7
    >
    > An implementation ensures that a corrupt value in a general-purpose, SIMD&FP, SVE, or SME register is not silently propagated, by [signaling](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A1-Introduction-to-the-Arm-Architecture/-A1-7-Reliability--Availability--and-Serviceability/-A1-7-3-General-taxonomy-of-errors?lang=en#mdterm_ras_signal) a [Deferred error](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#glossdef_deferred_error) on any write of data to any memory location, such that the memory location is [poisoned](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A1-Introduction-to-the-Arm-Architecture/-A1-7-Reliability--Availability--and-Serviceability/-A1-7-3-General-taxonomy-of-errors?lang=en#mdterm_ras_poisoned).
