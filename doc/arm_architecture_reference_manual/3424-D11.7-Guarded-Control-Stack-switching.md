# ​D11.7 Guarded Control Stack switching

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-7-Guarded-Control-Stack-switching>

#### D11.7 Guarded Control Stack switching

G XMPQT
:   [FEAT\_GCS](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-5-The-Armv9-4-architecture-extension?lang=en#feat_feat_gcs) provides means to switch between multiple Guarded Control Stacks of an Exception level at the same Exception level, without providing direct write access to the [current GCS pointer register](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_current_gcs_pr).

G GTMLR
:   Arm expects that an individual Guarded Control Stack is used by only one PE at a time, to ensure the stack is not being updated by one PE while being used by another.

I FZSVZ
:   When a Guarded Control Stack is not currently in use, the top entry contains a special value which indicates it is capped. The only way that the Guarded Control Stack can become uncapped is by execution of the [`GCSSS1`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-167-GCSSS1?lang=en#isa_gcsss1_sys) `Xn` and [`GCSSS2`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-168-GCSSS2?lang=en#isa_gcsss2_sysl) `Xn` instructions, to switch between two Guarded Control Stacks. These instructions check the cap on the incoming Guarded Control Stack and then add a cap to the outgoing Guarded Control Stack. Since there is no direct write access to the current GCS pointer register, the only way the current GCS pointer register can be made to point to the new Guarded Control Stack is using these instructions, and the checks performed by these instructions ensure that the value loaded is always pointing to a capped Guarded Control Stack. This ensures that any arbitrary location in a Guarded Control Stack cannot be switched to.

I GPHKD
:   The instruction pair [`GCSSS1`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-167-GCSSS1?lang=en#isa_gcsss1_sys) `Xn` and [`GCSSS2`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-168-GCSSS2?lang=en#isa_gcsss2_sysl) `Xn` provide means to switch between Guarded Control Stacks of the current Exception level without directly accessing [GCSPR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#gcspr_elx) at the same Exception level.

D PCHQS
:   A value of `0b000000000001` in bits [11:0] of a Guarded Control Stack entry is called a Valid cap token.

D QJDCV
:   A GCS cap record is defined as a [Valid GCS cap record](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_gcs_vc_record), if bits [63:12] of the entry value are the same as bits [63:12] of the address where the entry is stored and bits [11:0] contain a [Valid cap token](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-7-Guarded-Control-Stack-switching?lang=en#mdterm_valid_token).

D ZNSQG
:   A value of `0b101` in bits [2:0] of a Guarded Control Stack entry is called an In-progress cap token.

D XGMLV
:   A GCS cap record is defined as an [In-progress GCS cap record](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_gcs_ipc_record), if bits [63:3] of the value are the same as bits [63:3] of the [current GCS pointer register](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_current_gcs_pr) value and bits [2:0] contain an [In-progress cap token](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-7-Guarded-Control-Stack-switching?lang=en#mdterm_in_progress_token).

R QHSGP
:   The [`GCSSS1`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-167-GCSSS1?lang=en#isa_gcsss1_sys) `Xn` instruction performs the following functionalities in order:

    1. A doubleword is loaded from the Guarded Control Stack that is pointed to by `Xn`.
    2. If the loaded value is a [Valid GCS cap record](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_gcs_vc_record):

       - The top entry of the Guarded Control Stack pointed to by `Xn` is overwritten with an [In-progress GCS cap record](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_gcs_ipc_record):

         - Bits [63:3] of the [In-progress GCS cap record](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_gcs_ipc_record) contain bits [63:3] of the [current GCS pointer register](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_current_gcs_pr).
         - Bits [2:0] of the [In-progress GCS cap record](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_gcs_ipc_record) contain `0b101`.
       - The [current GCS pointer register](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_current_gcs_pr) is updated to the following value:

         - Bits [63:3] are set to bits [63:3] of `Xn`.
         - Bits [2:0] are set to `0b000`.
    3. If the loaded value is not a [Valid GCS cap record](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_gcs_vc_record), a [GCS Data Check exception](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-9-Guarded-Control-Stack-exceptions?lang=en#mdterm_gcs_data_check_exception) is generated and no write is required to be performed.
    4. All observers in the shareability domain observe the load and store atomically.

R PBWVT
:   The [`GCSSS2`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-168-GCSSS2?lang=en#isa_gcsss2_sysl) `Xn` instruction performs the following functionalities in order:

    1. A doubleword is loaded from the memory pointed by the [current GCS pointer register](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_current_gcs_pr).
    2. If the loaded value contains an [In-progress cap token](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-7-Guarded-Control-Stack-switching?lang=en#mdterm_in_progress_token):

       - A [Valid GCS cap record](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_gcs_vc_record) is written to the outgoing GCS, with the following parameters:

         - The target address of the write has:

           - Bits [63:3] set to bits [63:3] of the loaded value, minus 1.
           - Bits [2:0] set to `0b000`.
         - The data value written has:

           - Bits [63:12] set to bits [63:12] of the target address.
           - Bits [11:0] set to `0b000000000001`.
       - The [current GCS pointer register](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_current_gcs_pr) is incremented by the size of a [GCS procedure return record](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_gcs_pr_record).
       - `Xn` is updated to contain:

         - Bits [63:3] set to bits [63:3] of the loaded value, minus 1.
         - Bits [2:0] are set to `0b000`.
    3. If the loaded value does not contain an [In-progress cap token](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-7-Guarded-Control-Stack-switching?lang=en#mdterm_in_progress_token), a [GCS Data Check exception](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-9-Guarded-Control-Stack-exceptions?lang=en#mdterm_gcs_data_check_exception) is generated.

R KFMRX
:   For the purpose of permission checking, and for watchpoints, the [`GCSSS1`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-167-GCSSS1?lang=en#isa_gcsss1_sys) `Xn` instruction is treated as performing both a load and a store, even if the store does not happen.

G HMJGM
:   [FEAT\_GCS](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-5-The-Armv9-4-architecture-extension?lang=en#feat_feat_gcs) allows software to use address tagging in a Guarded Control Stack Pointer.

I MGLTC
:   While address tagging for data addresses is enabled, if the tag value in the target address register of the [`GCSSS1`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-167-GCSSS1?lang=en#isa_gcsss1_sys) `Xn` instruction is not same as the tag value in the [Valid GCS cap record](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_gcs_vc_record), the comparison as part of the [`GCSSS1`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-167-GCSSS1?lang=en#isa_gcsss1_sys) `Xn` instruction will cause a [GCS Data Check exception](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-9-Guarded-Control-Stack-exceptions?lang=en#mdterm_gcs_data_check_exception).

I MBHFS
:   While address tagging for data addresses is enabled, the [In-progress GCS cap record](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_gcs_ipc_record) stored by the [`GCSSS1`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-167-GCSSS1?lang=en#isa_gcsss1_sys) `Xn` instruction will contain any tag value that is present in the [current GCS pointer register](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-2-The-Guarded-Control-Stack?lang=en#mdterm_current_gcs_pr).

R XWQDB
:   All restrictions that are applicable to usage of the atomic instructions are also applicable to the usage of the [`GCSSS1`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-167-GCSSS1?lang=en#isa_gcsss1_sys) `Xn` instruction.

I DDFMX
:   For example, the memory types for which it is architecturally guaranteed that the [`GCSSS1`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-167-GCSSS1?lang=en#isa_gcsss1_sys) `Xn` instruction will be atomic are:

    - Inner Shareable, Inner Write-Back, Outer Write-Back Normal memory.
    - Outer Shareable, Inner Write-Back, Outer Write-Back Normal memory.

R PTCXM
:   For the purpose of exception prioritization, a [GCS Data Check exception](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D11-The-Guarded-Control-Stack/-D11-9-Guarded-Control-Stack-exceptions?lang=en#mdterm_gcs_data_check_exception) from a [`GCSSS2`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-168-GCSSS2?lang=en#isa_gcsss2_sysl) `Xn` instruction is considered to be caused by the load that is part of the same [`GCSSS2`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-168-GCSSS2?lang=en#isa_gcsss2_sysl) `Xn` instruction.

R XTZVS
:   For the purpose of prioritizing exceptions and debug events, all exceptions and debug events due to load part of a [`GCSSS2`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-168-GCSSS2?lang=en#isa_gcsss2_sysl) `Xn` instruction are higher priority than exceptions and debug events due to store part of the same [`GCSSS2`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-168-GCSSS2?lang=en#isa_gcsss2_sysl) `Xn` instruction.

    > #### Note
    >
    > This is a stricter requirement when compared to most of other instructions that cause multiple single copy atomic accesses where the priority is not architecturally defined.
