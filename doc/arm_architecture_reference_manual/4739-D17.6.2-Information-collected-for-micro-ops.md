# ​D17.6.2 Information collected for micro-ops

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-2-Information-collected-for-micro-ops>

##### D17.6.2 Information collected for micro-ops

Because architectural instructions might create zero, one, or more micro-ops, micro-ops might have different characteristics from the architectural instructions they are created from. The data collected for each micro-op is IMPLEMENTATION DEFINED. The PE collects the subset of data appropriate to the micro-op.

However, in order for the profile information to be meaningful to the user of the profile, Arm recommends that the sampled micro-op is recorded as a type appropriate to the instruction when the recorded properties of the micro-op correlate with the properties of the instruction.

> Example D17-2 Sampling of micro-ops
>
> If an architectural load instruction is split into an address generation micro-op and a load micro-op, then when generating the sample record and filtering based on operation type:
>
> - If the address generation micro-op is sampled, the sampled operation is treated as *other*.
> - If the load micro-op is sampled, the sampled operation is treated as a load.
