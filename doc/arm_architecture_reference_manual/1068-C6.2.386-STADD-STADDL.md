##### C6.2.386 STADD, STADDL

Atomic add on word or doubleword, without return

This instruction atomically loads a 32-bit word or 64-bit doubleword from memory, adds the value held in a register to it, and stores the result back to memory.

- `STADD` does not have release semantics.
- `STADDL` stores to memory with release semantics, as described in [Load-Acquire, Store-Release](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-6-Memory-barriers/-B2-6-10-Load-Acquire--Load-AcquirePC--and-Store-Release?lang=en#beihchef).

For information about addressing modes, see [Load/Store addressing modes](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C1-The-A64-Instruction-Set/-C1-3-Address-generation/-C1-3-3-Load-store-addressing-modes?lang=en#chdiiibb).

This is an alias of [LDADD, LDADDA, LDADDAL, LDADDL](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-180-LDADD--LDADDA--LDADDAL--LDADDL?lang=en#isa_ldadd). This means:

- The encodings in this description are named to match the encodings of [LDADD, LDADDA, LDADDAL, LDADDL](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-180-LDADD--LDADDA--LDADDAL--LDADDL?lang=en#isa_ldadd).
- The description of [LDADD, LDADDA, LDADDAL, LDADDL](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-180-LDADD--LDADDA--LDADDAL--LDADDL?lang=en#isa_ldadd) gives the operational pseudocode, any CONSTRAINED UNPREDICTABLE behavior, and any operational information for this instruction.

###### Encoding for the 32-bit no memory ordering variant

Applies when `(size == 10 && R == 0)`

```
STADD  <Ws>, [<Xn|SP>]
```

is equivalent to

```
LDADD  <Ws>, <Wt>, [<Xn|SP>]
```

and is always the preferred disassembly.

###### Encoding for the 32-bit release variant

Applies when `(size == 10 && R == 1)`

```
STADDL  <Ws>, [<Xn|SP>]
```

is equivalent to

```
LDADDL  <Ws>, <Wt>, [<Xn|SP>]
```

and is always the preferred disassembly.

###### Encoding for the 64-bit no memory ordering variant

Applies when `(size == 11 && R == 0)`

```
STADD  <Xs>, [<Xn|SP>]
```

is equivalent to

```
LDADD  <Xs>, <Xt>, [<Xn|SP>]
```

and is always the preferred disassembly.

###### Encoding for the 64-bit release variant

Applies when `(size == 11 && R == 1)`

```
STADDL  <Xs>, [<Xn|SP>]
```

is equivalent to

```
LDADDL  <Xs>, <Xt>, [<Xn|SP>]
```

and is always the preferred disassembly.

###### Assembler Symbols

<Ws>
:   ​

    Is the 32-bit name of the general-purpose register holding the data value to be operated on with the contents of the memory location, encoded in the “Rs” field.

<Xn|SP>
:   ​

    Is the 64-bit name of the general-purpose base register or stack pointer, encoded in the “Rn” field.

<Xs>
:   ​

    Is the 64-bit name of the general-purpose register holding the data value to be operated on with the contents of the memory location, encoded in the “Rs” field.
