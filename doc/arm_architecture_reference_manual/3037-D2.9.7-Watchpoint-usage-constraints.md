If a watchpoint is programmed with one of these reserved combinations:

- The watchpoint must behave as if it is either:

  - Disabled.
  - Programmed with a combination that is not reserved, other than for a direct or external read of [DBGWCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-11-DBGWCR-n--EL1--Debug-Watchpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgwcrn_el1).
- For a direct or external read of [DBGWCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-11-DBGWCR-n--EL1--Debug-Watchpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgwcrn_el1), if the reserved combination:

  - Has no function for any execution conditions, the value read back for each of SSCE, SSC, HMC, and PAC is UNKNOWN.
  - Has a function for execution conditions other than the current execution conditions, the value read back is the value written. This permits software to save and restore the combination so that the watchpoint functions for the other execution conditions.

The behavior of watchpoints with reserved combinations of SSCE, SSC, HMC, and PAC might change in future revisions of the architecture. For this reason, software must not rely on the behavior described here.

###### D2.9.7.3 Usage constraints on DBGWCR<n>\_EL1.{LBNX, LBN} values

For Linked Watchpoints
:   If any of the following are true for a Linked watchpoint <n>, then direct reads of [DBGWCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-11-DBGWCR-n--EL1--Debug-Watchpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgwcrn_el1).{LBNX, LBN} return an UNKNOWN value and it is CONSTRAINED UNPREDICTABLE whether Watchpoint exceptions and debug events are generated:

    - The Linked watchpoint is linked to an unimplemented breakpoint.
    - The Linked watchpoint is linked to a breakpoint which does not support linking.
    - [FEAT\_ABLE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-5-The-Armv9-4-architecture-extension?lang=en#feat_feat_able) is not implemented and the Linked watchpoint is linked to a breakpoint which is not context aware.

    Otherwise, if any of the following are true for a Linked watchpoint <n>, then the Linked watchpoint behaves as if it is disabled:

    - The Linked watchpoint is linked to an enabled breakpoint that does not have linking enabled.
    - [FEAT\_ABLE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-5-The-Armv9-4-architecture-extension?lang=en#feat_feat_able) is not implemented and the Linked watchpoint is linked to an enabled Address matching breakpoint.
    - The Linked watchpoint is linked to a disabled breakpoint.

    It is CONSTRAINED UNPREDICTABLE whether Watchpoint exceptions and debug events are generated if an instruction address generates a breakpoint match for more than one enabled Address matching breakpoint with linking enabled.

For Unlinked Watchpoints
:   For Unlinked watchpoints, [DBGWCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-11-DBGWCR-n--EL1--Debug-Watchpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgwcrn_el1).{LBNX, LBN} reads UNKNOWN and its value is ignored.

###### D2.9.7.4 Programming dependencies of the BAS and MASK fields

When programming a watchpoint, a debugger must use either:

- The MASK field, to program the watchpoint with an address range that can be eight bytes to 2GB.
- The BAS field, to select which bytes in the doubleword or word starting at the address contained in the [DBGWVR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-12-DBGWVR-n--EL1--Debug-Watchpoint-Value-Registers--n---0---63?lang=en#reg_aarch64_dbgwvrn_el1) the watchpoint must generate Watchpoint exceptions for.

If the debugger uses the:

- MASK field, it must program BAS to be `0b11111111`, so that all bytes in the doubleword or word are selected.
- BAS field, it must program MASK to be `0b00000`, so that the MASK field does not indicate any address ranges.

If an enabled watchpoint has a MASK field that is nonzero and a BAS field that is not set to `0b11111111`, then for each byte in the address range, it is CONSTRAINED UNPREDICTABLE whether or not a Watchpoint exception is generated.

###### D2.9.7.5 Reserved DBGWCR<n>\_EL1.BAS values

The BAS field must be programmed with a value [`Zeros`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-1-Standard-library?lang=en#asl_standard_library_zeros)`(8-n-m):`[`Ones`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-1-Standard-library?lang=en#asl_standard_library_ones)`(n):`[`Zeros`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-1-Standard-library?lang=en#asl_standard_library_zeros)`(m)`, where:

- `n` is a nonzero positive integer less-than-or-equal-to 8.
- `m` is a positive integer less-than 8. `m` is permitted to be zero.
- `n+m` is less-than-or-equal-to 8.
- If [DBGWVR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-12-DBGWVR-n--EL1--Debug-Watchpoint-Value-Registers--n---0---63?lang=en#reg_aarch64_dbgwvrn_el1)[2] is 1, then `n+m` is less-than-or-equal-to 4.

All other values are reserved.

> #### Note
>
> [`Zeros`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-1-Standard-library?lang=en#asl_standard_library_zeros)`{0}()` is an empty bitstring.

If [DBGWVR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-12-DBGWVR-n--EL1--Debug-Watchpoint-Value-Registers--n---0---63?lang=en#reg_aarch64_dbgwvrn_el1)[2] is 1, [DBGWCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-11-DBGWCR-n--EL1--Debug-Watchpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgwcrn_el1).BAS[7:4] are RES0.

If a watchpoint is programmed with a reserved BAS value:

- It is CONSTRAINED UNPREDICTABLE whether the watchpoint generates a Watchpoint exception for each byte in the doubleword or word of memory addressed by the [DBGWVR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-12-DBGWVR-n--EL1--Debug-Watchpoint-Value-Registers--n---0---63?lang=en#reg_aarch64_dbgwvrn_el1).
- A direct or external read of [DBGWCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-11-DBGWCR-n--EL1--Debug-Watchpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgwcrn_el1).BAS returns an UNKNOWN value.

Software must not rely on these properties as the behavior of reserved values might change in a future revision of the architecture.

###### D2.9.7.6 Reserved DBGWCR<n>\_EL1.MASK values

If a watchpoint is programmed with a reserved MASK value:

- The watchpoint must behave as if it is either:

  - Disabled.
  - Programmed with an UNKNOWN value that is not reserved, that might be `0b00000`, other than for a direct or external read of [DBGWCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-11-DBGWCR-n--EL1--Debug-Watchpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgwcrn_el1).
- A direct or external read of [DBGWCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-11-DBGWCR-n--EL1--Debug-Watchpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgwcrn_el1).MASK returns an UNKNOWN value.

###### D2.9.7.7 Other usage constraints

For all watchpoints:
:   - [DBGWVR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-12-DBGWVR-n--EL1--Debug-Watchpoint-Value-Registers--n---0---63?lang=en#reg_aarch64_dbgwvrn_el1)[1:0] are RES0 and are ignored.
    - If [DBGWCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-11-DBGWCR-n--EL1--Debug-Watchpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgwcrn_el1).MASK is nonzero, and any masked bits of [DBGWVR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-12-DBGWVR-n--EL1--Debug-Watchpoint-Value-Registers--n---0---63?lang=en#reg_aarch64_dbgwvrn_el1) are not 0, it is CONSTRAINED UNPREDICTABLE whether the watchpoint generates a Watchpoint exception when the unmasked bits match.
    - A watchpoint never generates any Watchpoint exceptions if [DBGWCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-11-DBGWCR-n--EL1--Debug-Watchpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgwcrn_el1).LSC is `0b00`.
