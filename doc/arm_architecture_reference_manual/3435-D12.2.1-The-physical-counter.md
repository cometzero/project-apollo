# ​D12.2.1 The physical counter

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D12-The-Generic-Timer-in-AArch64-state/-D12-2-The-AArch64-view-of-the-Generic-Timer/-D12-2-1-The-physical-counter>

##### D12.2.1 The physical counter

The PE includes a physical counter that contains the count value of the system counter. The [CNTPCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-17-CNTPCT-EL0--Counter-timer-Physical-Count-Register?lang=en#reg_aarch64_cntpct_el0) register holds the current physical counter value. This is defined as the pseudocode function [`PhysicalCountInt`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-631-PhysicalCountInt?lang=en#asl_func_physicalcountint_0)`()`. Reads of [CNTPCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-17-CNTPCT-EL0--Counter-timer-Physical-Count-Register?lang=en#reg_aarch64_cntpct_el0) register at EL2 or EL3 return the current value of [`PhysicalCountInt`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-631-PhysicalCountInt?lang=en#asl_func_physicalcountint_0)`()`.

When [FEAT\_ECV](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-7-The-Armv8-6-architecture-extension?lang=en#feat_feat_ecv) is implemented, the [CNTPOFF\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-18-CNTPOFF-EL2--Counter-timer-Physical-Offset-Register?lang=en#reg_aarch64_cntpoff_el2) register holds the optional physical offset that can be applied at EL0 and EL1 whether EL0 and EL1 are using AArch64 state or AArch32 state.

For more information, see [The physical offset register](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D12-The-Generic-Timer-in-AArch64-state/-D12-2-The-AArch64-view-of-the-Generic-Timer/-D12-2-1-The-physical-counter?lang=en#babdhagd).

Reads of [CNTPCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-17-CNTPCT-EL0--Counter-timer-Physical-Count-Register?lang=en#reg_aarch64_cntpct_el0) can occur speculatively and out of order relative to other instructions executed on the same PE.

###### D12.2.1.1 The self-synchronized view of the physical counter

When [FEAT\_ECV](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-7-The-Armv8-6-architecture-extension?lang=en#feat_feat_ecv) is implemented, an alternative way to read the physical counter is supported. The [CNTPCTSS\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-16-CNTPCTSS-EL0--Counter-timer-Self-Synchronized-Physical-Count-Register?lang=en#reg_aarch64_cntpctss_el0) register is a non-speculative view of the physical counter, as seen from the Exception level that [CNTPCTSS\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-16-CNTPCTSS-EL0--Counter-timer-Self-Synchronized-Physical-Count-Register?lang=en#reg_aarch64_cntpctss_el0) is read from.

Accesses to the [CNTPCTSS\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-16-CNTPCTSS-EL0--Counter-timer-Self-Synchronized-Physical-Count-Register?lang=en#reg_aarch64_cntpctss_el0) are subject to the same traps as accesses to the [CNTPCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-17-CNTPCT-EL0--Counter-timer-Physical-Count-Register?lang=en#reg_aarch64_cntpct_el0).

Reads of [CNTPCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-17-CNTPCT-EL0--Counter-timer-Physical-Count-Register?lang=en#reg_aarch64_cntpct_el0) occur in program order relative to reads of [CNTPCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-17-CNTPCT-EL0--Counter-timer-Physical-Count-Register?lang=en#reg_aarch64_cntpct_el0) or [CNTPCTSS\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-16-CNTPCTSS-EL0--Counter-timer-Self-Synchronized-Physical-Count-Register?lang=en#reg_aarch64_cntpctss_el0).

Reads of [CNTPCTSS\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-16-CNTPCTSS-EL0--Counter-timer-Self-Synchronized-Physical-Count-Register?lang=en#reg_aarch64_cntpctss_el0) occur in program order relative to reads of [CNTPCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-17-CNTPCT-EL0--Counter-timer-Physical-Count-Register?lang=en#reg_aarch64_cntpct_el0) or [CNTPCTSS\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-16-CNTPCTSS-EL0--Counter-timer-Self-Synchronized-Physical-Count-Register?lang=en#reg_aarch64_cntpctss_el0).

> Example D12-1 Ensuring reads of the physical counter occur after signal read from memory
>
> If a read from memory is used to obtain a signal from another agent that indicates that [CNTPCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-17-CNTPCT-EL0--Counter-timer-Physical-Count-Register?lang=en#reg_aarch64_cntpct_el0) must be read, an `ISB` is used to ensure that the read of [CNTPCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-17-CNTPCT-EL0--Counter-timer-Physical-Count-Register?lang=en#reg_aarch64_cntpct_el0) occurs after the signal has been read from memory, as shown in the following code sequence:
>
> ```
> loop                      ; polling for some communication to indicate a requirement to
>                           ; read the timer
>     LDR X1, [X2]
>     CMP X1, #1            ; has had the value 1 written to it
>     B.NE loop
>     ISB                   ; without this the CNTPCT_EL0 could be read before the memory
>                           ; location in [X2]
>     MRS X1, CNTPCT_EL0
> ```
>
> When [FEAT\_ECV](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-7-The-Armv8-6-architecture-extension?lang=en#feat_feat_ecv) is implemented, an access to [CNTPCTSS\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-16-CNTPCTSS-EL0--Counter-timer-Self-Synchronized-Physical-Count-Register?lang=en#reg_aarch64_cntpctss_el0) can be used in place of the [CNTPCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-17-CNTPCT-EL0--Counter-timer-Physical-Count-Register?lang=en#reg_aarch64_cntpct_el0) which, because it cannot be accessed speculatively, allows the `ISB` to be removed. This means that the following code sequence can be used:
>
> ```
> loop                      ; polling for some communication to indicate a requirement to
>                           ; read the timer
>     LDR X1, [X2]
>     CMP X1, #1            ; has had the value 1 written to it
>     B.NE loop
>     MRS X1, CNTPCTSS_EL0
> ```
>
> Similarly where a read of the physical counter is required to take place after the completion of all loads and stores appearing in program order before the read of the counter, then the following code sequences can be used:
>
> ```
>   ...                     ; earlier loads and stores
>     DSB                   ; completes the earlier loads and stores
>     ISB                   ; without this the CNTPCT_EL0 could be read before the completion
>                           ; of the earlier loads and stores
>     MRS X1, CNTPCT_EL0
> ```
>
> Or, if [FEAT\_ECV](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-7-The-Armv8-6-architecture-extension?lang=en#feat_feat_ecv) is implemented:
>
> ```
>   ...                     ; earlier loads and stores
>     DSB                   ; completes earlier loads and stores
>     MRS X1, CNTPCTSS_EL0
> ```

Neither view of the physical counter ensures that:

- Context changes occurring in program order before the read of the counter have been synchronized.
- Accesses to memory appearing in program order after the read of the counter are executed before the counter has been read.

Where there is a [Dependency through registers and memory](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-3-Ordering-requirements-defined-by-the-formal-concurrency-model/-B2-3-6-Dependency-relations?lang=en#mm_dependency_through_registers_and_memory) from the read of the physical counter to a Register effect generated by a read or write, the read or write will be executed after the read of the counter.

> Example D12-2 Ensuring reads of the physical counter occur after previous memory accesses
>
> To ensure that all previous memory accesses have completed and all previous context changes have been synchronized before the read of the counter, one of the following sequences should be used:
>
> either:
>
> ```
>   DSB
>     ISB
>     MRS Xn, CNTPCT{SS}_EL0    ; either view of the physical counter has the same effect in
>                               ; this example
> ```
>
> or
>
> ```
>   DMB
>     LDR Xa, [Xd]              ; this could be any memory location, for example the stack pointer
>     CBZ Xa, next
> next
>     ISB                       ; this ISB is not needed if the MRS is accessing CNTPCTSS_EL0
>     MRS Xn, CNTPCT{SS}_EL0
> ```
>
> To ensure that a memory access occurs only after a read of the counter, then either of the following sequences should be used:
>
> ```
>   MRS Xn, CNTPCT{SS}_EL0    ; either view of the physical counter has the same effect in
>                             ; this example
>     ISB
>     LDR Xa, [Xb]            ; this load will be executed after the timer has been read
> ```
>
> or
>
> ```
>   MRS Xn, CNTPCT{SS}_EL0    ; either view of the physical counter has the same effect in
>                             ; this example
>     EOR Xm, Xn, Xn
>     LDR Xa, [Xb, Xm]        ; this load will be executed after the timer has been read
> ```

###### D12.2.1.2 The physical offset register

When [FEAT\_ECV\_POFF](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-7-The-Armv8-6-architecture-extension?lang=en#feat_feat_ecv_poff) is implemented, the [CNTPOFF\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-18-CNTPOFF-EL2--Counter-timer-Physical-Offset-Register?lang=en#reg_aarch64_cntpoff_el2) register allows an offset to be applied to the physical counter, as viewed from EL1 and EL0, and to the EL1 physical timer. The functionality of this 64-bit register is affected by [CNTHCTL\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-2-CNTHCTL-EL2--Counter-timer-Hypervisor-Control-Register?lang=en#reg_aarch64_cnthctl_el2).ECV.

When [CNTHCTL\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-2-CNTHCTL-EL2--Counter-timer-Hypervisor-Control-Register?lang=en#reg_aarch64_cnthctl_el2).ECV is 1, an MRS to [CNTPCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-17-CNTPCT-EL0--Counter-timer-Physical-Count-Register?lang=en#reg_aarch64_cntpct_el0) or [CNTPCTSS\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-16-CNTPCTSS-EL0--Counter-timer-Self-Synchronized-Physical-Count-Register?lang=en#reg_aarch64_cntpctss_el0) from either EL0 or EL1 that is not trapped returns the value `(PhysicalCountInt() - CNTPOFF_EL2)`. For information on how the EL1 physical timer interrupt is triggered when [CNTHCTL\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-2-CNTHCTL-EL2--Counter-timer-Hypervisor-Control-Register?lang=en#reg_aarch64_cnthctl_el2).ECV is 1, see [Operation of the CompareValue views of the timers](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D12-The-Generic-Timer-in-AArch64-state/-D12-2-The-AArch64-view-of-the-Generic-Timer/-D12-2-4-Timers?lang=en#chddaeaj).

When EL2 is not enabled for the current Security state, or when [CNTHCTL\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-2-CNTHCTL-EL2--Counter-timer-Hypervisor-Control-Register?lang=en#reg_aarch64_cnthctl_el2).ECV is 0, then:

- An MRS to [CNTPCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-17-CNTPCT-EL0--Counter-timer-Physical-Count-Register?lang=en#reg_aarch64_cntpct_el0) from either EL0 or EL1 that is not trapped will return the value [`PhysicalCountInt`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-631-PhysicalCountInt?lang=en#asl_func_physicalcountint_0)`()`.
- The physical offset is treated as zero for all timer and counter calculations involving the physical offset.

When EL2 is not enabled for the current Security state, or when [CNTHCTL\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-2-CNTHCTL-EL2--Counter-timer-Hypervisor-Control-Register?lang=en#reg_aarch64_cnthctl_el2).ECV is 0, then the behavior of the counters and timers is as described for Armv8.5 and the optional physical offset is not used.

When [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).ECVEn is 0, the value of [CNTPOFF\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-18-CNTPOFF-EL2--Counter-timer-Physical-Offset-Register?lang=en#reg_aarch64_cntpoff_el2) is treated as 0 for all purposes other than direct reads or writes to [CNTPOFF\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-18-CNTPOFF-EL2--Counter-timer-Physical-Offset-Register?lang=en#reg_aarch64_cntpoff_el2) from EL3.
