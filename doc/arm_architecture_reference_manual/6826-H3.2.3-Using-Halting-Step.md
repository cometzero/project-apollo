# ​H3.2.3 Using Halting Step

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H3-Halting-Debug-Events/-H3-2-Halting-Step-debug-events/-H3-2-3-Using-Halting-Step>

##### H3.2.3 Using Halting Step

To step a single instruction the PE must be in Debug state:

1. The debugger sets [EDECR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-28-EDECR--External-Debug-Execution-Control-Register?lang=en#reg_ext_edecr).SS to 1 to enable Halting step.
2. The debugger signals the PE to exit Debug state with [DLR](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-1-Register-name-disambiguation-by-Execution-state?lang=en#babjjiaj) set to the address of the instruction being stepped. The PE clears [EDESR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-29-EDESR--External-Debug-Event-Status-Register?lang=en#reg_ext_edesr).SS to 0 and the Halting Step state machine enters the active-not-pending state.
3. The PE executes the instruction being stepped.

   If an exception is taken to a state where halting is prohibited, then [EDESR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-29-EDESR--External-Debug-Event-Status-Register?lang=en#reg_ext_edesr).SS is always correct for the preferred return address of the exception.
4. The PE enters Debug state before executing the next instruction and the step is complete.

> #### Note
>
> - If [FEAT\_DoPD](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_dopd) is not implemented, [EDECR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-28-EDECR--External-Debug-Execution-Control-Register?lang=en#reg_ext_edecr).SS value is in the Debug power domain, meaning that the state machine is maintained over a powerdown of the Core power domain.
> - If [FEAT\_DoPD](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_dopd) is implemented, the values of [EDECR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-28-EDECR--External-Debug-Execution-Control-Register?lang=en#reg_ext_edecr).SS and [EDESR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-29-EDESR--External-Debug-Event-Status-Register?lang=en#reg_ext_edesr).SS are set to 0 on a Cold reset, and, if the PE was stepping an instruction, [EDESR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-29-EDESR--External-Debug-Event-Status-Register?lang=en#reg_ext_edesr).SS is effectively UNKNOWN after a Warm reset. A debugger must use a Reset Catch debug event to step over a powerdown state.
> - A debugger must only change the value of [EDECR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-28-EDECR--External-Debug-Execution-Control-Register?lang=en#reg_ext_edecr).SS when the PE is in Debug state, otherwise behavior is CONSTRAINED UNPREDICTABLE as described in [Changing the value of EDECR.SS when not in Debug state](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H3-Halting-Debug-Events/-H3-2-Halting-Step-debug-events/-H3-2-5-Synchronization-and-the-Halting-Step-state-machine?lang=en#beiccchj).
