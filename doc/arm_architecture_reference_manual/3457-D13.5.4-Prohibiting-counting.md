##### D13.5.4 Prohibiting counting

D JHDZC
:   In this section:

    - *Context* means the Security state, Exception level, and Debug state.
    - Whether event counting for a context is allowed or prohibited by a PE counting an event is defined by the rules in this section.

    [Attributability](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D13-The-Performance-Monitors-Extension/-D13-4-Attributability?lang=en#cacbieia) defines how an event is [Attributable](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D13-The-Performance-Monitors-Extension/-D13-4-Attributability?lang=en#babiidig) to a context.

R QRRHL
:   When all of the following apply:

    - An event is to be counted by event counter <n>.
    - The [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [PMEVTYPER<n>](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-1-Register-name-disambiguation-by-Execution-state?lang=en#cihhcaec).MT is 0 and the event is [Attributable](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D13-The-Performance-Monitors-Extension/-D13-4-Attributability?lang=en#babiidig) to the PE counting the event.
    - The PE counting the event is executing in a context **A**.
    - The event is [Attributable](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D13-The-Performance-Monitors-Extension/-D13-4-Attributability?lang=en#babiidig) to context **B**.

    Then, it is IMPLEMENTATION SPECIFIC which of context **A** or context **B** the PE counting the event uses to determine whether the event is allowed to be counted or is not counted.

    Regardless of whether the event is allowed to be counted or not, if event filtering or any other controls disable counting the event, then the event is not counted.

    It is IMPLEMENTATION SPECIFIC whether event filtering uses context **A** or context **B**.

R XBXZL
:   When all of the following apply:

    - An event is to be counted by event counter <n>.
    - The [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [PMEVTYPER<n>](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-1-Register-name-disambiguation-by-Execution-state?lang=en#cihhcaec).MT is 0 and the event is [Attributable](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D13-The-Performance-Monitors-Extension/-D13-4-Attributability?lang=en#babiidig) to the PE counting the event.
    - The PE counting the event is executing in a context **A**.
    - The event is [Attributable](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D13-The-Performance-Monitors-Extension/-D13-4-Attributability?lang=en#babiidig) to context **B**.

    Then all of the following apply:

    - If both context **A** event counting and context **B** event counting are allowed by the PE counting the event, then the event is allowed to be counted.
    - If context **A** event counting is prohibited by the PE counting the event and context **B** event counting is allowed by the PE counting the event, then it is IMPLEMENTATION SPECIFIC whether the event is allowed to be counted or not counted.
    - If context **B** event counting is prohibited by the PE counting the event, then the event is not counted, regardless of whether context **A** event counting is allowed or prohibited by the PE counting the event.

    Whether event counting for any context is prohibited by the PE the event is [Attributable](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D13-The-Performance-Monitors-Extension/-D13-4-Attributability?lang=en#babiidig) to has no effect on this rule.

    Regardless of whether the event is allowed to be counted or not, if event filtering or any other controls disable counting the event, then the event is not counted. It is IMPLEMENTATION SPECIFIC which of context **A** or context **B** event filtering uses.

    Then the event is not counted. For more information, see [Multithreaded implementations](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D13-The-Performance-Monitors-Extension/-D13-6-Multithreaded-implementations?lang=en#caciaggh).

I SLTTL
:   [RQRRHL](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D13-The-Performance-Monitors-Extension/-D13-5-Controlling-the-PMU-counters/-D13-5-4-Prohibiting-counting?lang=en#qrrhl) and [RXBXZL](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D13-The-Performance-Monitors-Extension/-D13-5-Controlling-the-PMU-counters/-D13-5-4-Prohibiting-counting?lang=en#xbxzl) allow events in a single-threaded implementation to be attributed to the current context when they are counted, rather than requiring the PE to keep track of precisely which context an event was generated in. This is acceptable because the current context changes rarely, meaning such an implementation exhibits [a reasonable degree of inaccuracy](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D13-The-Performance-Monitors-Extension/-D13-2-Accuracy-of-the-Performance-Monitors/-D13-2-2-A-reasonable-degree-of-inaccuracy?lang=en#cacjabcb).

    This would not be acceptable for multithreaded implementations where an event might be generated by a different PE from the PE counting the events. However, these rules permit an implementation to keep track of which PE generated the event and attribute the event to the current context of the PE counting the event. It is also not expected that the controls for prohibiting events in a given context will be set differently on different PEs in a multithreaded implementation that is making use of the PMU multithreading extensions.
