##### K10.4.1 Example ticket lock use of the STSHH hint instruction

[FEAT\_PCDPHINT](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_pcdphint) provides a [`STSHH`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-424-STSHH?lang=en#isa_stshh) hint instruction, that PE software can use to hint to the memory system that if the next instruction the PE executes generates an explicit write effect, it will be to a location being observed, and it might be beneficial if the memory system takes some action to propagate the updated value to the observers with minimal latency.

One example use of [`STSHH`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-424-STSHH?lang=en#isa_stshh) is in ticket lock code, where a thread currently holding the lock can use [`STSHH`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-424-STSHH?lang=en#isa_stshh) before it releases the lock, as illustrated in [Example K10-1](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K10-Software-Usage-Examples/-K10-4-Use-of-the-FEAT-PCDPHINT-STSHH-and-PRFM-IR-hint-instructions/-K10-4-1-Example-ticket-lock-use-of-the-STSHH-hint-instruction?lang=en#ex_stshh_in_ticket_lock_example).

> Example K10-1 Example usage of STSHH in ticket lock code
>
> ```
> ; Consuming portion
>
> SPIN:   LDAR W0, <lock>
>         CMP <assigned ticket_value>, W0
>         B.NE SPIN
> ; ...
>
> ; Producing portion
>         LDR W0, <lock>
>         ADD W0, W0, #0x1
>         STSHH KEEP
>         STLR W0, <lock>
> ```

In [Example K10-1](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K10-Software-Usage-Examples/-K10-4-Use-of-the-FEAT-PCDPHINT-STSHH-and-PRFM-IR-hint-instructions/-K10-4-1-Example-ticket-lock-use-of-the-STSHH-hint-instruction?lang=en#ex_stshh_in_ticket_lock_example):

- There are two counters in the system:

  - Ticket assignment. A counter holding the number of the next ticket in the queue.
  - Current ticket number. Holds the number currently being served.
- In the Consuming portion of the code, the thread has already acquired a ticket from the ticket assignment counter and is waiting for its number to match the current ticket number. The current ticket number increments by one each time a thread holding the lock releases the lock.
- In the Producing portion of the code, the thread has already acquired the lock and finished the task it needed to do while it held the lock, and is now releasing the lock, by:

  1. Incrementing the current ticket number.
  2. Sending a [`STSHH`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-424-STSHH?lang=en#isa_stshh) hint that it is about to perform an explicit write effect, and that it might be beneficial if the memory system takes some action to propagate the updated current ticket number to the other observers as soon as possible.
  3. Storing the updated current ticket number back to the memory system. This releases the lock, allowing the next thread in ticket order to acquire the lock. The observing threads waiting for the current ticket number to match their assigned ticket number might be polling the current ticket counter, or might have executed a [`PRFM IR` (immediate)](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-315-PRFM--immediate-?lang=en#isa_prfm_imm) targeting the current ticket counter.

In [Example K10-1](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K10-Software-Usage-Examples/-K10-4-Use-of-the-FEAT-PCDPHINT-STSHH-and-PRFM-IR-hint-instructions/-K10-4-1-Example-ticket-lock-use-of-the-STSHH-hint-instruction?lang=en#ex_stshh_in_ticket_lock_example), [`STSHH`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-424-STSHH?lang=en#isa_stshh) uses the KEEP policy because if no other observer acquires the lock afterwards, and the thread needs to reenter the task it was doing while it held the lock, it can quickly do so.
