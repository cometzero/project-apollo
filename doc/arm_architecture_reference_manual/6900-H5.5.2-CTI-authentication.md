# ​H5.5.2 CTI authentication

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H5-The-Embedded-Cross-Trigger-Interface/-H5-5-CTI-registers-programmers--model/-H5-5-2-CTI-authentication>

##### H5.5.2 CTI authentication

The CTI ignores the state of the IMPLEMENTATION DEFINED authentication interface. This means that:

- [CTITRIGINSTATUS](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-5-Cross-Trigger-Interface-registers/-H9-5-38-CTITRIGINSTATUS--CTI-Trigger-In-Status-register?lang=en#reg_ext_ctitriginstatus) shows the status of the input triggers and [CTICHINSTATUS](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-5-Cross-Trigger-Interface-registers/-H9-5-6-CTICHINSTATUS--CTI-Channel-In-Status-register?lang=en#reg_ext_ctichinstatus) shows the status of the input channels, regardless of the value of [`ExternalNoninvasiveDebugEnabled`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-20-ExternalNoninvasiveDebugEnabled?lang=en#asl_func_externalnoninvasivedebugenabled_0)`()`.

  > #### Note
  >
  > The PE does not generate the Cross-halt trigger event and the trace unit does not generate Generic trace external output trigger events when [`ExternalNoninvasiveDebugEnabled`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-20-ExternalNoninvasiveDebugEnabled?lang=en#asl_func_externalnoninvasivedebugenabled_0)`()` == FALSE. However, the PE can generate Performance Monitors overflow trigger events.
- The CTI can generate external triggers regardless of the value of [`ExternalInvasiveDebugEnabled`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-18-ExternalInvasiveDebugEnabled?lang=en#asl_func_externalinvasivedebugenabled_0)`()` and [`ExternalNoninvasiveDebugEnabled`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-20-ExternalNoninvasiveDebugEnabled?lang=en#asl_func_externalnoninvasivedebugenabled_0)`()`.

  > #### Note
  >
  > The destination of the trigger is responsible for authenticating the trigger request:
  >
  > - The PE ignores Debug request events when [`ExternalInvasiveDebugEnabled`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-18-ExternalInvasiveDebugEnabled?lang=en#asl_func_externalinvasivedebugenabled_0)`()` is FALSE.
  > - It is IMPLEMENTATION DEFINED whether the PE ignores Restart request trigger events when [`ExternalInvasiveDebugEnabled`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-18-ExternalInvasiveDebugEnabled?lang=en#asl_func_externalinvasivedebugenabled_0)`()` is FALSE.
  > - The trace unit ignores Generic trace external input trigger events when [`ExternalNoninvasiveDebugEnabled`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-20-ExternalNoninvasiveDebugEnabled?lang=en#asl_func_externalnoninvasivedebugenabled_0)`()` is FALSE.
  > - The behavior of Generic CTI interrupt requests is part of the IMPLEMENTATION DEFINED handling of these interrupts, but it is permissible for an interrupt controller to receive these requests even when [`ExternalInvasiveDebugEnabled`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-18-ExternalInvasiveDebugEnabled?lang=en#asl_func_externalinvasivedebugenabled_0)`()` is FALSE, meaning software might need to configure the interrupt controller to ignore these requests.
