# ​G2.9.4 Watchpoint data address comparisons

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-4-Watchpoint-data-address-comparisons>

##### G2.9.4 Watchpoint data address comparisons

An address comparison is successful if bits [31:2] of the current data virtual address are equal to [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn)[31:2], taking into account all of the following:

- The size of the access. See [Size of the data access](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-4-Watchpoint-data-address-comparisons?lang=en#babihjbc).
- The bytes selected by [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn).BAS. See [Programming a watchpoint with eight bytes or fewer](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-4-Watchpoint-data-address-comparisons?lang=en#g3bcghdadb).
- Any address ranges indicated by [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn).MASK. See [Programming a watchpoint with eight or more bytes](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-4-Watchpoint-data-address-comparisons?lang=en#g3bcghdeja).

> #### Note
>
> [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn)[1:0] are RES0 and are ignored.

###### G2.9.4.1 Size of the data access

Because watchpoints can be programmed to generate Watchpoint exceptions on individual bytes, the size of each access must be taken into account. See [Example G2-2](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-4-Watchpoint-data-address-comparisons?lang=en#ex_bcgfgeih).

> Example G2-2
>
> 1. A debugger programs a watchpoint to generate Watchpoint exceptions only when the byte at address `0x1009` is accessed.
> 2. The PE accesses the unaligned doubleword starting at address `0x1003`.
>
> In this scenario, the watchpoint must generate a Watchpoint exception.

The size of data accesses initiated by `DCIMVAC` instructions is an IMPLEMENTATION DEFINED size that is both:

- From the inclusive range between:

  - The size that [CTR](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-2-General-system-control-registers/-G8-2-37-CTR--Cache-Type-Register?lang=en#reg_aarch32_ctr).DminLine defines.
  - 2KB.
- A power-of-two.

The lowest address accessed by a `DCIMVAC` instruction is the address supplied to the instruction, rounded down to the nearest multiple of the access size initiated by that instruction.

The highest address accessed is (size - 1) bytes above the lowest address accessed.

See also, [Watchpoint behavior on accesses by DCIMVAC instructions](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-5-Watchpoint-behavior-for-certain-instruction-classes?lang=en#g3bcgggfdg).

###### G2.9.4.2 Programming a watchpoint with eight bytes or fewer

The Byte Address Select field, [DBGWCR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-26-DBGWCR-n---Debug-Watchpoint-Control-Registers--n---0---15?lang=en#reg_aarch32_dbgwcrn).BAS, selects which bytes in the doubleword starting at the address contained in the [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn) the watchpoint generates Watchpoint exceptions for.

If the address programmed into the [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn) is:

- Doubleword-aligned:

  - All eight bits of [DBGWCR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-26-DBGWCR-n---Debug-Watchpoint-Control-Registers--n---0---15?lang=en#reg_aarch32_dbgwcrn).BAS are used, and the descriptions given in [Table G2-16](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-4-Watchpoint-data-address-comparisons?lang=en#tbl_g3bcgfbfab) apply.
- Word-aligned but not doubleword-aligned:

  - Only [DBGWCR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-26-DBGWCR-n---Debug-Watchpoint-Control-Registers--n---0---15?lang=en#reg_aarch32_dbgwcrn).BAS[3:0] are used, and the descriptions given in [Table G2-17](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-4-Watchpoint-data-address-comparisons?lang=en#tbl_g3bcgjdjhe) apply. In this case, [DBGWCR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-26-DBGWCR-n---Debug-Watchpoint-Control-Registers--n---0---15?lang=en#reg_aarch32_dbgwcrn).BAS[7:4] are RES0.

a. [DBGWCR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-26-DBGWCR-n---Debug-Watchpoint-Control-Registers--n---0---15?lang=en#reg_aarch32_dbgwcrn).BAS[7:4] are RES0.

If the BAS field selects more than one byte, the bytes it selects must be contiguous. For watchpoint behavior when its BAS field selects non-contiguous bytes, see [Other usage constraints](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-6-Watchpoint-usage-constraints?lang=en#g3bcgidfib).

When programming the BAS field with anything other than `0b11111111`, a debugger must also program [DBGWCR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-26-DBGWCR-n---Debug-Watchpoint-Control-Registers--n---0---15?lang=en#reg_aarch32_dbgwcrn).MASK to be `0b00000`. See [Programming dependencies of the BAS and MASK fields](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-6-Watchpoint-usage-constraints?lang=en#g3bcghhdgb).

A watchpoint generates a Watchpoint exception whenever a watched byte is accessed, even if:

- The access size is smaller or larger than the address region being watched.
- The access is misaligned, and the base address of the access is not in the doubleword or word of memory addressed by the [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn)[31:3]. See [Example G2-2](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-4-Watchpoint-data-address-comparisons?lang=en#ex_bcgfgeih).

The following are some example configurations of the BAS field:

- To program a watchpoint to generate a Watchpoint exception on the byte at address `0x1003`, program:

  - [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn) with `0x1000`.
  - [DBGWCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-11-DBGWCR-n--EL1--Debug-Watchpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgwcrn_el1).BAS to be `0b00001000`.
- To program a watchpoint to generate a Watchpoint exception on the bytes at addresses `0x2003`, `0x2004` and `0x2005`, program:

  - [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn) with `0x2000`.
  - [DBGWCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-11-DBGWCR-n--EL1--Debug-Watchpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgwcrn_el1).BAS to be `0b00111000`.
- If the address programmed into the [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn) is doubleword-aligned:

  - To generate a Watchpoint exception when any byte in the word starting at the doubleword-aligned address is accessed, program [DBGWCR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-26-DBGWCR-n---Debug-Watchpoint-Control-Registers--n---0---15?lang=en#reg_aarch32_dbgwcrn).BAS to be `0b00001111`.
  - To generate a Watchpoint exception when any byte in the word starting at address [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn)[31:3]:100 is accessed, program [DBGWCR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-26-DBGWCR-n---Debug-Watchpoint-Control-Registers--n---0---15?lang=en#reg_aarch32_dbgwcrn).BAS to be `0b11110000`.

> #### Note
>
> Arm deprecates programming a [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn) with an address that is not doubleword-aligned.

###### G2.9.4.3 Programming a watchpoint with eight or more bytes

A debugger can use the *MASK* field, [DBGWCR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-26-DBGWCR-n---Debug-Watchpoint-Control-Registers--n---0---15?lang=en#reg_aarch32_dbgwcrn).MASK, to program a single watchpoint with a data address range. The data address range must meet all of the following criteria:

- It is a size that is both:

  - A power-of-two.
  - A minimum of eight bytes.
  - A maximum of 2GB.
- It starts at an address that is aligned to the size.

The MASK field specifies the number of least significant data address bits that must be masked. Up to 31 least significant bits can be masked.

If *n* least significant address bits are masked, the watchpoint generates a Watchpoint exception on all of the following:

- Address [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn)[31:*n*]:000…
- Address [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn)[31:*n*]:111…
- Any address between these two addresses.

For example, if the four least significant address bits are masked, Watchpoint exceptions are generated for all addresses between [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn)[31:4]:0000 and [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn)[31:4]:1111, including these addresses.

> #### Note
>
> - The most significant bit cannot be masked. This means that the full address cannot be masked.
> - For watchpoint behavior when its MASK field is programmed with a reserved value, see [Reserved DBGWCR<n>.MASK values](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-6-Watchpoint-usage-constraints?lang=en#babbieaf).

When masking address bits, a debugger must both:

- Program [DBGWCR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-26-DBGWCR-n---Debug-Watchpoint-Control-Registers--n---0---15?lang=en#reg_aarch32_dbgwcrn).BAS to be `0b11111111`. See [Programming dependencies of the BAS and MASK fields](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-6-Watchpoint-usage-constraints?lang=en#g3bcghhdgb).
- In the [DBGWVR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-28-DBGWVR-n---Debug-Watchpoint-Value-Registers--n---0---15?lang=en#reg_aarch32_dbgwvrn), set the masked address bits to 0. For watchpoint behavior when any of the masked address bits are not 0, see [Other usage constraints](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G2-AArch32-Self-hosted-Debug/-G2-9-Watchpoint-exceptions/-G2-9-6-Watchpoint-usage-constraints?lang=en#g3bcgidfib).
