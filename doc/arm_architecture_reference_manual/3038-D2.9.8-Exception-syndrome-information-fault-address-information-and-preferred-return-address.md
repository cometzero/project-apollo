# ​D2.9.8 Exception syndrome information, fault address information, and preferred return address

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D2-AArch64-Self-hosted-Debug/-D2-9-Watchpoint-exceptions/-D2-9-8-Exception-syndrome-information--fault-address-information--and-preferred-return-address>

##### D2.9.8 Exception syndrome information, fault address information, and preferred return address

On taking a Watchpoint exception or entering Debug state for a Watchpoint debug event, the PE records the following:

- Information about the debug event or exception in a *syndrome register*. No information is recorded if the watchpoint causes the PE to enter Debug state and [FEAT\_EDHSR](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-10-The-Armv8-9-architecture-extension?lang=en#feat_feat_edhsr) is not implemented.
- An address that the debugger can use to determine the memory location that caused the watchpoint, in a *Fault Address Register*. No address is recorded if the PE sets the FnV bit in the syndrome register to 1, as described in [Fault address information](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D2-AArch64-Self-hosted-Debug/-D2-9-Watchpoint-exceptions/-D2-9-8-Exception-syndrome-information--fault-address-information--and-preferred-return-address?lang=en#fault_address_information).

The syndrome register and fault address register used are one of the following:

- For a Watchpoint exception taken to EL1, [ESR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-44-ESR-EL1--Exception-Syndrome-Register--EL1-?lang=en#reg_aarch64_esr_el1) and [FAR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-47-FAR-EL1--Fault-Address-Register--EL1-?lang=en#reg_aarch64_far_el1).
- For a Watchpoint exception taken to EL2, [ESR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-45-ESR-EL2--Exception-Syndrome-Register--EL2-?lang=en#reg_aarch64_esr_el2) and [FAR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-48-FAR-EL2--Fault-Address-Register--EL2-?lang=en#reg_aarch64_far_el2).
- For a Watchpoint debug event that causes entry to Debug state, [EDHSR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-30-EDHSR--External-Debug-Halting-Syndrome-Register?lang=en#reg_ext_edhsr), if implemented, and [EDWAR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-51-EDWAR--External-Debug-Watchpoint-Address-Register?lang=en#reg_ext_edwar).

In cases where one instruction triggers multiple watchpoints, only one address is recorded.

See [ISS encoding for an exception from a Watchpoint exception](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-44-ESR-EL1--Exception-Syndrome-Register--EL1-?lang=en#fieldset_aarch64_esr_el1_fieldset_0_iss_an_exception_from_a_watchpoint_exception) for more information.

> #### Note
>
> Watchpoint exceptions cannot be taken to EL3 using AArch64.

        - No larger than the smallest implemented translation granule if [ESR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#esr_elx).FnP or [EDHSR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-30-EDHSR--External-Debug-Halting-Syndrome-Register?lang=en#reg_ext_edhsr).FnP is 1.
        - Contains a watchpointed address accessed by the memory access or set of contiguous memory accesses that triggered the watchpoint, or a watchpointed address in the address range permitted by [RLVLYV](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D2-AArch64-Self-hosted-Debug/-D2-9-Watchpoint-exceptions/-D2-9-6-Watchpoint-behavior-for-certain-instruction-classes?lang=en#lvlyv) in [Watchpoint behavior on accesses by SVE and SME instructions](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D2-AArch64-Self-hosted-Debug/-D2-9-Watchpoint-exceptions/-D2-9-6-Watchpoint-behavior-for-certain-instruction-classes?lang=en#cegbhhifb7).

        The size of the naturally-aligned block of memory is IMPLEMENTATION DEFINED. There is no architectural means of discovering the size.

D WNGCC
:   Watchpointed address
    :   Is defined as follows:

        - If all watchpoints are address match watchpoints, then a watchpointed address is any address for which at least one of the address match watchpoints generates a watchpoint match.
        - If all watchpoints are address mismatch watchpoints, then a watchpointed address is any address for which all address mismatch watchpoints generate a watchpoint match.
        - Otherwise, a watchpointed address is any address for which at least one of the address match watchpoints generates a watchpoint match and all address mismatch watchpoints generate a watchpoint match.

:   When an instruction generates multiple watchpoint matches and the PE sets [ESR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#esr_elx).WPTV to 1 on taking a Watchpoint exception generated by the watchpoint match, or [FEAT\_EDHSR](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-10-The-Armv8-9-architecture-extension?lang=en#feat_feat_edhsr) is implemented and the PE sets [EDHSR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-30-EDHSR--External-Debug-Halting-Syndrome-Register?lang=en#reg_ext_edhsr).WPTV to 1 on entering Debug state on a Watchpoint debug event generated by the watchpoint match, then the value <n> reported in [ESR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#esr_elx).WPT or [EDHSR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-30-EDHSR--External-Debug-Halting-Syndrome-Register?lang=en#reg_ext_edhsr).WPT, is defined as follows:

    - If all the matching watchpoints are address match watchpoints or all the matching watchpoints are address mismatch watchpoints, then <n> is any watchpoint that generates a watchpoint match.
    - Otherwise, <n> is any address match watchpoint that generates a watchpoint match.

**D2.9.8.2.4 Address recorded for Watchpoint exceptions generated by other instructions**

The address recorded by other instructions must be both:

- From the inclusive range between:

  - The lowest address accessed by the memory access or set of contiguous memory accesses that triggered the watchpoint.
  - The highest [watchpointed address](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D2-AArch64-Self-hosted-Debug/-D2-9-Watchpoint-exceptions/-D2-9-8-Exception-syndrome-information--fault-address-information--and-preferred-return-address?lang=en#watchpointed_address) accessed by the memory access or set of contiguous memory accesses that triggered the watchpoint.
- Within a naturally-aligned block of memory.

> Example D2-10 Address recorded for a watchpoint programmed on `0x8019`
>
> A debugger programs a watchpoint to generate a Watchpoint exception on any access to the byte `0x8019`.
>
> An A32 load multiple instruction then loads nine registers starting from address `0x8004` upwards. This triggers the watchpoint.
>
> If the `DC ZVA` block size is:
>
> - 32 bytes, the address that the PE records must be between `0x8004` and `0x8019` inclusive.
> - 16 bytes, the address that the PE records must be between `0x8010` and `0x8019` inclusive.

###### D2.9.8.3 Preferred return address

The preferred return address of a Watchpoint exception is the address of the instruction that was not executed because the PE took the Watchpoint exception instead.

This means that the preferred return address is the address of the instruction that caused the exception.
