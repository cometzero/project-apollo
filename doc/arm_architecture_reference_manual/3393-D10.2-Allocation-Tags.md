# ​D10.2 Allocation Tags

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D10-The-Memory-Tagging-Extension/-D10-2-Allocation-Tags>

#### D10.2 Allocation Tags

D LLSFJ
:   All statements in this section require implementation of [FEAT\_MTE2](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-6-The-Armv8-5-architecture-extension?lang=en#feat_feat_mte2).

R CWPLY
:   Each set of 16 naturally-aligned bytes in memory is a *Tag Granule*.

R XQBST
:   Each *Tag Granule* is associated with an *Allocation Tag* in memory.

R CRCLC
:   An *Allocation Tag* is a 4-bit value.

R QYCTT
:   All accesses to any *Allocation Tag* are single-copy atomic.

R CPMDB
:   All implicit and explicit accesses to *Allocation Tags* are regarded as streams of accesses to *Allocation Tags*, and no atomicity between accesses to different *Allocation Tags*, or between accesses to *Allocation Tags* and accesses to bytes, is ensured by the architecture.

R YSRGL
:   An instruction that explicitly accesses an *Allocation Tag* at a VA accesses the *Allocation Tag* at the VA aligned to the *Tag Granule*.

R PJCWS
:   For an instruction that explicitly accesses both *Allocation Tags* and data, any [MMU faults](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-15-Memory-aborts?lang=en#aa64_mmu_fault) generated by the separate accesses are not ordered.
