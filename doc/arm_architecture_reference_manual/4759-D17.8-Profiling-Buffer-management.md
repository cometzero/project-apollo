# ​D17.8 Profiling Buffer management

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-8-Profiling-Buffer-management>

#### D17.8 Profiling Buffer management

R FJDLW
:   A Profiling Buffer management event occurs:

    - On a fault, see [Faults and watchpoints](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-8-Profiling-Buffer-management/-D17-8-3-Faults-and-watchpoints?lang=en#chdghbbg).
    - On an External abort, see [External aborts](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-8-Profiling-Buffer-management/-D17-8-4-External-aborts?lang=en#chdhjjdh).
    - When the Profiling Buffer fills, see [Buffer full event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-8-Profiling-Buffer-management/-D17-8-2-Buffer-full-event?lang=en#chdifiih).
    - When the access is not allowed for other reasons, see [Access not allowed](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-8-Profiling-Buffer-management/-D17-8-5-Access-not-allowed?lang=en#cacgebgeg0).
    - For IMPLEMENTATION DEFINED reasons, see [Implementation defined reason](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-8-Profiling-Buffer-management/-D17-8-6-Implementation-defined-reason?lang=en#cacbbbhad5).

I QRJYF
:   The Profiling Buffer management event behavior differs from that of the [FEAT\_TRBE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-1-The-Armv9-0-architecture-extension?lang=en#feat_feat_trbe) trace buffer management event.

R NXZXG
:   On a Profiling Buffer management event:

    - The service bit, [PMBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#pmbsr_elx).S, is set to 1.
    - The data loss bit, [PMBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#pmbsr_elx).DL, is set as described in the event description.
    - Additional syndrome for the event is written to [PMBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#pmbsr_elx).MSS.

    The value of ELx depends on the type of event, and is defined by [RHJXHT](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-8-Profiling-Buffer-management?lang=en#hjxht). Unless otherwise stated in the event description, other fields in [PMBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#pmbsr_elx) and the other [PMBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#pmbsr_elx) registers are unchanged.

R WVKFM
:   The following Profiling Buffer management events are reported synchronously:

    - Buffer full events.
    - If [FEAT\_SPEv1p5](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_spev1p5) is not implemented, Alignment fault and MMU fault events.

    If [FEAT\_SPEv1p3](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-9-The-Armv8-8-architecture-extension?lang=en#feat_feat_spev1p3) is not implemented, it is IMPLEMENTATION DEFINED whether External aborts are reported to the Statistical Profiling Unit synchronously or asynchronously.

    *Reported synchronously* means that profiling is disabled before the Statistical Profiling Unit samples further operations. The interrupt or Profiling exception resulting from recording the Profiling Buffer management event is an asynchronous exception.

    When [FEAT\_SPEv1p5](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_spev1p5) is implemented, the Statistical Profiling Unit is permitted to sample further operations after the sampled operation that generates the Alignment fault or MMU fault Profiling Buffer management event. This means that one or more samples might be discarded because of the Alignment fault or MMU fault Profiling Buffer management event.

R THGCR
:   The SPU never writes past the [PMBLIMITR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-2-PMBLIMITR-EL1--Profiling-Buffer-Limit-Address-Register?lang=en#reg_aarch64_pmblimitr_el1) limit pointer.

I QRKCL
:   Software cannot assume that:

    - The PE has not modified memory between the current [PMBPTR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-4-PMBPTR-EL1--Profiling-Buffer-Write-Pointer-Register?lang=en#reg_aarch64_pmbptr_el1) write pointer and the [PMBLIMITR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-2-PMBLIMITR-EL1--Profiling-Buffer-Limit-Address-Register?lang=en#reg_aarch64_pmblimitr_el1) limit pointer minus one.
    - The data between the current [PMBPTR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-4-PMBPTR-EL1--Profiling-Buffer-Write-Pointer-Register?lang=en#reg_aarch64_pmbptr_el1) write pointer and the [PMBLIMITR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-2-PMBLIMITR-EL1--Profiling-Buffer-Limit-Address-Register?lang=en#reg_aarch64_pmblimitr_el1) limit pointer minus one is valid.
    - If [PMBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#pmbsr_elx).DL is set to 1 on a Profiling Buffer management event, that there is any valid data between the end of the last complete sample record and the current [PMBPTR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-4-PMBPTR-EL1--Profiling-Buffer-Write-Pointer-Register?lang=en#reg_aarch64_pmbptr_el1) write pointer. The value of ELx depends on the type of event. See [RHJXHT](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-8-Profiling-Buffer-management?lang=en#hjxht).
    - *Any* valid data has been written to the Profiling Buffer if an External abort is reported asynchronously to the SPU. For more information, see [The External abort generates a MMU fault](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-8-Profiling-Buffer-management/-D17-8-4-External-aborts?lang=en#spe_external_abort_mmu_fault).

I VJVKZ
:   The Statistical Profiling Unit generates PMU events and [CTI trigger events](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H5-The-Embedded-Cross-Trigger-Interface/-H5-4-Description-and-allocation-of-CTI-triggers/-H5-4-5-Statistical-Profiling-Extension-sample-trigger-event?lang=en#cegjgegh) when a sampled operation completes.

    If writing records to the Profiling Buffer generates an MMU fault, one or more of these events might have been generated for one or more sampled operations that are discarded because of the MMU fault.

That is, any of the following faults on a write to the Profiling Buffer:

        - If [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).GPF is 1, GPFs.
        - If [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).EA is 1, External aborts.       - [MDCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-18-MDCR-EL3--Monitor-Debug-Configuration-Register--EL3-?lang=en#reg_aarch64_mdcr_el3).PMSEE is `0b10` and the management event is an IMPLEMENTATION DEFINED buffer management event that the implementation elects to record in [PMBSR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-7-PMBSR-EL3--Profiling-Buffer-Syndrome-Register--EL3-?lang=en#reg_aarch64_pmbsr_el3).
    - Otherwise, if all of the following are true, then the management event is recorded in [PMBSR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-6-PMBSR-EL2--Profiling-Buffer-Syndrome-Register--EL2-?lang=en#reg_aarch64_pmbsr_el2):

      - EL3 is not implemented or [MDCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-18-MDCR-EL3--Monitor-Debug-Configuration-Register--EL3-?lang=en#reg_aarch64_mdcr_el3).PMSEE is not `0b00`.
      - EL2 is implemented and any of the following are true:

        - The [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).NS is 1.
        - The [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).{NS, EEL2} is {0, 1}.

However, External aborts on translation table walks, translation table updates, and GPT walks can be reported as MMU faults. I JVQRY
:   [Table D17-5](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-8-Profiling-Buffer-management?lang=en#tbl_speprofilebuffereventgcp), [Table D17-6](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-8-Profiling-Buffer-management?lang=en#tbl_spebuffereventexternalabort), and [Table D17-7](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-8-Profiling-Buffer-management?lang=en#tbl_spebuffereventother) show which [PMBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#pmbsr_elx) register used to record the syndrome for each type of Profiling Buffer management event.

    Each column in the left side of the tables refers to the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of a field in a System register.

    Each column in the right side of the tables represents a Profiling Buffer management event:

    Other event
    :   Means a Profiling Buffer management event recorded with the EC value `0b000000`.

    Stage 1 (GPF)
    :   Means a Profiling Buffer management event for a Granule Protection Fault (GPF) reported as a stage 1 abort on a write to the buffer, recorded with the EC value of `0b100100` and an FSC value indicating a GPF.

    Stage 1 (External abort)
    :   Means a Profiling Buffer management event for an External abort reported as a stage 1 abort on a write to the buffer, recorded with the EC value of `0b100100` and an FSC value indicating an External abort.

    Stage 1 (Other abort)
    :   Means a Profiling Buffer management event for any other stage 1 abort on a write to the buffer, recorded with the EC value `0b100100`.

    Stage 2 (GPF)
    :   Means a Profiling Buffer management event for a GPF reported as a stage 2 abort on a write to the buffer, recorded with the EC value of `0b100101` and an FSC value indicating a GPF.

    Stage 2 (External abort)
    :   Means a Profiling Buffer management event for an External abort reported as a stage 2 abort on a write to the buffer, recorded with the EC value of `0b100101` and an FSC value indicating an External abort. That is, a synchronous External abort on a stage 2 translation table walk or translation table update.

    Stage 2 (Other abort)
    :   Means a Profiling Buffer management event for any other stage 2 abort on a write to the buffer, recorded with the EC value `0b100101`.

    GPC fault
    :   Means a Profiling Buffer management event for a Granule Protection Check fault, other than a GPF, on a write to the buffer, recorded with the EC value `0b011110`.

    The values in these cells denotes which [PMBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#pmbsr_elx) register is updated for that combination of control register values and Profiling Buffer management event type.

    - The [owning Exception level](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-7-The-Profiling-Buffer/-D17-7-5-The-owning-translation-regime?lang=en#spe_owning_el) is EL2, because EL2 has mapped the Profiling Buffer in the EL2 translation regime, but EL1 can handle all non-MMU management events, and so EL2 programs [PMSCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-9-PMSCR-EL2--Statistical-Profiling-Control-Register--EL2-?lang=en#reg_aarch64_pmscr_el2).EE to `0b10`.

R YMRRB
:   When [FEAT\_SPE\_EXC](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_spe_exc) is implemented, SPE Profiling exceptions are taken asynchronously and precisely.

R NXPMV
:   When [FEAT\_SPE\_EXC](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_spe_exc) is implemented, if an SPE Profiling exception is enabled and unmasked, and all of the following are true, then the SPE Profiling exception will be taken before an instruction **C** completes execution:

    - Instruction **A** is one of the following:

      - A direct read of the corresponding [PMBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#pmbsr_elx) register that observes that the S bit is 1.
      - A direct write of the corresponding [PMBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#pmbsr_elx) register that sets the S bit to 1.
      - A `PSB CSYNC` instruction that synchronizes a profiling operation that causes a Profiling Buffer management event that sets the corresponding [PMBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#pmbsr_elx).S bit to 1. For more information, see [Synchronization and Statistical Profiling](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-9-Synchronization-and-Statistical-Profiling?lang=en#chdedead).
    - **C** follows in program order immediately after a Context synchronization event **B**.
    - **B** is in program order after **A**.

    Otherwise, the SPE Profiling exception is taken in finite time.

R TSJRP
:   If any of the following are true, then the SPE interrupt request (**PMBIRQ**) is enabled and driven from [PMBSR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-5-PMBSR-EL1--Profiling-Buffer-Status-syndrome-Register--EL1-?lang=en#reg_aarch64_pmbsr_el1).S:

    - EL2 is implemented, [PMSCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-9-PMSCR-EL2--Statistical-Profiling-Control-Register--EL2-?lang=en#reg_aarch64_pmscr_el2).EE is `0b00`, and any of the following are true:

      - The [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).NS is 1.
      - The [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).{NS, EEL2} is {0, 1}.

    - [PMSCR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-8-PMSCR-EL1--Statistical-Profiling-Control-Register--EL1-?lang=en#reg_aarch64_pmscr_el1).EE is `0b00`.

    Otherwise, if [FEAT\_SPE\_EXC](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_spe_exc) is implemented, then the SPE interrupt request is disabled and driven LOW (inactive).

    The pseudocode function [`SPEInterruptEnabled`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-94-SPEInterruptEnabled?lang=en#asl_func_speinterruptenabled_0)`()` shows this.

I GRLRX
:   When the **PMBIRQ** is enabled:

    - A direct write that sets [PMBSR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-5-PMBSR-EL1--Profiling-Buffer-Status-syndrome-Register--EL1-?lang=en#reg_aarch64_pmbsr_el1).S to 1 causes the interrupt to be asserted.
    - **PMBIRQ** will remain asserted until software clears [PMBSR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-7-Statistical-Profiling-Extension-registers/-D24-7-5-PMBSR-EL1--Profiling-Buffer-Status-syndrome-Register--EL1-?lang=en#reg_aarch64_pmbsr_el1).S to 0.

I SMLLS
:   If a Generic Interrupt Controller (GIC) is implemented, **PMBIRQ** must be configured as a Private Peripheral Interrupt (PPI) in a multiprocessor system. **PMBIRQ** is signaled by the PE that implements the SPU.

    > #### Note
    >
    > A standard PPI number is allocated by the *Arm® Base System Architecture* (BSA).
