# ​D21.3.1 PARTID virtualization

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-3-Partition-Identifiers--PARTIDs-/-D21-3-1-PARTID-virtualization>

##### D21.3.1 PARTID virtualization

R DNZFT
:   The behaviors in this section apply if all the following are true:

    - EL2 is implemented and enabled in the current Security state.
    - Any [FEAT\_MPAM version](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-1-About-MPAM/-D21-1-8-FEAT-MPAM-versions?lang=en#mpam_feat_mpam_versions) is implemented.
    - [MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).HAS\_HCR is 1, meaning that the MPAM virtualization option is implemented.
    - If a version other than v1p0 is implemented and execution is in Secure state, then in addition:

      - [MPAM3\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-4-MPAM3-EL3--MPAM3-Register--EL3-?lang=en#reg_aarch64_mpam3_el3).SDEFLT is 0, preventing generation of the [Default physical PARTID](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-3-Partition-Identifiers--PARTIDs-/-D21-3-2-The-Default-PARTID?lang=en#mpam_default_partid) in Secure state. See [Effect of the MPAM3\_EL3.{SDEFLT, FORCE\_NS} controls on MPAM PE Secure state execution](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-5-Effect-of-the-MPAM3-EL3--SDEFLT--FORCE-NS--controls-on-PE-Secure-state-execution?lang=en#mpam_effect_mpam_el3_sdeflt_force_ns_on_pe_secure_state_execution).

I PKKWM
:   EL2 hypervisor software continuously updates *MPAM virtual PARTID mapping registers*, [MPAMVPM0\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-15-MPAMVPM0-EL2--MPAM-Virtual-PARTID-Mapping-Register-0?lang=en#reg_aarch64_mpamvpm0_el2) to [MPAMVPM7\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-22-MPAMVPM7-EL2--MPAM-Virtual-PARTID-Mapping-Register-7?lang=en#reg_aarch64_mpamvpm7_el2), that map virtual [PARTIDs](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-3-Partition-Identifiers--PARTIDs-?lang=en#mpam_partition_identifiers) to physical PARTIDs.

I TSKGT
:   Each [MPAMVPMn\_EL2](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpamvpmn_elx) register contains four *mapping fields*, and the maximum implemented [MPAMVPMn\_EL2](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpamvpmn_elx) is [MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).VPMR\_MAX. Therefore, the maximum implemented mapping field is (4 x VPMR\_MAX) + 3, and virtualized guests are limited to mapping fields in the range 0 to (4 x VPMR\_MAX) + 3.

I TXFDH
:   > Example D21-1
    >
    > If MPAMIDR\_EL1.VPMR\_MAX reports:
    >
    > - `0b000`, the maximum implemented register is [MPAMVPM0\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-15-MPAMVPM0-EL2--MPAM-Virtual-PARTID-Mapping-Register-0?lang=en#reg_aarch64_mpamvpm0_el2), and the maximum implemented mapping field is (4 x 0) + 3 = 3. There are therefore four virtual PARTIDs available for virtualized guests, numbered 0 to 3, that can be mapped to physical PARTIDs.
    > - `0b111`, the maximum implemented register is [MPAMVPM7\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-22-MPAMVPM7-EL2--MPAM-Virtual-PARTID-Mapping-Register-7?lang=en#reg_aarch64_mpamvpm7_el2), and the maximum implemented mapping field is (4 x 7) + 3 = 31. There are therefore 32 virtual PARTIDs available for virtualized guests, numbered 0 to 31, that can be mapped to physical PARTIDs.

R QMSMK
:   When:

    - [MPAMHCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-12-MPAMHCR-EL2--MPAM-Hypervisor-Control-Register--EL2-?lang=en#reg_aarch64_mpamhcr_el2).EL0\_VPMEN is 1, the PARTIDs in [MPAM0\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-1-MPAM0-EL1--MPAM0-Register--EL1-?lang=en#reg_aarch64_mpam0_el1).{PARTID\_D, PARTID\_I} are *treated as virtual*, and EL0 produces requests with [virtual PARTID spaces](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-3-Partition-Identifiers--PARTIDs-/-D21-3-1-PARTID-virtualization?lang=en#mdterm_virtual_partid_spaces).
    - [MPAMHCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-12-MPAMHCR-EL2--MPAM-Hypervisor-Control-Register--EL2-?lang=en#reg_aarch64_mpamhcr_el2).EL1\_VPMEN is 1, the PARTIDs in [MPAM1\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-2-MPAM1-EL1--MPAM1-Register--EL1-?lang=en#reg_aarch64_mpam1_el1).{PARTID\_D, PARTID\_I} are treated as virtual, and EL1 produces requests with virtual PARTID spaces.

    When a PARTID is treated as virtual, the MPAM PE attempts to map the PARTID to a physical PARTID using a MPAM virtual PARTID mapping register [MPAMVPMn\_EL2](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpamvpmn_elx). The PARTID that is treated as virtual is used as an index into both:

    - The vector of physical PARTIDs that the mapping registers hold.
    - The array of valid flags that [MPAMVPMV\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-23-MPAMVPMV-EL2--MPAM-Virtual-Partition-Mapping-Valid-Register?lang=en#reg_aarch64_mpamvpmv_el2) holds.

I XGFNP
:   > Example D21-2 Example of an MPAM PE mapping a virtual PARTID to a physical PARTID
    >
    > Assume all the following are true:
    >
    > - EL2 is implemented and enabled in the current Security state.
    > - Version v1p1 of FEAT\_MPAM is implemented, [MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).HAS\_HCR is 1, meaning that the MPAM virtualization option is implemented, and [MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).HAS\_SDEFLT is 0, meaning that [MPAM3\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-4-MPAM3-EL3--MPAM3-Register--EL3-?lang=en#reg_aarch64_mpam3_el3).SDEFLT is not implemented.
    > - [MPAMHCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-12-MPAMHCR-EL2--MPAM-Hypervisor-Control-Register--EL2-?lang=en#reg_aarch64_mpamhcr_el2).EL1\_VPMEN is 1, meaning that PARTIDs in [MPAM1\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-2-MPAM1-EL1--MPAM1-Register--EL1-?lang=en#reg_aarch64_mpam1_el1).{PARTID\_D, PARTID\_I} are treated as virtual.
    > - [MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).VPMR\_MAX is `0b010`, meaning that the maximum implemented mapping field is (4 x 2) + 3 = 11.
    > - The value of [MPAM1\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-2-MPAM1-EL1--MPAM1-Register--EL1-?lang=en#reg_aarch64_mpam1_el1).PARTID\_D is 6.
    >
    > In this example, 6 is treated as virtual and is the index into the array of valid flags and vector of physical PARTIDs. Behavior is:
    >
    > 1. Valid flag [MPAMVPMV\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-23-MPAMVPMV-EL2--MPAM-Virtual-Partition-Mapping-Valid-Register?lang=en#reg_aarch64_mpamvpmv_el2).VPM\_V<6> is checked:
    >
    >    1. A result of 1 means a valid mapping exists for virtual PARTID 6.
    >
    >       [MPAMVPM1\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-16-MPAMVPM1-EL2--MPAM-Virtual-PARTID-Mapping-Register-1?lang=en#reg_aarch64_mpamvpm1_el2).PhysPARTID6 contains the physical PARTID that the MPAM PE Requester sends.
    >    2. A result of 0 means *invalid*.
    > 2. If the result is invalid, the mapping for the [Default virtual PARTID](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-3-Partition-Identifiers--PARTIDs-/-D21-3-2-The-Default-PARTID?lang=en#mpam_default_partid), 0, is used. If a valid mapping does not exist for virtual PARTID 0, the MPAM PE Requester sends the [Default physical PARTID](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-3-Partition-Identifiers--PARTIDs-/-D21-3-2-The-Default-PARTID?lang=en#mpam_default_partid).

R XSJVY
:   The virtual PARTID spaces are:

    - If Secure state is implemented, Secure virtual PARTID space. This translates to the Secure physical PARTID space.
    - Non-secure virtual PARTID space. This translates to the Non-secure physical PARTID space.
    - If [FEAT\_RME](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-3-The-Armv9-2-architecture-extension?lang=en#feat_feat_rme) is implemented, Realm virtual PARTID space. This translates to the Realm physical PARTID space.

I BSWTR
:   If a virtual PARTID is greater than (4 x [MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).VPMR\_MAX) + 3, it is an *out-of-range virtual PARTID*.

R QTSFN
:   When a PARTID is an out-of-range virtual PARTID, the behavior is a CONSTRAINED UNPREDICTABLE choice of:

    - The out-of-range virtual PARTID is replaced by any in-range virtual PARTID in the same PARTID space.
    - The out-of-range virtual PARTID is replaced by the [Default physical PARTID](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-3-Partition-Identifiers--PARTIDs-/-D21-3-2-The-Default-PARTID?lang=en#mpam_default_partid) in the same PARTID space.

I HWFQY
:   In each [MPAMVPMn\_EL2](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpamvpmn_elx).PhyPARTID<n> mapping field, the architecture requires implementation of sufficient low-order bits to represent [MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).PARTID\_MAX. It is permitted to implement the bits that are higher-order than MPAMIDR\_EL1.PARTID\_MAX as RAZ/WI.
