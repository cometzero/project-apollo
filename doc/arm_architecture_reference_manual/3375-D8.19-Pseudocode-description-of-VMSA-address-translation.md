# ​D8.19 Pseudocode description of VMSA address translation

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-19-Pseudocode-description-of-VMSA-address-translation>

#### D8.19 Pseudocode description of VMSA address translation

I ZMHCV
:   The Arm architecture defines pseudocode that describes the translation table walk.

I STKYL
:   **Full Physical Address**

    A complete PA necessary to identify a location in physical memory is captured by the type `FullAddress`. This is composed of:

    - A bitstring `address`, which identifies the PA.
    - An enumeration `paspace` which identifies the PA space.

I MXLCQ
:   **Address translation**

    [`AArch64_TranslateAddress`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-703-AArch64-TranslateAddress?lang=en#asl_func_aarch64_translateaddress_4)`()` acts as the entry point to VMSA and performs the required address translation based on the provided parameters and System register configurations. The function returns an [`AddressDescriptor`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-801-AddressDescriptor?lang=en#asl_type_addressdescriptor) structure holding valid data for either of the following:

    - Target memory address and attributes for a non-faulting translation.
    - Fault details holding data to be populated in syndrome registers.

I LTNYC
:   [`AArch64_FullTranslate`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-692-AArch64-FullTranslate?lang=en#asl_func_aarch64_fulltranslate_4)`()` selects the translation regime and performs first and potentially second stage of translation returning the PA and attributes of target memory. [`AArch64_S1Translate`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-695-AArch64-S1Translate?lang=en#asl_func_aarch64_s1translate_6)`()` carries out the first stage of translation when stage 1 is not disabled, mapping the VA to the IPA and carrying out permission checks. Otherwise, [`AArch64_S1DisabledOutput`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-694-AArch64-S1DisabledOutput?lang=en#asl_func_aarch64_s1disabledoutput_5)`()` assigns the appropriate memory attributes and flat maps the input address to the output address. [`AArch64_S2Translate`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-697-AArch64-S2Translate?lang=en#asl_func_aarch64_s2translate_5)`()` carries out stage 2 translation for the EL1&0 translation regime when enabled mapping the IPA to the PA. Otherwise, the IPA is the PA.

I KKVJD
:   **Translation table walk**

    Each stage of translation has a separate walk function, [`AArch64_S1Walk`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-715-AArch64-S1Walk?lang=en#asl_func_aarch64_s1walk_6)`()` and [`AArch64_S2Walk`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-719-AArch64-S2Walk?lang=en#asl_func_aarch64_s2walk_5)`()`, corresponding to the first and second stage of translation respectively. Each use walk parameters extracted from related System registers. Parameters are collected based on the active translation regime.

    For instance, stage 1 EL2 translation regime parameters are obtained and returned by the function [`AArch64_S1TTWParamsEL2`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-744-AArch64-S1TTWParamsEL2?lang=en#asl_func_aarch64_s1ttwparamsel2_1)`()`. Given these parameters, a walk initializes a walk state of the type `TTWState`, holding the base address of the first translation table.

I XWTPZ
:   The walk progressively fetches and decodes translation Table descriptors, updating the walk state to the next base address as it descends through the levels of tables until a Block or Page descriptor is discovered or an invalid descriptor is fetched. Decoding the descriptor for both stage 1 and stage 2 walks is carried out by the function [`AArch64_DecodeDescriptorType`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-707-AArch64-DecodeDescriptorType?lang=en#asl_func_aarch64_decodedescriptortype_6)`()`.

I YMSFF
:   For a non-faulting walk, three items are returned by a translation table walk:

    - The final walk state.
    - The final descriptor fetched.
    - The address of the final descriptor.

I KGLCH
:   The final descriptor and its address are used to update the descriptor as specified by [Hardware management of the Access flag](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-5-Hardware-updates-to-the-translation-tables/-D8-5-1-The-Access-flag?lang=en#mdsec_hardware_management_of_the_access_flag) and [Hardware management of the dirty state](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-5-Hardware-updates-to-the-translation-tables/-D8-5-2-The-dirty-state?lang=en#mdsec_hardware_management_of_the_dirty_state).

I RQKNH
:   A faulting walk could report one of the following at a specified level:

    - Translation Fault.
    - Address size Fault.
    - Access flag Fault.

I DNSWC
:   **Hardware update of Translation Table descriptors**

    The walk parameters collected from System registers indicate the ability to update the access flag or set write permissions within descriptors. This is controlled by the Dirty Bit Modifier, and the conditions specified in [Hardware management of the Access flag](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-5-Hardware-updates-to-the-translation-tables/-D8-5-1-The-Access-flag?lang=en#mdsec_hardware_management_of_the_access_flag) and [Hardware management of the dirty state](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-5-Hardware-updates-to-the-translation-tables/-D8-5-2-The-dirty-state?lang=en#mdsec_hardware_management_of_the_dirty_state). The translation functions [`AArch64_S1Translate`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-695-AArch64-S1Translate?lang=en#asl_func_aarch64_s1translate_6)`()` or [`AArch64_S2Translate`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-697-AArch64-S2Translate?lang=en#asl_func_aarch64_s2translate_5)`()` set the appropriate descriptor bits returned by the walk functions and call [`AArch64_MemSwapTableDesc`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-693-AArch64-MemSwapTableDesc?lang=en#asl_func_aarch64_memswaptabledesc_7)`()` to swap the old descriptor for the updated one in an atomic fashion.

I DKMRY
:   **Address decoding and calculation**

    The walk state is initialized to hold the base address of the first translation table. For stage 1, the base address is acquired using [`AArch64_S1TTBaseAddress`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-653-AArch64-S1TTBaseAddress?lang=en#asl_func_aarch64_s1ttbaseaddress_4)`()`, which decodes [TTBR0\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#ttbr0_elx) and [TTBR1\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#ttbr1_elx) registers depending on the regime and the range the VA corresponds to. For stage 2, the base address is acquired using [`AArch64_S2TTBaseAddress`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-658-AArch64-S2TTBaseAddress?lang=en#asl_func_aarch64_s2ttbaseaddress_4)`()`, which decodes [VTTBR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-224-VTTBR-EL2--Virtualization-Translation-Table-Base-Register?lang=en#reg_aarch64_vttbr_el2) or [VSTTBR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-222-VSTTBR-EL2--Virtualization-Secure-Translation-Table-Base-Register?lang=en#reg_aarch64_vsttbr_el2) registers depending on the Security state of the executing PE. The walk progressively fetches and decodes translation Table descriptors, updating the walk state to the next base address utilizing [`AArch64_NextTableBase`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-648-AArch64-NextTableBase?lang=en#asl_func_aarch64_nexttablebase_6)`()` as it descends through the levels of tables. Prior to every descriptor fetch, apart from the fetch at the start level, the base address is indexed by the function [`AArch64_S1TTEntryAddress`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-654-AArch64-S1TTEntryAddress?lang=en#asl_func_aarch64_s1ttentryaddress_7)`()` for stage 1 or [`AArch64_S2TTEntryAddress`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-659-AArch64-S2TTEntryAddress?lang=en#asl_func_aarch64_s2ttentryaddress_5)`()` for stage 2 to point to the specific table entry. Indexing at the start level is shown in [`AArch64_S1SLTTEntryAddress`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-651-AArch64-S1SLTTEntryAddress?lang=en#asl_func_aarch64_s1slttentryaddress_4)`()` for stage 1 and in [`AArch64_S2SLTTEntryAddress`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-656-AArch64-S2SLTTEntryAddress?lang=en#asl_func_aarch64_s2slttentryaddress_3)`()` for stage 2. The final walk state would hold the base address for the output block or page; this is extracted from the Leaf descriptor in [`AArch64_S1LeafBase`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-650-AArch64-S1LeafBase?lang=en#asl_func_aarch64_s1leafbase_4)`()` for stage 1 and in [`AArch64_S2LeafBase`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-655-AArch64-S2LeafBase?lang=en#asl_func_aarch64_s2leafbase_4)`()` for stage 2.

I GDTNP
:   **Memory attribute decoding**

    If a stage of translation is enabled, fetched descriptors that are blocks or pages encode memory attributes assigned to the output of translation. Stage 1 memory attributes are decoded by the function [`S1DecodeMemAttrs`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-754-S1DecodeMemAttrs?lang=en#asl_func_s1decodememattrs_3)`()`. Likewise, the stage 2 memory attributes are decoded by the function [`S2DecodeMemAttrs`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-760-S2DecodeMemAttrs?lang=en#asl_func_s2decodememattrs_3)`()` followed by combining stage 1 and stage 2 attributes by the function [`S2CombineS1MemAttrs`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-757-S2CombineS1MemAttrs?lang=en#asl_func_s2combines1memattrs_3)`()`. However, if [FEAT\_S2FWB](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-5-The-Armv8-4-architecture-extension?lang=en#feat_feat_s2fwb) is enabled, this behavior is overridden and memory attributes are decoded as specified in [Stage 2 memory type and Cacheability attributes when FWB is enabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-6-Memory-region-attributes/-D8-6-6-Stage-2-memory-type-and-Cacheability-attributes-when-FWB-is-enabled?lang=en#mdsec_stage_2_memory_type_and_cacheability_attributes_when_feat_s2fwb_is_enabled). This is captured by the function [`AArch64_S2ApplyFWBMemAttrs`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-685-AArch64-S2ApplyFWBMemAttrs?lang=en#asl_func_aarch64_s2applyfwbmemattrs_4)`()`.

I HGFRX
:   **Fault detection**

    As soon as translation is invoked a reserve `FaultRecord` accompanies the process capturing the stage and level of translation as it proceeds. When a fault is detected, it is reflected in the `FaultRecord` and reported back as the result of translation with the most recent state to be reported already captured within. The following functions detect a certain type of fault:

    - The [`AArch64_S1CheckPermissions`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-664-AArch64-S1CheckPermissions?lang=en#asl_func_aarch64_s1checkpermissions_7)`()` and [`AArch64_S2CheckPermissions`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-673-AArch64-S2CheckPermissions?lang=en#asl_func_aarch64_s2checkpermissions_5)`()` functions check permissions for stage 1 and stage 2 respectively.
    - The [`AArch64_S1HasAlignmentFaultDueToMemType`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-668-AArch64-S1HasAlignmentFaultDueToMemType?lang=en#asl_func_aarch64_s1hasalignmentfaultduetomemtype_5)`()` and [`AArch64_S2HasAlignmentFaultDueToMemType`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-677-AArch64-S2HasAlignmentFaultDueToMemType?lang=en#asl_func_aarch64_s2hasalignmentfaultduetomemtype_3)`()` functions detect an alignment fault for stage 1 and stage 2 respectively.
    - The [`AArch64_S1TxSZFaults`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-672-AArch64-S1TxSZFaults?lang=en#asl_func_aarch64_s1txszfaults_2)`()` and [`AArch64_S2TxSZFaults`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-683-AArch64-S2TxSZFaults?lang=en#asl_func_aarch64_s2txszfaults_2)`()` functions detect a Translation fault caused by erroneous configuration of [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ field. Also, the [`AArch64_S2InconsistentSL`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-678-AArch64-S2InconsistentSL?lang=en#asl_func_aarch64_s2inconsistentsl_1)`()` and [`AArch64_S2InvalidSL`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-680-AArch64-S2InvalidSL?lang=en#asl_func_aarch64_s2invalidsl_1)`()` functions detect a stage 2 Translation fault caused by erroneous configuration of the [VTCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-223-VTCR-EL2--Virtualization-Translation-Control-Register?lang=en#reg_aarch64_vtcr_el2).{SL2, SL0} and [VSTCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-221-VSTCR-EL2--Virtualization-Secure-Translation-Control-Register?lang=en#reg_aarch64_vstcr_el2).{SL2, SL0} fields.
    - [`AArch64_VAIsOutOfRange`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-684-AArch64-VAIsOutOfRange?lang=en#asl_func_aarch64_vaisoutofrange_4)`()` detects a stage 1 Translation fault caused by VAs larger than the address input size configured. Similarly, [`AArch64_IPAIsOutOfRange`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-661-AArch64-IPAIsOutOfRange?lang=en#asl_func_aarch64_ipaisoutofrange_2)`()` detects a stage 2 Translation fault caused by the output of stage 1 being larger than the configured input size for stage 2.
    - [`AArch64_S1ContiguousBitFaults`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-666-AArch64-S1ContiguousBitFaults?lang=en#asl_func_aarch64_s1contiguousbitfaults_2)`()` detects a stage 1 Translation fault caused by a misprogrammed contiguous bit within a fetched descriptor.
    - [`AArch64_S2ContiguousBitFaults`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-675-AArch64-S2ContiguousBitFaults?lang=en#asl_func_aarch64_s2contiguousbitfaults_2)`()` detects a stage 2 Translation fault caused by a misprogrammed contiguous bit within a fetched descriptor.
