# ​I5.5.27 AMPIDR2, Activity Monitors Peripheral Identification Register 2

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-5-Activity-Monitors-external-register-descriptions/-I5-5-27-AMPIDR2--Activity-Monitors-Peripheral-Identification-Register-2>

##### I5.5.27 AMPIDR2, Activity Monitors Peripheral Identification Register 2

The AMPIDR2 characteristics are:

Purpose
:   Provides information to identify an activity monitors component.

    For more information, see [About the Peripheral identification scheme](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-4-About-the-Peripheral-identification-scheme?lang=en#babdfhah).

Configuration
:   It is IMPLEMENTATION DEFINED whether AMPIDR2 is implemented in the Core power domain or in the Debug power domain

    This register is present only when FEAT\_AMUv1 is implemented, FEAT\_AMU\_EXT is implemented, and FEAT\_AMU\_PIDR is implemented. Otherwise, direct accesses to AMPIDR2 are RES0.

Attributes
:   AMPIDR2 is a 32-bit register.

###### Field descriptions

![](images/7280-I5.5.27-AMPIDR2-Activity-Monitors-Peripheral-Identification-Register-2-img01.svg)

Bits [31:8]
:   Reserved, RES0.

REVISION, bits [7:4]
:   Indicates either the revision of the component, or a portion of the part number of the component.

    Where the component has a single 4-bit revision number, the revision number is an incremental value starting at zero for the first revision of the component.

    Where the component has separate major and minor revision numbers, the major and minor revision numbers are each incremental values starting at zero for the first revision of the component. For each minor revision of the component, the minor revision number increments monotonically. For each major revision of the component, the major revision number increments monotonically and the minor revision begins again at zero.

    For a component with a 12-bit part number with a single 4-bit revision number:

    - [AMPIDR2](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-5-Activity-Monitors-external-register-descriptions/-I5-5-27-AMPIDR2--Activity-Monitors-Peripheral-Identification-Register-2?lang=en#reg_amu_ampidr2).REVISION indicates the 4-bit revision number.
    - [AMPIDR3](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-5-Activity-Monitors-external-register-descriptions/-I5-5-28-AMPIDR3--Activity-Monitors-Peripheral-Identification-Register-3?lang=en#reg_amu_ampidr3).REVAND indicates component modifications.

    For a component with a 12-bit part number with separate major and minor revision numbers:

    - [AMPIDR2](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-5-Activity-Monitors-external-register-descriptions/-I5-5-27-AMPIDR2--Activity-Monitors-Peripheral-Identification-Register-2?lang=en#reg_amu_ampidr2).REVISION indicates the 4-bit major revision number.
    - [AMPIDR3](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-5-Activity-Monitors-external-register-descriptions/-I5-5-28-AMPIDR3--Activity-Monitors-Peripheral-Identification-Register-3?lang=en#reg_amu_ampidr3).REVAND indicates the 4-bit minor revision number.

    For a component with a 16-bit part number:

    - [AMPIDR2](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-5-Activity-Monitors-external-register-descriptions/-I5-5-27-AMPIDR2--Activity-Monitors-Peripheral-Identification-Register-2?lang=en#reg_amu_ampidr2).REVISION contains part number bits [3:0].
    - [AMPIDR3](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-5-Activity-Monitors-external-register-descriptions/-I5-5-28-AMPIDR3--Activity-Monitors-Peripheral-Identification-Register-3?lang=en#reg_amu_ampidr3).REVAND indicates the 4-bit revision number.

    The choice of which style of revision information is used is specific to the designer of the component, and might also be specific to each individual component with a different part number.

    This field has an IMPLEMENTATION DEFINED value.

    Access to this field is RO.

JEDEC, bit [3]
:   JEDEC-assigned JEP106 implementer code is used.

    Reads as `0b1`

    Access to this field is RO.

DES\_1, bits [2:0]
:   Designer, JEP106 identification code, bits [6:4].

    The JEP106 identification and continuation codes are stored as follows:

    - [AMPIDR1](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-5-Activity-Monitors-external-register-descriptions/-I5-5-26-AMPIDR1--Activity-Monitors-Peripheral-Identification-Register-1?lang=en#reg_amu_ampidr1).DES\_0: JEP106 identification code bits[3:0].
    - [AMPIDR2](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-5-Activity-Monitors-external-register-descriptions/-I5-5-27-AMPIDR2--Activity-Monitors-Peripheral-Identification-Register-2?lang=en#reg_amu_ampidr2).DES\_1: JEP106 identification code bits[6:4].
    - [AMPIDR4](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-5-Activity-Monitors-external-register-descriptions/-I5-5-29-AMPIDR4--Activity-Monitors-Peripheral-Identification-Register-4?lang=en#reg_amu_ampidr4).DES\_2: JEP106 continuation code.

    These codes indicate the designer of the component and not the implementer, except where the two are the same. To obtain a number, or to see the assignment of these codes, contact JEDEC http://www.jedec.org.

    A JEP106 identification and continuation code takes the following form:

    - A sequence of zero or more numbers, all having the value `0x7F`.
    - A following 8-bit number, that is not `0x7F`, and where bit[7] is an odd parity bit.

    The parity bit in the JEP106 identification code is not included.

    > #### Note
    >
    > For example, Arm Limited is assigned the code `0x7F` `0x7F` `0x7F` `0x7F` `0x3B`.
    >
    > - The continuation code is the number of times `0x7F` appears before the final number. For example, a component designed by Arm Limited has the code `0x4`.
    > - The identification code is bits[6:0] of the final number. For example, a component designed by Arm Limited has the code `0x3B`.

    This field has an IMPLEMENTATION DEFINED value.

    Access to this field is RO.

###### Accessing AMPIDR2

Accesses to this register use the following encodings:

When FEAT\_AMUv1 is implemented
:   Accessible at offset `0xFE8` from AMU

    - When ImpDefBool(“AMU CoreSight management registers ignore access controls”), accesses to this register are RO.
    - When FEAT\_RME is implemented, FEAT\_AMU\_EXTACR is implemented, an access is Secure, and AMROOTCR().RA IN {‘001’, ‘000’}, accesses to this register are RAZ/WI.
    - When FEAT\_RME is implemented, FEAT\_AMU\_EXTACR is implemented, an access is Realm, and AMROOTCR().RA IN {‘010’, ‘000’}, accesses to this register are RAZ/WI.
    - When FEAT\_RME is implemented, FEAT\_AMU\_EXTACR is implemented, an access is Non-secure, and AMROOTCR().RA != ‘011’, accesses to this register are RAZ/WI.
    - When FEAT\_RME is not implemented, FEAT\_AMU\_EXTACR is implemented, an access is Non-secure, and AMSCR().NSRA == ‘0’, accesses to this register are RAZ/WI.
    - Otherwise, accesses to this register are RO.
