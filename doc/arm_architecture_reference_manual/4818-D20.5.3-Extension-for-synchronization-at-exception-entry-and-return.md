# ​D20.5.3 Extension for synchronization at exception entry and return

##### D20.5.3 Extension for synchronization at exception entry and return

D DPSJR
:   The rules in this section apply when [FEAT\_IESB](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-3-The-Armv8-2-architecture-extension?lang=en#feat_feat_iesb) is implemented.

I WDSBL
:   An implicit [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event) has no effect on [DISR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-9-RAS-registers/-D24-9-1-DISR-EL1--Deferred-Interrupt-Status-Register?lang=en#reg_aarch64_disr_el1) or [VDISR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-9-RAS-registers/-D24-9-16-VDISR-EL2--Virtual-Deferred-Interrupt-Status-Register--EL2-?lang=en#reg_aarch64_vdisr_el2).

R KJWNS
:   When [FEAT\_DoubleFault](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-5-The-Armv8-4-architecture-extension?lang=en#feat_feat_doublefault) is implemented, the PE is in Non-debug state, and the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).NMEA is 1, then the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [SCTLR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-176-SCTLR-EL3--System-Control-Register--EL3-?lang=en#reg_aarch64_sctlr_el3).IESB is 1.

R HLVWK
:   When [FEAT\_DoubleFault2](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-10-The-Armv8-9-architecture-extension?lang=en#feat_feat_doublefault2) is implemented and the PE is in Non-debug state, all of the following apply:

    - If the Effective value of [SCTLR2\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-169-SCTLR2-EL1--System-Control-Register--EL1-?lang=en#reg_aarch64_sctlr2_el1).NMEA is 1, then the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [SCTLR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-174-SCTLR-EL1--System-Control-Register--EL1-?lang=en#reg_aarch64_sctlr_el1).IESB is 1.
    - If the Effective value of [SCTLR2\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-170-SCTLR2-EL2--System-Control-Register--EL2-?lang=en#reg_aarch64_sctlr2_el2).NMEA is 1, then the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [SCTLR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-175-SCTLR-EL2--System-Control-Register--EL2-?lang=en#reg_aarch64_sctlr_el2).IESB is 1.

###### D20.5.3.1 Synchronization on exception entry

R RNZWY
:   For each value of ELx in EL1, EL2, EL3, if all of the following are true, then each exception that is taken to ELx generates an [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event):

    - ELx is using AArch64.
    - The [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [SCTLR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#sctlr_elx).IESB is `0b1`.

R JQSKQ
:   If an SError exception is taken to the Exception level ELy as a result of the [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event) generated on exception entry by the [FEAT\_IESB](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-3-The-Armv8-2-architecture-extension?lang=en#feat_feat_iesb) mechanism, then all the following occur:

    - The PE sets the ESR\_ELy.IESB bit in the SError exception syndrome to `0b1`.
    - The preferred return address for the SError exception is the exception vector address for the original exception.

    Note: ELy might be the same Exception level as ELx.

I FWZHV
:   If SError exceptions are masked at ELx, then any SError exception made pending by the [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event) stays pending.

I MMVJW
:   The prioritization of asynchronous exceptions is IMPLEMENTATION DEFINED. This means that an implementation might choose to behave as if the SError exception made pending by the Error synchronization event was taken before the implicit Error synchronization event, if the SError exception was not masked, taking the SError exception in place of the original exception, unless the original exception is also an SError exception.

    In this case, ESR\_ELy.IESB is cleared to 0 and the reported PE error state correctly indicates, for instance, whether software can recover execution from the preferred return address for the SError exception in ELR\_ELy.

I BVBKS
:   Arm recommends that, when enabled, an implicit [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event) is inserted before taking an exception other than an SError exception. In particular, Arm recommends that:

    - When [FEAT\_DoubleFault](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-5-The-Armv8-4-architecture-extension?lang=en#feat_feat_doublefault) is implemented, an implicit [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event) is inserted before taking the exception to EL3.
    - When [FEAT\_DoubleFault2](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-10-The-Armv8-9-architecture-extension?lang=en#feat_feat_doublefault2) is implemented, an implicit [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event) is inserted before taking the exception to the target Exception level of an SError exception.

###### D20.5.3.2 Synchronization on exception return

R SKRCR
:   For each value of ELx in EL1, EL2, EL3, if all of the following are true, then executing an exception return instruction at ELx generates an [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event):

    - The instruction does not generate any exception.
    - ELx is using AArch64.
    - The [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [SCTLR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#sctlr_elx).IESB is `0b1`.

I GPPXQ
:   On an illegal return event, the exception return instruction sets [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).IL to `0b1`, which causes the next instruction to generate an Illegal State exception. The exception return instruction does not generate the exception.

R GXQYD
:   Any SError exception taken as part of the [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event) terminates execution of the instruction.

R LPKVM
:   If an SError exception is taken to an Exception level, ELy, as a result of the [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event) generated on exception return by the [FEAT\_IESB](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-3-The-Armv8-2-architecture-extension?lang=en#feat_feat_iesb) mechanism, then all the following occur:

    - The PE sets the ESR\_ELy.IESB bit in the SError exception syndrome to an IMPLEMENTATION DEFINED choice of `0b0` or `0b1`.
    - The preferred return address for the SError exception is the address of the `ERET` instruction.

S MHCTH
:   [RJQSKQ](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event/-D20-5-3-Extension-for-synchronization-at-exception-entry-and-return?lang=en#jqskq) and [RLPKVM](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event/-D20-5-3-Extension-for-synchronization-at-exception-entry-and-return?lang=en#lpkvm) describe how ESR\_ELy.IESB records that an SError exception was taken because of an implicit [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event) generated by the [FEAT\_IESB](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-3-The-Armv8-2-architecture-extension?lang=en#feat_feat_iesb) mechanism.

    When ESR\_ELy.IESB is 1, software can compare the value in ELR\_ELy with the value of [VBAR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#vbar_elx), where ELx is the Exception level the SError exception was taken from, to confirm whether this is due to the exception entry or the exception return case.

    If the error is also reported as a [synchronizable error](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_synchronized_by_ese), then:

    - In the exception entry case:

      - ESR\_ELy.IESB == 1 indicates that the error was generated by an instruction in program order before the exception was taken.
      - ELR\_ELy will contain the address of an exception vector. See [Exception vectors](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-4-Exceptions/-D1-4-1-Exception-entry-terminology?lang=en#beifjiia).
      - Software can determine the Exception level the exception was taken from the value recorded in [SPSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#spsr_elx), where ELx is the Exception level the SError was taken from.
    - In the exception return case, software can ignore the value of ESR\_ELy.IESB:

      - The value 1 indicates that the error was generated by an instruction in program order before the exception return.
      - However, this is indistinguishable from an SError taken before the exception return was executed. Hence the value of ESR\_ELy.IESB is IMPLEMENTATION SPECIFIC in this case.

    If [ID\_AA64MMFR4\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-91-ID-AA64MMFR4-EL1--AArch64-Memory-Model-Feature-Register-4?lang=en#reg_aarch64_id_aa64mmfr4_el1).EIESB indicates to software that implicit [Error synchronization events](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event) are inserted before exceptions taken to ELy, then software can ignore the value in ESR\_ELy.IESB, as it would only ever be set for the exception return case.

I JZHDB
:   If SError exceptions are masked at ELx, then any SError exception made pending by the [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdterm_error_synchronization_event) stays pending.
