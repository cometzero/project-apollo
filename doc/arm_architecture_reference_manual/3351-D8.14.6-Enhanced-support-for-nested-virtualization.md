##### D8.14.6 Enhanced support for nested virtualization

I GDQNK
:   Enhanced support for nested virtualization provides a mechanism for hardware to transform reads and writes from System registers into reads and writes from memory.

R JXWDQ
:   All statements in this section and subsections require implementation of [FEAT\_NV2](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-5-The-Armv8-4-architecture-extension?lang=en#feat_feat_nv2).

I TMCKW
:   If the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [HCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-61-HCR-EL2--Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcr_el2).NV2 is 1 and the current Exception level is EL1, then all of the following apply:

    - Accesses to EL2 registers are redirected to EL1 registers.
    - Accesses to System registers are transformed to [Memory Effect](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-3-Ordering-requirements-defined-by-the-formal-concurrency-model/-B2-3-1-Basic-definitions?lang=en#term_memory_effect)s.

I VGFWB
:   If the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [HCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-61-HCR-EL2--Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcr_el2).NV2 is 0, then the behavior of [HCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-61-HCR-EL2--Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcr_el2).{NV, NV1} is unchanged.

I ZSQQK
:   If [ID\_AA64MMFR4\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-91-ID-AA64MMFR4-EL1--AArch64-Memory-Model-Feature-Register-4?lang=en#reg_aarch64_id_aa64mmfr4_el1).NV\_frac is `0b0001` and [HCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-61-HCR-EL2--Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcr_el2).NV is 1, then the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [HCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-61-HCR-EL2--Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcr_el2).NV2 is 1.

###### D8.14.6.1 Redirection of register accesses from EL2 to EL1

I RKLVD
:   If the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [HCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-61-HCR-EL2--Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcr_el2).{NV, NV2} is {1, 1} and the current Exception level is EL1, then accesses to all of the following EL2 Special-purpose registers are redirected to the corresponding EL1 register:

    - An access from EL1 to [SPSR\_EL2](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C5-The-A64-System-Instruction-Class/-C5-2-Special-purpose-registers/-C5-2-22-SPSR-EL2--Saved-Program-Status-Register--EL2-?lang=en#reg_aarch64_spsr_el2) is redirected to [SPSR\_EL1](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C5-The-A64-System-Instruction-Class/-C5-2-Special-purpose-registers/-C5-2-21-SPSR-EL1--Saved-Program-Status-Register--EL1-?lang=en#reg_aarch64_spsr_el1).
    - An access from EL1 to [ELR\_EL2](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C5-The-A64-System-Instruction-Class/-C5-2-Special-purpose-registers/-C5-2-6-ELR-EL2--Exception-Link-Register--EL2-?lang=en#reg_aarch64_elr_el2) is redirected to [ELR\_EL1](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C5-The-A64-System-Instruction-Class/-C5-2-Special-purpose-registers/-C5-2-5-ELR-EL1--Exception-Link-Register--EL1-?lang=en#reg_aarch64_elr_el1).

I DLGPW
:   If the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [HCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-61-HCR-EL2--Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcr_el2).{NV, NV2} is {1, 1} and the current Exception level is EL1, then accesses to all of the following EL2 System registers are redirected to the corresponding EL1 register:

    - An access from EL1 to [ESR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-45-ESR-EL2--Exception-Syndrome-Register--EL2-?lang=en#reg_aarch64_esr_el2) is redirected to [ESR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-44-ESR-EL1--Exception-Syndrome-Register--EL1-?lang=en#reg_aarch64_esr_el1).
    - An access from EL1 to [FAR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-48-FAR-EL2--Fault-Address-Register--EL2-?lang=en#reg_aarch64_far_el2) is redirected to [FAR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-47-FAR-EL1--Fault-Address-Register--EL1-?lang=en#reg_aarch64_far_el1).
    - An access from EL1 to [TFSR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-199-TFSR-EL2--Tag-Fault-Status-Register--EL2-?lang=en#reg_aarch64_tfsr_el2) is redirected to [TFSR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-198-TFSR-EL1--Tag-Fault-Status-Register--EL1-?lang=en#reg_aarch64_tfsr_el1).

    - [op0 == `0b11`, Moves to and from Special-purpose registers](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C5-The-A64-System-Instruction-Class/-C5-1-The-System-instruction-class-encoding-space/-C5-1-5-op0----0b11--Moves-to-and-from-non-debug-System-registers-and-Special-purpose-registers?lang=en#cihccegd).

###### D8.14.6.2 Loads and stores generated by transforming register accesses

I KYDSS
:   If the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [HCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-61-HCR-EL2--Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcr_el2).{NV, NV2} is {1, 1} and the current Exception level is EL1, then when an MRS or MSR instruction is executed to access one of the registers listed in [Table D8-120](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-14-Nested-virtualization/-D8-14-6-Enhanced-support-for-nested-virtualization?lang=en#tbl_mdtbl_memory_offset_transformed_register), all of the following apply:

    - The instruction is treated as an instruction executed at EL1.
    - The register accesses do not generate an exception to EL2.
    - The register accesses are transformed to [Memory Effect](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-3-Ordering-requirements-defined-by-the-formal-concurrency-model/-B2-3-1-Basic-definitions?lang=en#term_memory_effect)s.
    - The [Memory Effect](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-3-Ordering-requirements-defined-by-the-formal-concurrency-model/-B2-3-1-Basic-definitions?lang=en#term_memory_effect)s are treated as if they were generated due to execution at EL2.

I LKWDD
:   When register accesses are transformed to [Memory Effect](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-3-Ordering-requirements-defined-by-the-formal-concurrency-model/-B2-3-1-Basic-definitions?lang=en#term_memory_effect)s, all of the following information is used to form the memory address:

    - A base address that is stored in the [VNCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-219-VNCR-EL2--Virtual-Nested-Control-Register?lang=en#reg_aarch64_vncr_el2) register.
    - For a register that is redirected to memory, a unique memory offset value.
    - The memory address is a combination of the base address and the memory offset according to the formula `SignExtend(VNCR_EL2.BADDR : Offset<11:0>, 64)`.
