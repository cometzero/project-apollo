# ​I2.2.3 Counter module control and status register summary

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I2-System-Level-Implementation-of-the-Generic-Timer/-I2-2-Memory-mapped-counter-module/-I2-2-3-Counter-module-control-and-status-register-summary>

##### I2.2.3 Counter module control and status register summary

The Counter module control and status registers are memory-mapped registers in the following register memory *frames*:

- A control frame, with base address [CNTControlBase](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I2-System-Level-Implementation-of-the-Generic-Timer/-I2-2-Memory-mapped-counter-module/-I2-2-3-Counter-module-control-and-status-register-summary?lang=en#tbl_chdbeaba).
- A status frame, with base address [CNTReadBase](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I2-System-Level-Implementation-of-the-Generic-Timer/-I2-2-Memory-mapped-counter-module/-I2-2-3-Counter-module-control-and-status-register-summary?lang=en#tbl_babbbejj).

Each of these register memory frames is in its own [memory page](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I2-System-Level-Implementation-of-the-Generic-Timer/-I2-1-About-the-Generic-Timer-specification/-I2-1-1-Registers-in-the-system-level-implementation-of-the-Generic-Timer?lang=en#cegjhbgi) or [memory protection region](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I2-System-Level-Implementation-of-the-Generic-Timer/-I2-1-About-the-Generic-Timer-specification/-I2-1-1-Registers-in-the-system-level-implementation-of-the-Generic-Timer?lang=en#cegbgjhc), and the frame base address points to the start of this region. Each base address must be aligned to the size of the translation granule or protection granule.

> #### Note
>
> Each frame of a memory-mapped Generic Timer takes the name of its base address.

In each register memory frame, the memory at offset `0xFD0`-`0xFFF` is reserved for twelve 32-bit IMPLEMENTATION DEFINED ID registers, see the [CounterID<n>](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-7-Generic-Timer-memory-mapped-register-descriptions/-I5-7-23-CounterID-n---Counter-ID-registers--n---0---11?lang=en#reg_ext_counteridn) register descriptions for more information.

> #### Note
>
> The Arm architecture requires memory-mapped peripherals to be little-endian, and therefore the counter is little-endian.

In an implementation with multiple physical address spaces, [CNTControlBase](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I2-System-Level-Implementation-of-the-Generic-Timer/-I2-2-Memory-mapped-counter-module/-I2-2-3-Counter-module-control-and-status-register-summary?lang=en#tbl_chdbeaba) is only accessible by accesses from the most secure physical address space. For example, in a system with Secure and Non-secure memory maps, [CNTControlBase](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I2-System-Level-Implementation-of-the-Generic-Timer/-I2-2-Memory-mapped-counter-module/-I2-2-3-Counter-module-control-and-status-register-summary?lang=en#tbl_chdbeaba) is only accessible by Secure accesses. For example, in a system with [FEAT\_RME](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-3-The-Armv9-2-architecture-extension?lang=en#feat_feat_rme), [CNTControlBase](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I2-System-Level-Implementation-of-the-Generic-Timer/-I2-2-Memory-mapped-counter-module/-I2-2-3-Counter-module-control-and-status-register-summary?lang=en#tbl_chdbeaba) is only accessible by Root accesses.
