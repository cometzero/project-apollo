# ​H3.9.1 Pending Halting debug events

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H3-Halting-Debug-Events/-H3-9-Synchronization-and-Halting-debug-events/-H3-9-1-Pending-Halting-debug-events>

##### H3.9.1 Pending Halting debug events

A Halting debug event might be pending:

- If Halting Step of an instruction sets [EDESR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-29-EDESR--External-Debug-Event-Status-Register?lang=en#reg_ext_edesr).SS to 1, and halting is prohibited following the step, then the Halting Step state machine is inactive but a Halting Step debug event is pending.
- If a Reset Catch debug event sets [EDESR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-29-EDESR--External-Debug-Event-Status-Register?lang=en#reg_ext_edesr).RC to 1, and halting is prohibited following reset, then a Reset Catch debug event is pending.
- If an OS Unlock Catch debug event sets [EDESR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-29-EDESR--External-Debug-Event-Status-Register?lang=en#reg_ext_edesr).OSUC to 1, then an OS Unlock Catch debug event is pending.
- If [FEAT\_Debugv8p8](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-9-The-Armv8-8-architecture-extension?lang=en#feat_feat_debugv8p8) is implemented and an Exception Catch debug event sets [EDESR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-29-EDESR--External-Debug-Event-Status-Register?lang=en#reg_ext_edesr).EC to 1, and before the PE takes the Exception Catch debug event, the PE takes an asynchronous exception, then an Exception Catch debug event is pending.
- If [FEAT\_Debugv8p9](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-10-The-Armv8-9-architecture-extension?lang=en#feat_feat_debugv8p9) and [FEAT\_ETEv1p3](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-5-The-Armv9-4-architecture-extension?lang=en#feat_feat_etev1p3) are implemented, and an ETE external debug request is generated, and the PE enters a state where halting is prohibited before the PE halts and enters Debug state.
- If [FEAT\_Debugv8p9](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-10-The-Armv8-9-architecture-extension?lang=en#feat_feat_debugv8p9) and [FEAT\_TRBE\_EXT](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-5-The-Armv9-4-architecture-extension?lang=en#feat_feat_trbe_ext) are implemented, and a Trace Buffer Unit external debug request is generated, and the PE enters a state where halting is prohibited before the PE halts and enters Debug state.
- If [FEAT\_Debugv8p9](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-10-The-Armv8-9-architecture-extension?lang=en#feat_feat_debugv8p9) and [FEAT\_PMUv3p9](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-10-The-Armv8-9-architecture-extension?lang=en#feat_feat_pmuv3p9) are implemented, and a PMU overflow external debug request is generated, and the PE enters a state where halting is prohibited before the PE halts and enters Debug state.

Pending Halting debug events are taken asynchronously when halting is allowed.

Pending Halting debug events are discarded by a Cold reset. The debugger can also force a pending event to be dropped by writing to [EDESR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-29-EDESR--External-Debug-Event-Status-Register?lang=en#reg_ext_edesr).

Any Halting debug event that is observed as pending in the [EDESR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-29-EDESR--External-Debug-Event-Status-Register?lang=en#reg_ext_edesr) before a [Context Synchronization event](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#babdjfhg) is taken and the PE enters Debug state before the first instruction following the [Context Synchronization event](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#babdjfhg) completes its execution. This is possible only if halting is allowed after completion of the [Context Synchronization event](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#babdjfhg).

If the first instruction after the [Context Synchronization event](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#babdjfhg) generates a synchronous exception then the architecture does not define the order in which the debug event and the exception or exceptions are taken, unless both:

- A Halting Step debug event is pending. [EDESR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-29-EDESR--External-Debug-Event-Status-Register?lang=en#reg_ext_edesr).SS == 1.
- The [Context Synchronization event](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#babdjfhg) is an exception return from EL3 when halting is prohibited at EL3 to a state where halting is allowed.

  > Example H3-4
  >
  > Context synchronization event
  >
  > When [FEAT\_RME](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-3-The-Armv9-2-architecture-extension?lang=en#feat_feat_rme) is not implemented, [FEAT\_ExS](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-6-The-Armv8-5-architecture-extension?lang=en#feat_feat_exs) is implemented, and [SCTLR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-176-SCTLR-EL3--System-Control-Register--EL3-?lang=en#reg_aarch64_sctlr_el3).EOS is `0b1`, an exception return from EL3 using AArch64 with [`ExternalSecureInvasiveDebugEnabled`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-25-ExternalSecureInvasiveDebugEnabled?lang=en#asl_func_externalsecureinvasivedebugenabled_0)`()` == FALSE to Non-secure state with [`ExternalInvasiveDebugEnabled`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-18-ExternalInvasiveDebugEnabled?lang=en#asl_func_externalinvasivedebugenabled_0)`()` == TRUE is such an event.

In this case the order in which the debug events are handled is specified to avoid a double-step. See [Entering the active-pending state](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H3-Halting-Debug-Events/-H3-2-Halting-Step-debug-events/-H3-2-4-Detailed-Halting-Step-state-machine-behavior?lang=en#babgcaeb).

If [FEAT\_Debugv8p8](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-9-The-Armv8-8-architecture-extension?lang=en#feat_feat_debugv8p8) is implemented and [EDESR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-29-EDESR--External-Debug-Event-Status-Register?lang=en#reg_ext_edesr).EC is 1, when a pending Exception Catch debug event is taken following a [Context Synchronization event](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#babdjfhg), the PE enters Debug state before fetching any instruction:

- At ELn in Non-secure state, if [EDECCR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-27-EDECCR--External-Debug-Exception-Catch-Control-Register?lang=en#reg_ext_edeccr).NSE<n> is 1 and address translation is disabled at ELn.
- At ELn in Secure state, if [EDECCR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-27-EDECCR--External-Debug-Exception-Catch-Control-Register?lang=en#reg_ext_edeccr).SE<n> is 1 and address translation is disabled at ELn.
- At ELn in Realm state, if [EDECCR](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-27-EDECCR--External-Debug-Exception-Catch-Control-Register?lang=en#reg_ext_edeccr).RLE<n> is 1 and address translation is disabled at ELn.

If an asynchronous exception is also pending after the [Context Synchronization event](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#babdjfhg) then the architecture does not define the order in which the debug event and the exception or exceptions are taken.

> #### Note
>
> These rules are based on the rules that apply to taking asynchronous exceptions. See [Asynchronous exception types](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-4-Exceptions/-D1-4-6-Asynchronous-exception-types?lang=en#beiccadh).
