##### D8.7.3 Table and Block entry

R DFJNG
:   All statements in this section require implementation of [FEAT\_BBML1](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-5-The-Armv8-4-architecture-extension?lang=en#feat_feat_bbml1).

I PJZBK
:   The nT bit is supported in the following descriptors:

    - VMSAv8-64 Block descriptors.
    - VMSAv9-128 descriptors, when the SKL field in that descriptor is not 0.

I XPRKH
:   Setting the nT bit in a Table descriptor or Block descriptor guarantees that, when changing the table or block size, Memory Effects whose addresses are translated by the translation table entry do not break coherency, ordering guarantees or uniprocessor semantics, or fail to clear the Exclusives monitors.

R MRRPW
:   When using a Table descriptor or Block descriptor with the nT bit set to 1, all of the following apply:

    - It is IMPLEMENTATION DEFINED whether a Translation fault is generated.
    - If a Translation fault is not generated, a TLB conflict abort can be generated.

    For more information, see [Support levels for changing table or block size](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-17-TLB-maintenance/-D8-17-2-Support-levels-for-changing-table-or-block-size?lang=en#mdsec_support_levels_for_changing_block_size).

I DXRJK
:   If the nT bit in a Table descriptor or Block descriptor is 1, then the translation performance can be significantly impacted.
