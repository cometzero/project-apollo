# ​D21.3 Partition Identifiers (PARTIDs)

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-3-Partition-Identifiers--PARTIDs->

#### D21.3 Partition Identifiers (PARTIDs)

I NHJZF
:   A *Partition Identifier* (PARTID) is a number that has no inherent meaning and does not imply any ordering. The number solely references a particular partition in a [PARTID space](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-2-PARTID-spaces?lang=en#mpam_partid_spaces).

R CZHSY
:   Each PARTID can exist once in each PARTID space.

R RBWRS
:   The scope of a PARTID is bound by its PARTID space. If a PARTID is used in multiple PARTID spaces, then a reference to that PARTID in one PARTID space does not also reference that PARTID in the other PARTID spaces.

I NFCZF
:   Each *MPAM-compliant* component in an SoC is permitted to implement a maximum PARTID width that is less than or equal to the architecturally defined maximum width of 16-bits.

I NPBWK
:   In an MPAM PE, [MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).PARTID\_MAX reports the maximum PARTID implemented.

R PJTCQ
:   In an MPAM PE, [MPAMn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpamn_elx).{PARTID\_D, PARTID\_I} are permitted to hold PARTIDs in the range 0 to [MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).PARTID\_MAX, inclusive.

R NYXVG
:   The PARTID that an MPAM PE Requester sends as part of an MPAM information bundle is one of:

    - If any of the conditions for [the Default PARTID](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-3-Partition-Identifiers--PARTIDs-/-D21-3-2-The-Default-PARTID?lang=en#mpam_default_partid) are met, the Default physical PARTID.
    - If the PARTID held is *treated as virtual* and a valid mapping exists, the mapped physical PARTID. Also see both:

      - [Behavior when a valid mapping does not exist for a PARTID that is treated as virtual](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-9-MPAM-errors/-D21-9-2-Behavior-when-a-valid-mapping-does-not-exist-for-a-PARTID-that-is-treated-as-virtual?lang=en#mpam_behavior_when_a_valid_mapping_does_not_exist_for_a_partid_that_is_treated_as_virtual).
      - [Behavior when a PARTID is out-of-range](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-9-MPAM-errors/-D21-9-1-Behavior-when-a-PARTID-is-out-of-range?lang=en#mpam_behavior_when_a_partid_is_out_of_range).
    - If the PARTID held is not treated as virtual, it is determined as follows:

      - For an instruction fetch, [MPAMn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpamn_elx).PARTID\_I is used.
      - For a data access, [MPAMn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpamn_elx).PARTID\_D is used. However, if a data access is due to the execution of an SME load or store instruction, or of a [Streaming SVE mode](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B1-The-AArch64-Application-Level-Programmers--Model/-B1-4-The-Scalable-Vector-and-Scalable-Matrix-Extensions--SVE---SME-/-B1-4-6-Streaming-SVE-mode?lang=en#beigieigd1) load or store instruction, [MPAMSM\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-14-MPAMSM-EL1--MPAM-Streaming-Mode-Register?lang=en#reg_aarch64_mpamsm_el1).PARTID\_D is used instead.

      Also see [Behavior when a PARTID is out-of-range](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-9-MPAM-errors/-D21-9-1-Behavior-when-a-PARTID-is-out-of-range?lang=en#mpam_behavior_when_a_partid_is_out_of_range).

I QKRPD
:   Software can set [MPAMn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpamn_elx).{PARTID\_D, PARTID\_I} to the same or different PARTID values.

I QDFWX
:   Arm recommends that all MPAM-compliant components in an SoC implement the same maximum PARTID, though this is not required.
