##### E2.6.3 Cases where unaligned accesses are CONSTRAINED UNPREDICTABLE

Any load instruction that is not faulted by the alignment restrictions shown in [Table E2-2](/documentation/ddi0487/mc/-Part-E-The-AArch32-Application-Level-Architecture/-Chapter-E2-The-AArch32-Application-Level-Memory-Model/-E2-6-Alignment-support/-E2-6-2-Unaligned-data-access?lang=en#tbl_chdddhie) and that loads the PC has CONSTRAINED UNPREDICTABLE behavior if the address it loads from is not word-aligned, see [Loads and Stores to unaligned locations](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K1-Architectural-Constraints-on-UNPREDICTABLE-Behaviors/-K1-1-AArch32-CONSTRAINED-UNPREDICTABLE-behaviors/-K1-1-6-Loads-and-Stores-to-unaligned-locations?lang=en#ceghcfhh). This overrules any permitted load/store behavior shown in [Table E2-2](/documentation/ddi0487/mc/-Part-E-The-AArch32-Application-Level-Architecture/-Chapter-E2-The-AArch32-Application-Level-Memory-Model/-E2-6-Alignment-support/-E2-6-2-Unaligned-data-access?lang=en#tbl_chdddhie).
