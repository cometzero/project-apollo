# ​D8.15 Memory aborts

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-15-Memory-aborts>

#### D8.15 Memory aborts

R SQLMR
:   For a VMSAv8-64 implementation, all of the following abort mechanisms can cause the PE to take an exception due to a failed memory access:

    - A *Debug exception* generated by the self-hosted debug system. For more information, see [AArch64 Self-hosted Debug](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D2-AArch64-Self-hosted-Debug?lang=en#bcgefacd).
    - An *Alignment fault* generated by a memory access that is not aligned as required by the operation. For more information, see [Alignment support](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-8-Alignment-support?lang=en#chdidcci).
    - An *MMU fault* generated by the fault checking sequence in the appropriate translation regime. For more information, see [MMU fault types](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-15-Memory-aborts/-D8-15-1-MMU-fault-types?lang=en#mdsec_mmu_fault_types).
    - An *External abort* generated by the memory system and not by self-hosted debug, alignment checking, or MMU checking. For more information, see [External aborts](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D7-The-AArch64-System-Level-Memory-Model/-D7-6-External-aborts?lang=en#beicegfj).

R XXMXW
:   For AArch64 state, MMU faults are synchronous exceptions that are reported as one of the following:

    - Data Aborts due to data memory access faults.
    - Instruction Aborts due to instruction fetch faults.

    For more information, see [Synchronous exception types](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-4-Exceptions/-D1-4-5-Synchronous-exception-types?lang=en#beibcfcc).

I WFYSR
:   In some cases, an [MMU fault](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-15-Memory-aborts?lang=en#aa64_mmu_fault) generated as part of `AT` instruction execution is reported in PAR\_EL1 rather than as a synchronous abort.

I YMZWZ
:   When an [MMU fault](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-15-Memory-aborts?lang=en#aa64_mmu_fault) is generated and reported as an Instruction Abort or Data Abort, the Exception level that the exception is taken to depends on the translation regime and translation stage that caused the fault.

I DHWPX
:   When a memory access abort generates an exception, all of the following registers are used to record context information:

    - A Fault Address Register, [FAR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#far_elx).
    - An Exception Syndrome Register, [ESR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#esr_elx).

I XLTCG
:   When an [MMU fault](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-15-Memory-aborts?lang=en#aa64_mmu_fault) is generated, the fault context saved in the [ESR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#esr_elx) at the Exception level that the fault is taken to depends on all of the following:

    - Whether the fault is reported as an Instruction Abort or as a Data Abort.
    - Whether the exception is taken from the same or a lower Exception level.

I FVNYG
:   For an Instruction Abort, only the following two exceptions have a higher priority in the exception priority hierarchy:

    - Software Step exception.
    - PC alignment fault exception.

I SRPXB
:   For a Data Abort, only Watchpoint exceptions have a lower priority in the exception priority hierarchy.
