#### B2.3 Ordering requirements defined by the formal concurrency model

The material presented in the current section corresponds to what is described in the [formal concurrency model](https://developer.arm.com/herd7). The definitions of relations, including but not limited to Dependency-ordered-before, Barrier-ordered-before, or Atomic-ordered-before, are automatically transliterated from the formal concurrency model.

The Arm memory model introduces a number of relations which are as follows:

- *Intrinsic relations*; For example, Intrinsic Data Dependencies, Intrinsic Control Dependencies, Intrinsic Order Dependencies and Translation-intrinsically-before are hardware requirements which stem from the instruction semantics.
- *After relations*; For example, Coherence-after and TLBI-after are relations which happen to be oriented that way in a specific execution, but could be oriented the other way in a different execution.
- *Observation relations*; For example, Explicit-Observed-by and TLBI-Observed-by build on *After relations* to describe an execution.
- *Ordered relations*; For example, Ordered-before and TLBI-ordered-before are architectural requirements which must be respected by hardware in all executions.

The formal memory model described in this section covers much, but not all, of the memory system functionality. In particular the following are in scope:

- Ordering requirements for instructions that explicitly access memory (for example: `LDR`, `STR`, `SWP`, etc.).

  - This includes the ordering requirements between any two Explicit Memory Effects where:

    - The Explicit Memory Effects are to the same Location either from the same or different PEs.
    - One or both of the Explicit Memory Effects are generated by an atomic instruction.
    - A barrier instruction is in program order between the Explicit Memory Effects.
    - There is a dependency between the Explicit Memory Effects.
  - And excludes cases where:

    - At least one of the Explicit Memory Effects is generated by SVE instructions.
    - At least one of the Explicit Memory Effects is generated by SME instructions.
    - At least one of the Explicit Memory Effects is generated by instructions added by [FEAT\_MOPS](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-9-The-Armv8-8-architecture-extension?lang=en#feat_feat_mops).
- Ordering requirements relating to the [Virtual Memory System Architecture](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture?lang=en#caciiijc):

  - This includes:

    - Implicit TTD Memory Read Effects.
    - Implicit TTD Memory Write Effects when [FEAT\_HAF](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-2-The-Armv8-1-architecture-extension?lang=en#feat_feat_haf) or [FEAT\_HAFDBS](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-2-The-Armv8-1-architecture-extension?lang=en#feat_feat_hafdbs) is implemented.
    - MMU Fault Effects that cause Data Abort exceptions.
  - This excludes:

    - Any Effects relating to address translation instructions.
    - Any Effects relating to address translation for instruction fetch.
    - The ordering requirements between Implicit TTD Memory Effects that belong to different levels or stages of translation.
    - The ordering requirements relating to [FEAT\_HDBSS](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-6-The-Armv9-5-architecture-extension?lang=en#feat_feat_hdbss).
    - The ordering requirements relating to [FEAT\_HACDBS](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-6-The-Armv9-5-architecture-extension?lang=en#feat_feat_hacdbs).
- Ordering requirements relating to tag checks when [FEAT\_MTE2](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-6-The-Armv8-5-architecture-extension?lang=en#feat_feat_mte2) is implemented. This includes:

  - Implicit Tag Memory Read Effects generated by tag checked instructions.
  - Explicit Tag Memory Effects generated by tag load, tag store, tag and data store, and bulk allocation tag access instructions.
  - TagCheck Fault Effects generated by tag checked instructions.
- Ordering requirements relating to instruction fetch. This includes:

  - Implicit Instruction Memory Read Effects generated as a result of instruction fetch.
  - DC CVAU Effects.
  - IC Effects.
  - Undefined Instruction Fault Effects.

For the purposes of the memory model, all Effects generated due to execution of an instruction are considered to be generated by the PE on which the instruction is executed. The list of all Effects of an instruction in the scope of the Arm Memory Model is further presented in [Effects](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-3-Ordering-requirements-defined-by-the-formal-concurrency-model/-B2-3-1-Basic-definitions?lang=en#term_effects).

In this section [Ordering requirements defined by the formal concurrency model](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-3-Ordering-requirements-defined-by-the-formal-concurrency-model?lang=en#beifddeh), all of the following are assumed:

- One of the following applies:

  - All PEs are part of the same Inner Shareable domain and all Memory Effects are to Inner Shareable or Outer Shareable memory as long as no TLB invalidations nor their corresponding `DSB` specify the Non-shareable domain.
  - All PEs are part of the same Outer Shareable domain and all Memory Effects are to Outer Shareable memory as long as no TLB invalidations nor their corresponding `DSB` specify the Non-shareable domain or the Inner Shareable domain.
  - All PEs are part of the Full System domain and all Memory Effects are to Normal, Inner Non-cacheable, Outer Non-cacheable memory or all Memory Effects are to Normal, Inner Write-Through, Outer Write-Through memory or all Memory Effects are to Device memory as long as all barriers specify the Full System domain and there are no TLB invalidations.
- All Memory Effects are to Normal, Inner Write-Back, Outer Write-Back memory. Behaviors in [Ordering requirements defined by the formal concurrency model](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-3-Ordering-requirements-defined-by-the-formal-concurrency-model?lang=en#beifddeh) also apply to Memory Effects to memory with attributes other than Normal, Inner Write-Back, Outer Write-Back (for example, Device or Inner Write-Through, Outer Write-Through) as long as the behavior of the instruction which generated the Memory Effect is guaranteed for the memory type. For example, atomic instructions are only guaranteed to be atomic for Normal, Inner Write-Back, Outer Write-Back, Shareable memory. Memory Effects to memory with attributes other than Normal, Inner Write-Back, Outer Write-Back may require additional ordering behaviors than specified in [Ordering requirements defined by the formal concurrency model](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-3-Ordering-requirements-defined-by-the-formal-concurrency-model?lang=en#beifddeh). Such additional behaviors are described in [Memory types and attributes](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-10-Memory-types-and-attributes?lang=en#chddaiha).
- All Memory Effects to a given Location are not using mismatched memory attributes as described in [Mismatched memory attributes](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B2-The-AArch64-Application-Level-Memory-Model/-B2-11-Mismatched-memory-attributes?lang=en#chdghffd).
