# ​F5.1.9 ADD, ADDS (SP plus register)

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-F-The-AArch32-Instruction-Sets/-Chapter-F5-T32-and-A32-Base-Instruction-Set-Instruction-Descriptions/-F5-1-Alphabetical-list-of-T32-and-A32-base-instruction-set-instructions/-F5-1-9-ADD--ADDS--SP-plus-register->

##### F5.1.9 ADD, ADDS (SP plus register)

Add to SP (register) adds an optionally-shifted register value to the SP value, and writes the result to the destination register.

If the destination register is not the PC, the ADDS variant of the instruction updates the condition flags based on the result.

The field descriptions for `<Rd>` identify the encodings where the PC is permitted as the destination register. Arm deprecates any use of these encodings. However, when the destination register is the PC:

- The ADD variant of the instruction is an interworking branch, see [Pseudocode description of operations on the AArch32 general-purpose registers and the PC](/documentation/ddi0487/mc/-Part-E-The-AArch32-Application-Level-Architecture/-Chapter-E1-The-AArch32-Application-Level-Programmers--Model/-E1-2-The-Application-level-programmers--model-in-AArch32-state/-E1-2-3-The-general-purpose-registers--and-the-PC--in-AArch32-state?lang=en#beicjfeh).
- The ADDS variant of the instruction performs an exception return without the use of the stack. In this case:
  - The PE branches to the address written to the PC, and restores [PSTATE](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G1-The-AArch32-System-Level-Programmers--Model/-G1-11-Process-state--PSTATE?lang=en#chdedfdc) from SPSR\_<current\_mode>.
  - The PE checks SPSR\_<current\_mode> for an illegal return event. See [Illegal return events from AArch32 state](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G1-The-AArch32-System-Level-Programmers--Model/-G1-15-Exception-return-to-an-Exception-level-using-AArch32/-G1-15-3-Illegal-return-events-from-AArch32-state?lang=en#chdddjdb).
  - The instruction is UNDEFINED in Hyp mode.
  - The instruction is CONSTRAINED UNPREDICTABLE in User mode and System mode.

It has encodings from the following instruction sets: A32 ([A1](/documentation/ddi0487/mc/-Part-F-The-AArch32-Instruction-Sets/-Chapter-F5-T32-and-A32-Base-Instruction-Set-Instruction-Descriptions/-F5-1-Alphabetical-list-of-T32-and-A32-base-instruction-set-instructions/-F5-1-9-ADD--ADDS--SP-plus-register-?lang=en#isa_add_sp_r_iclass_a1)) and T32 ([T1](/documentation/ddi0487/mc/-Part-F-The-AArch32-Instruction-Sets/-Chapter-F5-T32-and-A32-Base-Instruction-Set-Instruction-Descriptions/-F5-1-Alphabetical-list-of-T32-and-A32-base-instruction-set-instructions/-F5-1-9-ADD--ADDS--SP-plus-register-?lang=en#isa_add_sp_r_iclass_t1), [T2](/documentation/ddi0487/mc/-Part-F-The-AArch32-Instruction-Sets/-Chapter-F5-T32-and-A32-Base-Instruction-Set-Instruction-Descriptions/-F5-1-Alphabetical-list-of-T32-and-A32-base-instruction-set-instructions/-F5-1-9-ADD--ADDS--SP-plus-register-?lang=en#isa_add_sp_r_iclass_t2), and [T3](/documentation/ddi0487/mc/-Part-F-The-AArch32-Instruction-Sets/-Chapter-F5-T32-and-A32-Base-Instruction-Set-Instruction-Descriptions/-F5-1-Alphabetical-list-of-T32-and-A32-base-instruction-set-instructions/-F5-1-9-ADD--ADDS--SP-plus-register-?lang=en#isa_add_sp_r_iclass_t3)).

###### A1

![](images/5626-F5.1.9-ADD-ADDS-SP-plus-register-img01.svg)

###### Encoding for the ADD, rotate right with extend variant

Applies when `(S == 0 && imm5 == 00000 && stype == 11)`

```
ADD{<c>}{<q>}  {<Rd>, }SP, <Rm> , RRX
```

###### Encoding for the ADD, shift or rotate by value variant

Applies when `(S == 0 && !(imm5 == 00000 && stype == 11))`

```
ADD{<c>}{<q>}  {<Rd>, }SP, <Rm> {, <shift> #<amount>}
```

###### Encoding for the ADDS, rotate right with extend variant

Applies when `(S == 1 && imm5 == 00000 && stype == 11)`

```
ADDS{<c>}{<q>}  {<Rd>, }SP, <Rm> , RRX
```

###### Encoding for the ADDS, shift or rotate by value variant

Applies when `(S == 1 && !(imm5 == 00000 && stype == 11))`

```
ADDS{<c>}{<q>}  {<Rd>, }SP, <Rm> {, <shift> #<amount>}
```

###### Decode for all variants of this encoding

```
let d : integer = UInt(Rd);
let m : integer = UInt(Rm);
let setflags : boolean = (S == ‘1’);
let (shift_t, shift_n) : (SRType, integer) = DecodeImmShift(stype, imm5);
```

###### T1

![](images/5626-F5.1.9-ADD-ADDS-SP-plus-register-img02.svg)

###### Encoding

```
ADD{<c>}{<q>}  {<Rdm>, }SP, <Rdm>
```

###### Decode for this encoding

```
let d : integer = UInt(DM::Rdm);
let m : integer = UInt(DM::Rdm);
let setflags : boolean = FALSE;
let shift_t : SRType = SRType_LSL;
let shift_n : integer = 0;
if d == 15 && InITBlock() && !LastInITBlock() then UnpredictableProcedure(); end;
```

###### T2

![](images/5626-F5.1.9-ADD-ADDS-SP-plus-register-img03.svg)

###### Encoding

```
ADD{<c>}{<q>}  {SP, }SP, <Rm>
```

###### Decode for this encoding

```
if Rm == ‘1101’ then See(“encoding T1”); end;
let d : integer = 13;
let m : integer = UInt(Rm);
let setflags : boolean = FALSE;
let shift_t : SRType = SRType_LSL;
let shift_n : integer = 0;
```

###### T3

![](images/5626-F5.1.9-ADD-ADDS-SP-plus-register-img04.svg)

###### Encoding for the ADD, rotate right with extend variant

Applies when `(S == 0 && imm3 == 000 && imm2 == 00 && stype == 11)`

```
ADD{<c>}{<q>}  {<Rd>, }SP, <Rm>, RRX
```

###### Encoding for the ADD, shift or rotate by value variant

Applies when `(S == 0 && !(imm3 == 000 && imm2 == 00 && stype == 11))`

```
ADD{<c>}{<q>}  {<Rd>, }SP, <Rm> {, <shift> #<amount>}
```

```
ADD{<c>}.W  {<Rd>, }SP, <Rm> // (<Rd>, <Rm> can be represented in T1 or T2)
```

###### Encoding for the ADDS, rotate right with extend variant

Applies when `(S == 1 && imm3 == 000 && Rd != 1111 && imm2 == 00 && stype == 11)`

```
ADDS{<c>}{<q>}  {<Rd>, }SP, <Rm>, RRX
```

###### Encoding for the ADDS, shift or rotate by value variant

Applies when `(S == 1 && Rd != 1111 && !(imm3 == 000 && imm2 == 00 && stype == 11))`

```
ADDS{<c>}{<q>}  {<Rd>, }SP, <Rm> {, <shift> #<amount>}
```

###### Decode for all variants of this encoding

```
if Rd == ‘1111’ && S == ‘1’ then See(“CMN (register)”); end;
let d : integer = UInt(Rd);
let m : integer = UInt(Rm);
let setflags : boolean = (S == ‘1’);
let (shift_t, shift_n) : (SRType, integer) = DecodeImmShift(stype, imm3::imm2);
// Armv8-A removes UNPREDICTABLE for R13
if (d == 15 && !setflags) || m == 15 then UnpredictableProcedure(); end;
```

For more information about the CONSTRAINED UNPREDICTABLE behavior, see [Architectural Constraints on UNPREDICTABLE behaviors](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K1-Architectural-Constraints-on-UNPREDICTABLE-Behaviors?lang=en#cjaegdjc).

    ​

    See [Standard assembler syntax fields](/documentation/ddi0487/mc/-Part-F-The-AArch32-Instruction-Sets/-Chapter-F1-About-the-T32-and-A32-Instruction-Descriptions/-F1-2-Standard-assembler-syntax-fields?lang=en#babbefhf).

<Rd>
:   ​

    For the “A1 ADD, rotate right with extend”, “A1 ADD, shift or rotate by value”, “A1 ADDS, rotate right with extend”, and “A1 ADDS, shift or rotate by value” variants: is the general-purpose destination register, encoded in the “Rd” field. If omitted, this register is the SP. Arm deprecates using the PC as the destination register, but if the PC is used:

    - For the ADD variant, the instruction is a branch to the address calculated by the operation. This is an interworking branch, see [Pseudocode description of operations on the AArch32 general-purpose registers and the PC](/documentation/ddi0487/mc/-Part-E-The-AArch32-Application-Level-Architecture/-Chapter-E1-The-AArch32-Application-Level-Programmers--Model/-E1-2-The-Application-level-programmers--model-in-AArch32-state/-E1-2-3-The-general-purpose-registers--and-the-PC--in-AArch32-state?lang=en#beicjfeh).
    - For the ADDS variant, the instruction performs an exception return, that restores [PSTATE](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G1-The-AArch32-System-Level-Programmers--Model/-G1-11-Process-state--PSTATE?lang=en#chdedfdc) from SPSR\_<current\_mode>.

    ​

    For the “T3 ADD, rotate right with extend”, “T3 ADD, shift or rotate by value”, “T3 ADDS, rotate right with extend”, and “T3 ADDS, shift or rotate by value” variants: is the general-purpose destination register, encoded in the “Rd” field. If omitted, this register is the SP.

<Rm>
:   ​

    For the “A1 ADD, rotate right with extend”, “A1 ADD, shift or rotate by value”, “A1 ADDS, rotate right with extend”, “A1 ADDS, shift or rotate by value”, and “T2” variants: is the second general-purpose source register, encoded in the “Rm” field. The PC can be used, but this is deprecated.

    ​

    For the “T3 ADD, rotate right with extend”, “T3 ADD, shift or rotate by value”, “T3 ADDS, rotate right with extend”, and “T3 ADDS, shift or rotate by value” variants: is the second general-purpose source register, encoded in the “Rm” field.

<amount>
:   ​

    For the “A1 ADD, shift or rotate by value” and “A1 ADDS, shift or rotate by value” variants: is the shift amount, in the range 1 to 31 (when <shift> = LSL or ROR) or 1 to 32 (when <shift> = LSR or ASR) encoded in the “imm5” field as <amount> modulo 32.

    ​

    For the “T3 ADD, shift or rotate by value” and “T3 ADDS, shift or rotate by value” variants: is the shift amount, in the range 1 to 31 (when <shift> = LSL or ROR) or 1 to 32 (when <shift> = LSR or ASR), encoded in the “imm3:imm2” field as <amount> modulo 32.

<Rdm>
:   ​

    Is the general-purpose destination and second source register, encoded in the “Rdm” field. If omitted, this register is the SP. Arm deprecates using the PC as the destination register, but if the PC is used, the instruction is a branch to the address calculated by the operation. This is a simple branch, see [Pseudocode description of operations on the AArch32 general-purpose registers and the PC](/documentation/ddi0487/mc/-Part-E-The-AArch32-Application-Level-Architecture/-Chapter-E1-The-AArch32-Application-Level-Programmers--Model/-E1-2-The-Application-level-programmers--model-in-AArch32-state/-E1-2-3-The-general-purpose-registers--and-the-PC--in-AArch32-state?lang=en#beicjfeh).

SP
:   ​

    Is the stack pointer.

###### Operation

```
if ConditionPassed() then
    EncodingSpecificOperations();
    let shifted : bits(32) = Shift{}(R(m), shift_t, shift_n, PSTATE.C);
    let (result, nzcv) : (bits(32), bits(4)) = AddWithCarry{32}(R(13), shifted, ‘0’);
    if d == 15 then
        if setflags then
            ALUExceptionReturn(result);
        else
            ALUWritePC(result);
        end;
    else
        R(d) = result;
        if setflags then
            PSTATE.[N,Z,C,V] = nzcv;
        end;
    end;
end;
```
