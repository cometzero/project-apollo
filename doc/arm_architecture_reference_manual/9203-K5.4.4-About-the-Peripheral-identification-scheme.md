##### K5.4.4 About the Peripheral identification scheme

The Peripheral Identification scheme provides the standard information required by all components that conform to the *Arm® Debug Interface Architecture Specification, ADIv5.0 to ADIv5.2*, that implements the CoreSight identification scheme. They identify a peripheral in a particular namespace. For more information, see the *Arm® CoreSight™ Architecture Specification*.

A component is identified uniquely by the combination of the following fields:

- JEP106 continuation code.
- JEP106 identification code.
- Part number.
- REVISION.
- REVAND.

For components with a *Component class* of `0x9`, Debug component, indicated by the Component Identification Registers, multiple components can have the same Part number, provided each component has a different CoreSight *Device type* or *Device architecture*. ###### K5.4.4.1 Allocating revisions and part numbers

Within the Peripheral Identification registers, the allocation of major and minor revisions, part numbers, and customer-modified fields is IMPLEMENTATION DEFINED.

The size of the part number is specific to the designer of the component, but is typically 12-bits wide or 16-bits wide. How component revision information is presented is specific to the designer of the component, and might also be specific to each individual component with a different part number. Arm recommends one of the following styles is used:

- For a component with a 12-bit part number:

  - [PIDR1](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-4-About-the-Peripheral-identification-scheme?lang=en#pidr1).PART\_1 contains part number bits [11:8].
  - [PIDR0](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-4-About-the-Peripheral-identification-scheme?lang=en#pidr0).PART\_0 contains part number bits [7:0].
  - Where the component uses single 4-bit revision number:

    - [PIDR2](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-4-About-the-Peripheral-identification-scheme?lang=en#pidr2).REVISION indicates the 4-bit revision number.
    - [PIDR3](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-4-About-the-Peripheral-identification-scheme?lang=en#pidr3).REVAND indicates component modifications.
  - Where the component uses separate major and minor revision numbers:

    - [PIDR2](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-4-About-the-Peripheral-identification-scheme?lang=en#pidr2).REVISION indicates the 4-bit major revision number.
    - [PIDR3](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-4-About-the-Peripheral-identification-scheme?lang=en#pidr3).REVAND indicates the 4-bit minor revision number.
- For a component with a 16-bit part number:

  - [PIDR1](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-4-About-the-Peripheral-identification-scheme?lang=en#pidr1).PART\_1 contains part number bits [15:12].
  - [PIDR0](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-4-About-the-Peripheral-identification-scheme?lang=en#pidr0).PART\_0 contains part number bits [11:4].
  - [PIDR2](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-4-About-the-Peripheral-identification-scheme?lang=en#pidr2).REVISION contains part number bits [3:0].
  - [PIDR3](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-4-About-the-Peripheral-identification-scheme?lang=en#pidr3).REVAND indicates the 4-bit revision number.

Arm recommends that the revision information is updated for each update to the component, regardless of whether this is a major or minor update. The revision information increases monotonically with each revision of the component. When the REVAND field is updated on a new revision, this field is incremented monotonically. When the REVISION field is updated on a new revision, REVAND is typically set to zero on the first release of this new revision.
