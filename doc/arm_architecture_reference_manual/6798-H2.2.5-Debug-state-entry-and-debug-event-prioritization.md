# ​H2.2.5 Debug state entry and debug event prioritization

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H2-Debug-State/-H2-2-Halting-the-PE-on-debug-events/-H2-2-5-Debug-state-entry-and-debug-event-prioritization>

##### H2.2.5 Debug state entry and debug event prioritization

The following are synchronous debug events:

- Breakpoint debug event.
- Watchpoint debug event.
- Halting Step debug event.
- Halt Instruction debug event.
- Exception Catch debug event.
- Software Access debug event.
- Reset Catch debug event.

Each of these synchronous debug events are treated as a synchronous exception generated by an instruction, or by the taking of an exception or reset. That is, if halting is allowed, the synchronous debug event must be taken before any subsequent instructions are executed. Reset Catch debug events must be taken before the PE executes the instruction at the reset vector.

> #### Note
>
> - Reset Catch and Exception Catch debug events might be generated asynchronously, because they can result from an asynchronous exception. However, if halting is allowed after the reset or asynchronous exception has been processed, the Reset Catch or Exception Catch debug event is taken synchronously.
> - The Halting Step debug event is generated by the instruction after the stepped instruction. Therefore, if the stepped instruction generates any other synchronous exceptions or debug events these are taken first.

If halting is prohibited then Halting Step debug events and Reset Catch debug events might be pended and taken asynchronously. OS Unlock Catch debug events are always pended and taken asynchronously. See [Pending Halting debug events](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H3-Halting-Debug-Events/-H3-9-Synchronization-and-Halting-debug-events/-H3-9-1-Pending-Halting-debug-events?lang=en#babchiec).

The architecture does not define when asynchronous debug events are taken, and therefore the prioritization of asynchronous debug events is IMPLEMENTATION DEFINED. See [Synchronization and Halting debug events](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H3-Halting-Debug-Events/-H3-9-Synchronization-and-Halting-debug-events?lang=en#babgeeca).

The following list shows how the synchronous debug events are prioritized, with 1 being the highest priority.

> #### Note
>
> The priority numbering is the same as the numbering for AArch64 synchronous exception priorities listed in [Synchronous exception types](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-4-Exceptions/-D1-4-5-Synchronous-exception-types?lang=en#beibcfcc), and in particular [Prioritization of asynchronous exceptions](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-4-Exceptions/-D1-4-6-Asynchronous-exception-types?lang=en#beiidfea). This numbering correlates with the equivalent AArch32 list in [Exception prioritization for exceptions taken to AArch32 state](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G1-The-AArch32-System-Level-Programmers--Model/-G1-13-Handling-exceptions-that-are-taken-to-an-Exception-level-using-AArch32/-G1-13-2-Exception-prioritization-for-exceptions-taken-to-AArch32-state?lang=en#chdidhje).

The priority for synchronous debug events is as follows:

1
:   Reset Catch debug event. See [Reset Catch debug events](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H3-Halting-Debug-Events/-H3-7-Reset-Catch-debug-events?lang=en#babhbbeg).

    This debug event has a higher priority than the synchronous exceptions listed in [Synchronous exception types](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-4-Exceptions/-D1-4-5-Synchronous-exception-types?lang=en#beibcfcc).

2
:   Exception Catch debug event if it has a priority of 2. See [Exception Catch debug event](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H3-Halting-Debug-Events/-H3-4-Exception-Catch-debug-event?lang=en#exception_catch_debug_event).

    This debug event can be assigned one of two priorities, 2 or 5. When it has a priority of 2, it has a higher priority than the synchronous exceptions listed in the Exception model.

3
:   Halting Step debug event. See [Halting Step debug events](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H3-Halting-Debug-Events/-H3-2-Halting-Step-debug-events?lang=en#babfcjha).

    This debug event has a higher priority than the synchronous exceptions listed in the Exception model.

4
:   This event is not a debug event.

5
:   Exception Catch debug event if it has a priority of 5. See [Exception Catch debug event](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H3-Halting-Debug-Events/-H3-4-Exception-Catch-debug-event?lang=en#exception_catch_debug_event).

    This debug event can be assigned one of two priorities, 2 or 5.

6-9
:   These events are not debug events.

10
:   Breakpoint debug events. See [Breakpoint and Watchpoint debug events](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H2-Debug-State/-H2-2-Halting-the-PE-on-debug-events/-H2-2-3-Breakpoint-and-Watchpoint-debug-events?lang=en#babjijfb).

11-13
:   These events are not debug events.

14
:   Halt Instruction debug event. See [Halt Instruction debug event](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H3-Halting-Debug-Events/-H3-3-Halt-Instruction-debug-event?lang=en#babebjgf).

15-40
:   These events are not debug events.

41
:   Software Access debug event. See [Software Access debug event](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H3-Halting-Debug-Events/-H3-8-Software-Access-debug-event?lang=en#babcedie).

42-46
:   These events are not debug events.

47
:   Watchpoint debug events. See [Breakpoint and Watchpoint debug events](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H2-Debug-State/-H2-2-Halting-the-PE-on-debug-events/-H2-2-3-Breakpoint-and-Watchpoint-debug-events?lang=en#babjijfb).

48-49
:   These events are not debug events.

For Reset Catch debug events and Halting Step debug events, the priorities listed in this section apply only when halting is allowed at the time the event is generated. This means that the event is taken synchronously and not pended.

###### H2.2.5.1 Breakpoint debug events and Vector Catch exception

An Address Matching Vector Catch exception has the same priority as a Breakpoint debug event. See [Prioritization of Synchronous exceptions taken to AArch64 state](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-4-Exceptions/-D1-4-5-Synchronous-exception-types?lang=en#mdsec_prioritization_of_synchronous_exceptions_taken_to_aarch64_state).

The prioritization of these events is unchanged even if the breakpoint generates entry to Debug state instead of a Breakpoint exception. This means that if a single instruction generates both an Address Matching Vector Catch exception and a Breakpoint debug event, there is a CONSTRAINED UNPREDICTABLE choice of:

- The PE entering Debug state due to the Breakpoint debug event.
- A Vector Catch exception.

This applies only if all of the following are true:

- Halting debug is enabled.
- Halting is allowed.
- The OS Lock is unlocked.

An Exception Trapping Vector Catch exception must be generated immediately following the exception that generated it. This means that it does not appear in the priority table.
