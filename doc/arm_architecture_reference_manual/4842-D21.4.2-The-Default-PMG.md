# ​D21.4.2 The Default PMG

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-4-Performance-Monitoring-Groups--PMGs-/-D21-4-2-The-Default-PMG>

##### D21.4.2 The Default PMG

R CZSZX
:   The *Default PMG* number is 0.

R PQSLB
:   In each of the following scenarios, the MPAM PE Requester sends the Default PMG as part of the [MPAM information bundle](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-1-About-MPAM/-D21-1-2-MPAM-information-bundles?lang=en#mpam_mpam_information_bundles):

    - When the [MPAM enable control](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-1-About-MPAM/-D21-1-6-The-MPAM-enable-control?lang=en#mpam_mpam_enabled_control) is 0, meaning that MPAM is disabled.
    - When a PMG is an *out-of-range* PMG and the choice of CONSTRAINED UNPREDICTABLE behavior is to replace it with the Default PMG. See [Behavior when a PMG is out-of-range](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-9-MPAM-errors/-D21-9-3-Behavior-when-a-PMG-is-out-of-range?lang=en#mpam_behavior_when_pmg_out_of_range).
    - When a Default PARTID is generated due to a PARTID generation error, and the choice of CONSTRAINED UNPREDICTABLE behavior is to send the Default PMG. See [PMG value when a Default PARTID is generated due to an MPAM error](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-9-MPAM-errors/-D21-9-4-PMG-value-when-a-Default-PARTID-is-generated-due-to-an-MPAM-error?lang=en#mpam_pmg_value_when_default_partid_is_generated_due_to_an_mpam_error).

I TJBXP
:   > #### Note
    >
    > The MPAM architecture permits SoC designers to make non-MPAM Requesters label every request to the memory system with the Default PMG.
