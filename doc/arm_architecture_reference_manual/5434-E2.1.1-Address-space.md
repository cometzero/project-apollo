# ​E2.1.1 Address space

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-E-The-AArch32-Application-Level-Architecture/-Chapter-E2-The-AArch32-Application-Level-Memory-Model/-E2-1-About-the-Arm-memory-model/-E2-1-1-Address-space>

##### E2.1.1 Address space

Address calculations are performed using 32-bit registers. Supervisory software determines the valid address range.

Attempting to access an address that is not valid generates an [MMU fault](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G5-The-AArch32-Virtual-Memory-System-Architecture/-G5-11-VMSAv8-32-memory-aborts?lang=en#aa32_mmu_fault).

Address calculations are performed modulo 232.

The result of an address calculation is UNKNOWN if it overflows or underflows the 32-bit address range A[31:0].

Memory accesses use the [`MemA`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-105-MemA?lang=en#asl_accessor_mema_2)`{size}()`, [`MemO`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-106-MemO?lang=en#asl_accessor_memo_2)`{size}()`, [`MemU`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-108-MemU?lang=en#asl_accessor_memu_2)`{size}()`, and [`MemU_unpriv`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-109-MemU-unpriv?lang=en#asl_accessor_memu_unpriv_2)`{size}()` pseudocode accessors:

- The [`MemA`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-105-MemA?lang=en#asl_accessor_mema_2)`{size}()` accessor makes an aligned access of the required type.
- The [`MemO`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-106-MemO?lang=en#asl_accessor_memo_2)`{size}()` accessor makes an ordered access of the required type.
- The [`MemU`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-108-MemU?lang=en#asl_accessor_memu_2)`{size}()` accessor makes an unaligned access of the required type
- The [`MemU_unpriv`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-109-MemU-unpriv?lang=en#asl_accessor_memu_unpriv_2)`{size}()` accessor makes an unaligned, unprivileged access of the required type.

Each of these accessors calls the [`Mem_with_type`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-110-Mem-with-type?lang=en#asl_accessor_mem_with_type_3)`{size}()` accessor, which specifies the required access. This calls [`AArch32_MemSingle`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-98-AArch32-MemSingle?lang=en#asl_accessor_aarch32_memsingle_4)`{size}()`, which performs an atomic, little-endian read.

The [`AccessDescriptor`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-370-AccessDescriptor?lang=en#asl_type_accessdescriptor) type defines the different access types and attributes.
