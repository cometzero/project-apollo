# ​D20.5.2 ESB and delegated SError exceptions

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event/-D20-5-2-ESB-and-delegated-SError-exceptions>

##### D20.5.2 ESB and delegated SError exceptions

R KKPVY
:   If all of the following are true, then an [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction executed at EL0, EL1, or EL2 synchronizes a pending delegated SError exception:

    - [FEAT\_E3DSE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-6-The-Armv9-5-architecture-extension?lang=en#feat_feat_e3dse) is implemented.
    - [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).{EnDSE, DSE} is {`0b1`, `0b1`}.
    - [VSESR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-9-RAS-registers/-D24-9-19-VSESR-EL3--Virtual-SError-Exception-Syndrome-Register--EL3-?lang=en#reg_aarch64_vsesr_el3) is writable.

    In this case, a delegated SError exception is pending, and the following occur when an [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction is executed at EL0, EL1, or EL2:

    - If the delegated SError exception is unmasked at the current Exception level, then the exception is taken before the completion of the [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction.
    - If the delegated SError exception is masked at the current Exception level, then all the following occur:

      - [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).DSE is cleared to `0b0`.
      - The delegated SError exception syndrome from [VSESR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-9-RAS-registers/-D24-9-19-VSESR-EL3--Virtual-SError-Exception-Syndrome-Register--EL3-?lang=en#reg_aarch64_vsesr_el3) is recorded in [VDISR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-9-RAS-registers/-D24-9-17-VDISR-EL3--Virtual-Deferred-Interrupt-Status-Register--EL3-?lang=en#reg_aarch64_vdisr_el3).
      - [VDISR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-9-RAS-registers/-D24-9-17-VDISR-EL3--Virtual-Deferred-Interrupt-Status-Register--EL3-?lang=en#reg_aarch64_vdisr_el3).A is set to `0b1` to indicate the delegated SError exception was pending prior to the execution of the [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction.

R GGVCW
:   If all of the following are true, then it is IMPLEMENTATION DEFINED whether or not an [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction executed at EL0, EL1, or EL2 synchronizes a pending delegated SError exception:

    - [FEAT\_E3DSE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-6-The-Armv9-5-architecture-extension?lang=en#feat_feat_e3dse) is implemented.
    - [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).{EnDSE, DSE} is {`0b1`, `0b1`}.
    - The [VSESR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-9-RAS-registers/-D24-9-19-VSESR-EL3--Virtual-SError-Exception-Syndrome-Register--EL3-?lang=en#reg_aarch64_vsesr_el3) register is implemented as RAZ/WI.

    In this case, a delegated SError exception is pending. If the IMPLEMENTATION DEFINED choice is that the [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction synchronizes a pending delegated SError exception, then the following occur when an [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction is executed at EL0, EL1, or EL2:

    - If the delegated SError exception is unmasked at the current Exception level, then the exception is taken before the completion of the [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction.
    - If the delegated SError exception is masked at the current Exception level, then all the following occur:

      - [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).DSE is cleared to `0b0`.
      - The delegated SError exception syndrome in [VDISR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-9-RAS-registers/-D24-9-17-VDISR-EL3--Virtual-Deferred-Interrupt-Status-Register--EL3-?lang=en#reg_aarch64_vdisr_el3) is set to zero.
      - [VDISR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-9-RAS-registers/-D24-9-17-VDISR-EL3--Virtual-Deferred-Interrupt-Status-Register--EL3-?lang=en#reg_aarch64_vdisr_el3).A is set to `0b1` to indicate the delegated SError exception was pending prior to the execution of the [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction.

    If the IMPLEMENTATION DEFINED choice is that the [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction does not synchronize a pending delegated SError exception, then an [`ESB`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-159-ESB?lang=en#isa_esb) instruction executed at EL1 or EL2 ignores the pending delegated SError exception and the delegated SError exception stays pending.

    See also [Syndrome registers](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-7-Error-records-in-the-PE/-D20-7-1-Error-record-System-register-view?lang=en#mdsec_fields_in_sys_registers).

I VYGVB
:   If both a delegated SError exception and a physical SError exception are pending as described in [RKKPVY](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event/-D20-5-2-ESB-and-delegated-SError-exceptions?lang=en#kkpvy) and [Error synchronization event](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D20-RAS-PE-Architecture/-D20-5-Error-synchronization-event?lang=en#mdsec_error_synchronization_event), then the physical SError exception is not masked at the current Exception level, because this is not possible when a delegated SError exception is pending. This means that:

    - If the delegated SError exception is masked at the current Exception level, then the physical SError exception will be taken before the `ESB` instruction completes and [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).DSE and [VDISR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-9-RAS-registers/-D24-9-17-VDISR-EL3--Virtual-Deferred-Interrupt-Status-Register--EL3-?lang=en#reg_aarch64_vdisr_el3) are unchanged.
    - If the delegated SError exception is not masked at the current Exception level, then it is IMPLEMENTATION DEFINED which of the delegated SError or physical SError exceptions is taken before the `ESB` instruction completes. If the delegated SError exception is taken and, after taking the exception to EL1 or EL2, the physical SError exception is still pending, then the physical SError exception is still not masked and will be taken.

    A virtual SError exception injected using [HCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-61-HCR-EL2--Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcr_el2).VSE has priority over a delegated SError exception injected using [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).DSE when both are synchronized by `ESB`.
