# ​G8.2.98 ID_MMFR5, Memory Model Feature Register 5

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-2-General-system-control-registers/-G8-2-98-ID-MMFR5--Memory-Model-Feature-Register-5>

##### G8.2.98 ID\_MMFR5, Memory Model Feature Register 5

The ID\_MMFR5 characteristics are:

Purpose
:   Provides information about the implemented memory model and memory management support in AArch32 state.

    For general information about the interpretation of the ID registers, see [‘Principles of the ID scheme for fields in ID registers’](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-1-About-the-AArch32-System-registers/-G8-1-3-Principles-of-the-ID-scheme-for-fields-in-ID-registers?lang=en#chdidagf).

Configuration
:   AArch32 System register ID\_MMFR5 bits [31:0] are architecturally mapped to AArch64 System register [ID\_MMFR5\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-112-ID-MMFR5-EL1--AArch32-Memory-Model-Feature-Register-5?lang=en#reg_aarch64_id_mmfr5_el1)[31:0].

    This register is present only when FEAT\_AA32EL1 is implemented. Otherwise, direct accesses to ID\_MMFR5 are UNDEFINED.

Attributes
:   ID\_MMFR5 is a 32-bit register.

    Non-coherent physical translation caches are non-coherent caches of previous valid translation table entries since the last completed relevant TLBI applicable to the PE, where either:

    - The caching is indexed by the physical address of the location holding the translation table entry.
    - The caching is used for stage 1 translations and is indexed by the intermediate physical address of the location holding the translation table entry.

    All other values are reserved.

    [FEAT\_nTLBPA](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-1-The-Armv8-0-architecture-extension?lang=en#feat_feat_ntlbpa) implements the functionality identified by the value `0b0001`.

    From Armv8.0, the permitted values are `0b0000` and `0b0001`.

    Access to this field is RO.

    [FEAT\_ETS3](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-6-The-Armv9-5-architecture-extension?lang=en#feat_feat_ets3) implements the functionality identified by the value `0b0011`.

    From Armv8.8, the values `0b0000` and `0b0001` are not permitted.

    From Armv9.5, the value `0b0010` is not permitted.

    Access to this field is RO.
