##### D8.10.4 PSTATE.PACM

R BYRKF
:   All statements in this section require implementation of [FEAT\_PAuth\_LR](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-6-The-Armv9-5-architecture-extension?lang=en#feat_feat_pauth_lr).

I TQTGT
:   [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate) and the PACM instruction provide a mechanism to produce a program that can run on a PE that implements [FEAT\_PAuth\_LR](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-6-The-Armv9-5-architecture-extension?lang=en#feat_feat_pauth_lr) or on a PE that does not implement [FEAT\_PAuth\_LR](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-6-The-Armv9-5-architecture-extension?lang=en#feat_feat_pauth_lr), by extending the behavior of existing instructions for signing and authenticating a return address.

I RZKKL
:   `PACM` is intended to be executed immediately before a `PACIASP`, `PACIBSP`, `AUTIASP`, `AUTIBSP`, `RETAA`, `RETAB`, `AUTIA1716`, `AUTIB1716`, `PACIA1716`, or `PACIB1716` instruction, to extend the operation of those instructions to take a second diversifier.

R PLWLR
:   Unless otherwise specified, [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PACM is set to 0 after execution of any instruction..

R GJJYJ
:   If an IMPLEMENTATION DEFINED algorithm is implemented for Pointer authentication instructions other than the `PACGA` instruction, [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PACM is permitted to be a trivial implementation.

    Otherwise, [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PACM is fully implemented.

I LYDML
:   For a trivial implementation of [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PACM, all of the following apply:

    - The `PACM` instruction does not set [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PACM to 1.
    - The effects of `PACM` instructions are disabled at all Exception levels and [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PACM behaves as 0.
    - [SPSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#spsr_elx).PACM, [DSPSR\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-14-DSPSR-EL0--Debug-Saved-Program-Status-Register?lang=en#reg_aarch64_dspsr_el0).PACM, [HCRX\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-62-HCRX-EL2--Extended-Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcrx_el2).PACMEn, and [SCTLR2\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#sctlr2_elx).{EnPACM0, EnPACM} are fully implemented, although a value of 1 in these fields has no effect other than for reading back the value of the register.

    > #### Note
    >
    > If [FEAT\_PACIMP](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_pacimp) is implemented, then use of [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PACM to modify the behavior of a subsequent instruction might not result in the same PAC field insertion or authentication as the explicit instructions. For example, use of [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PACM to modify a subsequent `PACIASP` instruction might not result in the same PAC field insertion as a `PACIASPPC` instruction at the same PC as the `PACIASP`. This means that software should not mix the methods used to sign and authenticate a pointer, and should use a single method for a specific pointer.

R TQKBS
:   For a full implementation of [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PACM, if the effects of `PACM` instructions are enabled, then [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PACM is set to 1 after execution of a `PACM` instruction.

R WNZMT
:   If [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PACM is 1, then the behavior of the `PACIASP`, `PACIBSP`, `AUTIASP`, `AUTIBSP`, `RETAA`, `RETAB`, `AUTIA1716`, `AUTIB1716`, `PACIA1716`, and `PACIB1716` instructions are extended as follows:

    - The pseudocode function [`ComputePAC2`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-2-Pseudocode-for-AArch64-operation/-J1-2-388-ComputePAC2?lang=en#asl_func_computepac2_5)`()` is used for the generation of the PAC. See [RZYPJV](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-10-Pointer-authentication/-D8-10-3-PAC-instructions?lang=en#zypjv).
    - For the `PACIASP` and `PACIBSP` instructions, the 64-bit value of `modifier2` used in the generation of the PAC is the value specified in the PC.
    - For the `AUTIASP`, `AUTIBSP`, `RETAA`, and `RETAB` instructions, the 64-bit value of `modifier2` is the value in X16.
    - For the `AUTIA1716`, `AUTIB1716`, `PACIA1716`, and `PACIB1716` instructions, the 64-bit value of `modifier2` is the value in X15.

I SRKXB
:   Each of the [SCTLR2\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#sctlr2_elx).{EnPACM, EnPACM0} control bits enables or disables the effect of the `PACM` instruction at an Exception level.

I HBWFK
:   The [HCRX\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-62-HCRX-EL2--Extended-Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcrx_el2).PACMEn bit can control the effect of a `PACM` instruction at EL1 and EL0.

I RVHSQ
:   If the effects of `PACM` instructions are disabled at an Exception level, [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PACM cannot be set to 1 at that Exception level and is consistent with being treated as 0 at that Exception level.

I CDWGZ
:   When the `PACM` instruction is used, to ensure code is fully backward compatible with a PE that does not implement [FEAT\_PAuth\_LR](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-6-The-Armv9-5-architecture-extension?lang=en#feat_feat_pauth_lr), a `BTI` instruction must be used in the function prologue. For more information, see [PSTATE.BTYPE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-4-Memory-access-control/-D8-4-5-Effect-of-PSTATE-on-access-permission?lang=en#mdsec_pstate_btype).
