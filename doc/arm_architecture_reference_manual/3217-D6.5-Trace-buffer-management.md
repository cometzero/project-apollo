# ​D6.5 Trace buffer management

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management>

#### D6.5 Trace buffer management

I GYHBH
:   [FEAT\_TRBE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-1-The-Armv9-0-architecture-extension?lang=en#feat_feat_trbe) supports the following trace buffer modes:

    Circular Buffer mode
    :   In Circular Buffer mode, when the [*current write pointer*](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-1-About-the-Trace-Buffer-Extension/-D6-1-1-The-trace-buffer-pointers?lang=en#chdciahcf5) reaches the [*Limit pointer*](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-1-About-the-Trace-Buffer-Extension/-D6-1-1-The-trace-buffer-pointers?lang=en#chdfdibgj3), it is wrapped by setting it to the [*Base pointer*](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-1-About-the-Trace-Buffer-Extension/-D6-1-1-The-trace-buffer-pointers?lang=en#chdhagiii9).

    Wrap mode
    :   As Circular Buffer mode, except that an interrupt request is generated when the [*current write pointer*](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-1-About-the-Trace-Buffer-Extension/-D6-1-1-The-trace-buffer-pointers?lang=en#chdciahcf5) is wrapped.

    Fill mode
    :   As Wrap mode, except that trace collection stops when the [*current write pointer*](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-1-About-the-Trace-Buffer-Extension/-D6-1-1-The-trace-buffer-pointers?lang=en#chdciahcf5) is wrapped.

I FZXSV
:   The trace buffer mode is controlled by [TRBLIMITR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-3-TRBLIMITR-EL1--Trace-Buffer-Limit-Address-Register?lang=en#reg_aarch64_trblimitr_el1).FM.

I NFZKS
:   A trace buffer management event occurs:

    - On an Alignment fault or [MMU fault](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-15-Memory-aborts?lang=en#aa64_mmu_fault).
    - On an External abort.
    - On a *Trigger Event*, if enabled.
    - When the [*current write pointer*](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-1-About-the-Trace-Buffer-Extension/-D6-1-1-The-trace-buffer-pointers?lang=en#chdciahcf5) is wrapped to the [*Base pointer*](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-1-About-the-Trace-Buffer-Extension/-D6-1-1-The-trace-buffer-pointers?lang=en#chdhagiii9) and the trace buffer mode is not Circular Buffer mode. This event is known as:

      - A buffer wrap event, if the trace buffer mode is Wrap mode.
      - A buffer full event, if the trace buffer mode is Fill mode.
    - On a programming error, when permitted as an UNPREDICTABLE behavior of the PE. For more information, see [Restrictions on programming the Trace Buffer Unit](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-2-The-trace-buffer/-D6-2-2-Restrictions-on-programming-the-Trace-Buffer-Unit?lang=en#mdsec_ptr_align) and [UNPREDICTABLE behavior](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-11-UNPREDICTABLE-behavior?lang=en#mdsec_unp_behavior).
    - On an IMPLEMENTATION DEFINED event.

    > #### Note
    >
    > The trace buffer management event behavior differs from that of the SPE Profiling Buffer management event.

R HLKSG
:   On a trace buffer management event, all of the following occurs:

    - The interrupt request bit, [TRBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#trbsr_elx).IRQ, is set to 1.
    - Additional syndrome for the event might be written to [TRBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#trbsr_elx).MSS.

    The value of ELx depends on the type of event, and is defined by [RBNQRP](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#bnqrp). The other fields in [TRBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#trbsr_elx) and the other [TRBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#trbsr_elx) registers are unchanged.

R BNQRP
:   If [FEAT\_TRBE\_EXC](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_trbe_exc) is implemented and self-hosted trace is [enabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D3-AArch64-Self-hosted-Trace/-D3-1-About-self-hosted-trace/-D3-1-2-Register-controls-to-enable-self-hosted-trace?lang=en#sh_trace_enabled), then when a trace buffer management event is generated:

    - If EL3 is implemented and any of the following are true, then the management event is recorded in [TRBSR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-9-TRBSR-EL3--Trace-Buffer-Syndrome-Register--EL3-?lang=en#reg_aarch64_trbsr_el3):

      - [MDCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-18-MDCR-EL3--Monitor-Debug-Configuration-Register--EL3-?lang=en#reg_aarch64_mdcr_el3).TRBEE is `0b11`.
      - [MDCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-18-MDCR-EL3--Monitor-Debug-Configuration-Register--EL3-?lang=en#reg_aarch64_mdcr_el3).TRBEE is `0b10` and the management event is due to a fault on a write to the trace buffer that would generate a Data Abort exception taken to EL3 if generated by a store instruction executed at the [owning Exception level](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-3-Trace-buffer-Self-hosted-mode/-D6-3-5-The-owning-translation-regime?lang=en#trbe_owning_el). That is, any of the following faults on a write to the trace buffer:

        - Granule Protection Check (GPC) faults, other than Granule Protection Faults (GPFs). For more information, see [Granule Protection Check faults](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-4-Exceptions/-D1-4-5-Synchronous-exception-types?lang=en#chdgibfdf4).
        - If [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).GPF is 1, GPFs.
        - If [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).EA is 1, External aborts. See also [IFRNZK](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#frnzk).
      - [MDCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-18-MDCR-EL3--Monitor-Debug-Configuration-Register--EL3-?lang=en#reg_aarch64_mdcr_el3).TRBEE is `0b10` and the management event is an IMPLEMENTATION DEFINED buffer management event that the implementation elects to record in [TRBSR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-9-TRBSR-EL3--Trace-Buffer-Syndrome-Register--EL3-?lang=en#reg_aarch64_trbsr_el3).
    - Otherwise, if all of the following are true, then the management event is recorded in [TRBSR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-8-TRBSR-EL2--Trace-Buffer-Syndrome-Register--EL2-?lang=en#reg_aarch64_trbsr_el2):

      - EL3 is not implemented or [MDCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-18-MDCR-EL3--Monitor-Debug-Configuration-Register--EL3-?lang=en#reg_aarch64_mdcr_el3).TRBEE is not `0b00`.
      - EL2 is implemented and any of the following are true:

        - The Effective value of [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).NS is 1.
        - The Effective value of [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).{NS, EEL2} is {0, 1}.

        This applies even when the current Exception level is EL3.
      - One of the following is true:

        - [TRFCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-74-TRFCR-EL2--Trace-Filter-Control-Register--EL2-?lang=en#reg_aarch64_trfcr_el2).EE is `0b11`.
        - [TRFCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-74-TRFCR-EL2--Trace-Filter-Control-Register--EL2-?lang=en#reg_aarch64_trfcr_el2).EE is `0b10` and the management event is due to any fault on a write to the trace buffer that would generate a Data Abort exception taken to EL2 if generated by a store instruction executed at the [owning Exception level](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-3-Trace-buffer-Self-hosted-mode/-D6-3-5-The-owning-translation-regime?lang=en#trbe_owning_el).

          If the [owning Exception level](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-3-Trace-buffer-Self-hosted-mode/-D6-3-5-The-owning-translation-regime?lang=en#trbe_owning_el) is EL2, this means any fault on a write to the trace buffer.

          If the [owning Exception level](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-3-Trace-buffer-Self-hosted-mode/-D6-3-5-The-owning-translation-regime?lang=en#trbe_owning_el) is EL1, this means any of the following faults on a write to the trace buffer:

          - Stage 2 faults.
          - If [HCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-61-HCR-EL2--Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcr_el2).GPF is 1, GPFs.
          - If [HCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-61-HCR-EL2--Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcr_el2).TEA is 1, External aborts. See also [IFRNZK](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#frnzk).
        - [TRFCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-74-TRFCR-EL2--Trace-Filter-Control-Register--EL2-?lang=en#reg_aarch64_trfcr_el2).EE is `0b10` and the management event is due to a GPC fault other than a GPF.
        - [TRFCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-74-TRFCR-EL2--Trace-Filter-Control-Register--EL2-?lang=en#reg_aarch64_trfcr_el2).EE is `0b10` and the management event is an IMPLEMENTATION DEFINED buffer management event that the implementation elects to record in [TRBSR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-8-TRBSR-EL2--Trace-Buffer-Syndrome-Register--EL2-?lang=en#reg_aarch64_trbsr_el2).
    - Otherwise, the management event is recorded in [TRBSR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-7-TRBSR-EL1--Trace-Buffer-Status-syndrome-Register--EL1-?lang=en#reg_aarch64_trbsr_el1).

    If [FEAT\_TRBE\_EXC](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_trbe_exc) is not implemented or self-hosted trace is [disabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D3-AArch64-Self-hosted-Trace/-D3-1-About-self-hosted-trace/-D3-1-2-Register-controls-to-enable-self-hosted-trace?lang=en#sh_trace_disabled), then the management event is recorded in [TRBSR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-7-TRBSR-EL1--Trace-Buffer-Status-syndrome-Register--EL1-?lang=en#reg_aarch64_trbsr_el1).

    The pseudocode function [`ReportTRBEEvent`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-716-ReportTRBEEvent?lang=en#asl_func_reporttrbeevent_2)`()` shows this.

:   From Armv9.3, External aborts are not reported on writes to the trace buffer. However, External aborts on translation table walks, translation table updates, and GPT walks can be reported as MMU faults. See [Faults](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management/-D6-5-4-Faults?lang=en#mdsec_trbe_faults).

I KKVYZ
:   [Table D6-5](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#tbl_tracebuffereventgcp), [Table D6-6](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#tbl_tracebuffereventexternalabort), and [Table D6-7](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#tbl_tracebuffereventother) show which [TRBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#trbsr_elx) register used to record the syndrome for each type of trace buffer management event when self-hosted trace is [enabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D3-AArch64-Self-hosted-Trace/-D3-1-About-self-hosted-trace/-D3-1-2-Register-controls-to-enable-self-hosted-trace?lang=en#sh_trace_enabled).

    Each column in the left side of the tables refers to the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of a field in a System register.

    Each column in the right side of the tables represents a trace buffer management event:

    Other event
    :   Means a trace buffer management event recorded with the EC value `0b000000`.

    Stage 1 (GPF)
    :   Means a trace buffer management event for a Granule Protection Fault (GPF) reported as a stage 1 abort on a write to the buffer, recorded with the EC value of `0b100100` and an FSC value indicating a GPF.

    Stage 1 (External abort)
    :   Means a trace buffer management event for an External abort reported as a stage 1 abort on a write to the buffer, recorded with the EC value of `0b100100` and an FSC value indicating an External abort.

    Stage 1 (Other abort)
    :   Means a trace buffer management event for any other stage 1 abort on a write to the buffer, recorded with the EC value `0b100100`.

    Stage 2 (GPF)
    :   Means a trace buffer management event for a GPF reported as a stage 2 abort on a write to the buffer, recorded with the EC value of `0b100101` and an FSC value indicating a GPF.

    Stage 2 (External abort)
    :   Means a trace buffer management event for an External abort reported as a stage 2 abort on a write to the buffer, recorded with the EC value of `0b100101` and an FSC value indicating an External abort. That is, a synchronous External abort on a stage 2 translation table walk or translation table update.

    Stage 2 (Other abort)
    :   Means a trace buffer management event for any other stage 2 abort on a write to the buffer, recorded with the EC value `0b100101`.

    GPC fault
    :   Means a trace buffer management event for a Granule Protection Check fault, other than a GPF, on a write to the buffer, recorded with the EC value `0b011110`.

    The values in each of these cells denotes which [TRBSR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#trbsr_elx) register is updated for that combination of control register values and trace buffer management event type.

    - All of the following are true:

      - EL3 is implemented.
      - [MDCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-18-MDCR-EL3--Monitor-Debug-Configuration-Register--EL3-?lang=en#reg_aarch64_mdcr_el3).TRBEE is `0b10` or `0b11`.
      - [TRBSR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-9-TRBSR-EL3--Trace-Buffer-Syndrome-Register--EL3-?lang=en#reg_aarch64_trbsr_el3).IRQ is 1.

      In this case:

      - The target Exception level is EL3.
      - If all of the following are true, then the TRBE Profiling exception is *unmasked*:

        - The PE is executing at EL2, EL1, or EL0.
        - The PE is in Non-debug state.
    - All of the following are true:

      - EL3 is not implemented or [MDCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-18-MDCR-EL3--Monitor-Debug-Configuration-Register--EL3-?lang=en#reg_aarch64_mdcr_el3).TRBEE is not `0b00`.
      - EL2 is implemented and enabled in the current Security State.
      - [TRFCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-74-TRFCR-EL2--Trace-Filter-Control-Register--EL2-?lang=en#reg_aarch64_trfcr_el2).EE is `0b10` or `0b11`.
      - [TRBSR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-8-TRBSR-EL2--Trace-Buffer-Syndrome-Register--EL2-?lang=en#reg_aarch64_trbsr_el2).IRQ is 1.

      In this case:

      - The target Exception level is EL2.
      - If the PE is executing in the [owning Security state](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-3-Trace-buffer-Self-hosted-mode/-D6-3-5-The-owning-translation-regime?lang=en#trbe_owning_ss), the PE is in Non-debug state, and any of the following are true, then the TRBE Profiling exception is unmasked:

        - The PE is executing at EL1 or EL0.
        - The PE is executing at EL2, [TRFCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-74-TRFCR-EL2--Trace-Filter-Control-Register--EL2-?lang=en#reg_aarch64_trfcr_el2).EE is `0b11`, [TRFCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-74-TRFCR-EL2--Trace-Filter-Control-Register--EL2-?lang=en#reg_aarch64_trfcr_el2).KE is 1, and [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PM is 0.
    - All of the following are true:

      - EL3 is not implemented or [MDCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-18-MDCR-EL3--Monitor-Debug-Configuration-Register--EL3-?lang=en#reg_aarch64_mdcr_el3).TRBEE is not `0b00`.
      - EL2 is not implemented, or EL2 is disabled in the current Security State, or [TRFCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-74-TRFCR-EL2--Trace-Filter-Control-Register--EL2-?lang=en#reg_aarch64_trfcr_el2).EE is not `0b00`.
      - [TRFCR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-73-TRFCR-EL1--Trace-Filter-Control-Register--EL1-?lang=en#reg_aarch64_trfcr_el1).EE is `0b11`.
      - [TRBSR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-7-TRBSR-EL1--Trace-Buffer-Status-syndrome-Register--EL1-?lang=en#reg_aarch64_trbsr_el1).IRQ is 1.

      In this case:

      - The target Exception level is EL2 if the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [HCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-61-HCR-EL2--Hypervisor-Configuration-Register?lang=en#reg_aarch64_hcr_el2).TGE is 1, and EL1 otherwise.
      - If the PE is executing in the [owning Security state](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-3-Trace-buffer-Self-hosted-mode/-D6-3-5-The-owning-translation-regime?lang=en#trbe_owning_ss), the PE is in Non-debug state, and any of the following are true, then the TRBE Profiling exception is unmasked.

        - The PE is executing at EL0.
        - The PE is executing at EL1, [TRFCR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-73-TRFCR-EL1--Trace-Filter-Control-Register--EL1-?lang=en#reg_aarch64_trfcr_el1).KE is 1, and [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PM is 0.

    When self-hosted trace is [disabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D3-AArch64-Self-hosted-Trace/-D3-1-About-self-hosted-trace/-D3-1-2-Register-controls-to-enable-self-hosted-trace?lang=en#sh_trace_disabled) or none of the above apply, the TRBE Profiling exception is [disabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D3-AArch64-Self-hosted-Trace/-D3-1-About-self-hosted-trace/-D3-1-2-Register-controls-to-enable-self-hosted-trace?lang=en#babhfddh) and not pending.

    When the TRBE Profiling exception is [enabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#trbe_exception_enabled) and [unmasked](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#trbe_exception_unmasked), the TRBE Profiling exception will be taken to the [target Exception level](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#target_exception_trbe).

    When the TRBE Profiling exception is [enabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#trbe_exception_enabled) and not [unmasked](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#trbe_exception_unmasked), then the TRBE Profiling exception is *masked*. The TRBE Profiling exception is always [masked](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#trbe_exception_masked) at EL3.

    The pseudocode function [`CheckForTRBEException`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-700-CheckForTRBEException?lang=en#asl_func_checkfortrbeexception_0)`()` shows this.

:   [Table D6-8](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#tbl_trbeprofilingexceptiontrbsr_el1), [Table D6-9](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#tbl_trbeprofilingexceptiontrbsr_el2), and [Table D6-10](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-5-Trace-buffer-management?lang=en#tbl_trbeprofilingexceptiontrbsr_el3) show the TRBE Profiling exception enable and masking for each Exception level, for each of the [TRBSR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-7-TRBSR-EL1--Trace-Buffer-Status-syndrome-Register--EL1-?lang=en#reg_aarch64_trbsr_el1).IRQ, [TRBSR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-8-TRBSR-EL2--Trace-Buffer-Syndrome-Register--EL2-?lang=en#reg_aarch64_trbsr_el2).IRQ, and [TRBSR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-9-TRBSR-EL3--Trace-Buffer-Syndrome-Register--EL3-?lang=en#reg_aarch64_trbsr_el3).IRQ bits respectively when all of the following apply:

    - [FEAT\_TRBE\_EXC](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_trbe_exc) is implemented.
    - The PE is executing in AArch64 state.
    - Self-hosted trace is [enabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D3-AArch64-Self-hosted-Trace/-D3-1-About-self-hosted-trace/-D3-1-2-Register-controls-to-enable-self-hosted-trace?lang=en#sh_trace_enabled).

    Each column in the left side of the table refers to the [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of a field in a System register or [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).

    HIGH

    None
    :   Means the exception is disabled.     B
    :   Means the exception is enabled and masked by [PSTATE](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-5-Process-state--PSTATE?lang=en#pstate).PM. The exception remains pending.

    n/a
    :   Not applicable.     Otherwise, the TRBE Profiling exception is taken in finite time.
