# ​D2.8.5 Breakpoint instruction address comparisons

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D2-AArch64-Self-hosted-Debug/-D2-8-Breakpoint-exceptions/-D2-8-5-Breakpoint-instruction-address-comparisons>

##### D2.8.5 Breakpoint instruction address comparisons

In this subsection, the term `AddrTop` represents the most significant bit of a virtual address used by breakpoint data address comparisons. `AddrTop` is:

- 55, if address tagging is used for the address. See [Address tagging](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-8-Address-tagging?lang=en#mdsec_address_tagging).
- 63, otherwise.

> #### Note
>
> When stage 1 translation is enabled, in AArch64 state, the virtual address size is determined by the configured input address size for the stage 1 translation. Software can configure a smaller address width for a virtual address, see [Input address size configuration](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-1-Address-translation/-D8-1-9-Input-address-size-configuration?lang=en#mdsec_input_address_size_configuration). Attempting to translate an address that is larger than the configured input address size generates a Translation fault.
>
> When stage 1 translation is disabled, using an address that is larger than the implemented PA size generates an Address size fault. The implemented PA size is IMPLEMENTATION DEFINED, as described in [Implemented physical address size](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-1-Address-translation/-D8-1-6-Implemented-physical-address-size?lang=en#mdsec_implemented_physical_address_size).
>
> These faults have a higher priority than breakpoints.

An address comparison is successful if bits [`AddrTop`:2] of the current instruction virtual address are equal to [DBGBVR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-3-DBGBVR-n--EL1--Debug-Breakpoint-Value-Registers--n---0---63?lang=en#reg_aarch64_dbgbvrn_el1)[`AddrTop`:2].

> #### Note
>
> [DBGBVR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-3-DBGBVR-n--EL1--Debug-Breakpoint-Value-Registers--n---0---63?lang=en#reg_aarch64_dbgbvrn_el1) is a 64-bit register. The most significant bits of this register are sign-extension bits. [DBGBVR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-3-DBGBVR-n--EL1--Debug-Breakpoint-Value-Registers--n---0---63?lang=en#reg_aarch64_dbgbvrn_el1)[1:0] are RES0 and are ignored.

If EL1 is using AArch64 and EL0 is using AArch32, T32 and A32 instructions can be executed in stage 1 of an AArch64 translation regime. In this case, the instruction addresses are zero-extended before comparison with the breakpoint.

###### D2.8.5.2 Address Mismatch breakpoints

If [FEAT\_BWE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-5-The-Armv9-4-architecture-extension?lang=en#feat_feat_bwe) is not implemented, then mismatch breakpoints do not generate a breakpoint match in AArch64 state.

If [FEAT\_BWE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-5-The-Armv9-4-architecture-extension?lang=en#feat_feat_bwe) is implemented, then mismatch breakpoints can generate a breakpoint match in AArch64 state and this can cause entry to Debug state.

The behavior of an address mismatch breakpoint is the same as for an address match breakpoint, except that the result is inverted such that only addresses other than the specified address, or addresses outside of the range of addresses, generate a breakpoint match.

Other breakpoint conditions specified by [DBGBCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-2-DBGBCR-n--EL1--Debug-Breakpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgbcrn_el1) are not inverted.

###### D2.8.5.3 Programming a breakpoint range with eight or more bytes

A debugger can use the [DBGBCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-2-DBGBCR-n--EL1--Debug-Breakpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgbcrn_el1).MASK field to program a single breakpoint with an instruction address range if all of the following are true:

- It is a size that is:

  - A power-of-two.
  - A minimum of eight bytes.
  - A maximum of 2GB.
- It starts at an address that is aligned to the size.

If *m* least significant address bits are masked, the breakpoint generates a Breakpoint exception on all of the following:

- Address [DBGBCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-2-DBGBCR-n--EL1--Debug-Breakpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgbcrn_el1)[`AddrTop`:*m*]:000…
- Address [DBGBCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-2-DBGBCR-n--EL1--Debug-Breakpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgbcrn_el1)[`AddrTop`:*m*]:111…
- Any address between these two addresses.

For example, if the four least significant address bits are masked, Breakpoint exceptions are generated for all addresses between [DBGBCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-2-DBGBCR-n--EL1--Debug-Breakpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgbcrn_el1)[`AddrTop`:4]:0000 and [DBGBCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-2-DBGBCR-n--EL1--Debug-Breakpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgbcrn_el1)[`AddrTop`:4]:1111, including these addresses.

When masking address bits, a debugger must both:

- Program [DBGBCR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-2-DBGBCR-n--EL1--Debug-Breakpoint-Control-Registers--n---0---63?lang=en#reg_aarch64_dbgbcrn_el1).BAS to be `0b1111`. See [Programming dependencies of the BAS and MASK fields](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D2-AArch64-Self-hosted-Debug/-D2-8-Breakpoint-exceptions/-D2-8-7-Breakpoint-usage-constraints?lang=en#babihbaab9).
- In [DBGBVR<n>\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-3-DBGBVR-n--EL1--Debug-Breakpoint-Value-Registers--n---0---63?lang=en#reg_aarch64_dbgbvrn_el1), set the masked address bits to zero. See [Other usage constraints](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D2-AArch64-Self-hosted-Debug/-D2-9-Watchpoint-exceptions/-D2-9-7-Watchpoint-usage-constraints?lang=en#bcgidfib).
