# ​D8.10.5 Faulting on pointer authentication

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-10-Pointer-authentication/-D8-10-5-Faulting-on-pointer-authentication>

##### D8.10.5 Faulting on pointer authentication

I XBGSY
:   A PAC authentication failure for a given VA can cause a fault to be generated in the following three manners, according to the type of the instruction and whether [FEAT\_FPAC](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_fpac) and [FEAT\_FPACCOMBINE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_fpaccombine) are implemented:

    - The PAC instruction makes the VA non-canonical, such that a subsequent use of the VA generates a fault. In this case, the PAC instruction does not directly generate the fault.
    - The PAC instruction makes the VA non-canonical and uses that VA such that a fault is generated by that instruction.
    - The PAC instruction directly generates a PAC Fail exception, with EC code `0b011100`.

R MLWGL
:   If an instruction is a combined instruction that includes pointer authentication, then when the PAC is incorrect in a given VA, one of the following behaviors occurs:

    - For a combined authenticate and load instruction, then:

      - If [FEAT\_FPACCOMBINE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_fpaccombine) is not implemented, the VA is made non-canonical and then used as the address for the load.
      - If [FEAT\_FPACCOMBINE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_fpaccombine) is implemented, then the instruction generates a PAC Fail exception, with EC code `0b011100`.
    - For a combined authenticate and branch instruction, then:

      - If [FEAT\_FPACCOMBINE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_fpaccombine) is not implemented, the VA is made non-canonical and the PC is updated to this non-canonical value.
      - If [FEAT\_FPACCOMBINE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_fpaccombine) is implemented, then the instruction generates a PAC Fail exception, with EC code `0b011100`.

R KJSRQ
:   For a PAC authentication instruction, `AUT*`, when the PAC is incorrect for a given VA, one of the following behaviors occurs:

    - If [FEAT\_FPAC](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_fpac) is not implemented, the VA is made non-canonical.
    - If [FEAT\_FPAC](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_fpac) is implemented, then the instruction generates a PAC Fail exception, with EC code `0b011100`.

R XXFXH
:   Predicting the result of a PAC Authentication is a form of control flow prediction.

R GKVYD
:   Prediction of the results of a PAC Authentication must adhere to the requirements of [FEAT\_FPACC\_SPEC](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_fpacc_spec), if implemented.
