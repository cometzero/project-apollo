##### D24.1.1 Reading the System register descriptions

###### D24.1.1.1 Registers and register names

The title of each section in [AArch64 System Register Descriptions](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions?lang=en#autogen_registers_aarch64) refers to a register.

An AArch64 register is accessed using one of the functions [`MRS`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-287-MRS?lang=en#isa_mrs), [`MSR (register)`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-289-MSR--register-?lang=en#isa_msr_reg), [`MSR (immediate)`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-288-MSR--immediate-?lang=en#isa_msr_imm), [`MRRS`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-286-MRRS?lang=en#isa_mrrs), or [`MSRR`](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-290-MSRR?lang=en#isa_msrr), using an encoding value.

The encoding value is associated with a mnemonic register name, which may not be the same as the name of the register. Tables listing all encodings, mnemonics and the register they access are found in [Table D23-1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D23-AArch64-System-Register-Encoding/-D23-2-Moves-to-and-from-debug-and-trace-System-registers/-D23-2-1-Instructions-for-accessing-debug-System-registers?lang=en#tbl_aarch64_register_encoding_table_mrsmsr_op010) and [Table D23-2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D23-AArch64-System-Register-Encoding/-D23-3-Moves-to-and-from-non-debug-System-registers--Special-purpose-registers/-D23-3-1-Instructions-for-accessing-non-debug-System-registers?lang=en#tbl_aarch64_register_encoding_table_mrsmsr_mrrsmsrr_op011).

Some registers can be accessed using multiple encodings.

For example:

- When virtualization is implemented, see [System and Special-purpose register redirection](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-13-Virtualization-Host-Extensions/-D8-13-2-System-and-Special-purpose-register-redirection?lang=en#mdsec_system_and_special_purpose_register_redirection).
- When there is an alias mnemonic, see [System and Special-purpose register aliasing](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-13-Virtualization-Host-Extensions/-D8-13-3-System-and-Special-purpose-register-aliasing?lang=en#mdsec_system_and_special_purpose_register_aliasing).
- When a mnemonic accesses a register in an array of registers, for example [PMXEVCNTR\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-5-Performance-Monitors-registers/-D24-5-26-PMXEVCNTR-EL0--Performance-Monitors-Selected-Event-Count-Register?lang=en#reg_aarch64_pmxevcntr_el0).

###### D24.1.1.2 Register arrays and names

Arrays of registers are indicated by an `<n>` or `<m>` in the title of the register. These are a shortcut for referencing a number of registers with identical field layout. The index letter is considered to be replaced by a number for each individual register in the array.

There are several different ways for a register in an array to be associated with an encoding:

- The same number of encodings as there are registers in the array. The mnemonic will include an index letter, which may not be the same as the register array index letter, and the encodings will be represented in terms of that index letter. For example, see [PMEVCNTR<n>](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-4-Performance-Monitors-registers/-G8-4-10-PMEVCNTR-n---Performance-Monitors-Event-Count-Registers--n---0---30?lang=en#reg_aarch32_pmevcntrn).
- One encoding for all registers in the array. Another register is used to select the register in the array to be accessed. For example, see [PMXEVCNTR\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-5-Performance-Monitors-registers/-D24-5-26-PMXEVCNTR-EL0--Performance-Monitors-Selected-Event-Count-Register?lang=en#reg_aarch64_pmxevcntr_el0).
- A group of encodings, used to access a subset of the register array, with another register used to select which bank of registers is accessed. For example, see [SPMEVCNTR<n>\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-5-Performance-Monitors-registers/-D24-5-39-SPMEVCNTR-n--EL0--System-Performance-Monitors-Event-Count-Register--n---0---63?lang=en#reg_aarch64_spmevcntrn_el0).

###### D24.1.1.3 Multiple conditions in register fields, resets or accessors

Throughout the register descriptions, conditions are used to represent changes of behavior. If multiple conditions apply to the same item, they are not necessarily mutually exclusive. The conditions are ordered so that the first true condition applies, and no further conditions are considered.

###### D24.1.1.4 Direct register access

In the pseudocode representing access to a particular encoding, direct access to a register is represented by a function using the same name as the register.

On a direct read, the architecturally visible value includes any field-level access controls or conditional read constraints on the value read from the register using the function.

On a direct write, any field-level access controls and constraints are applied to the value before it is written to the register using the function.

The accessibility pseudocode in the register description represents the traps and redirections for read and write accesses, and in most cases, the function to read or write the register is simple. In a few cases, there are more complex behaviors that would not be possible to represent on the register page, and these are documented in [A-profile Architecture Pseudocode](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode?lang=en#chap_pseudocode).
