# ​K5.4 Management registers and CoreSight compliance

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance>

#### K5.4 Management registers and CoreSight compliance

The CoreSight architecture requires the implementation of a set of management registers that occupy the memory map from `0xF00` upwards in each of the debug components.

CoreSight compliance and complete implementation of the management registers is OPTIONAL in some components:

- When [FEAT\_ED\_PIDR](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-1-The-Armv8-0-architecture-extension?lang=en#feat_feat_ed_pidr) is implemented, the external debug registers provide CoreSight compliance.
- When [FEAT\_PMU\_PIDR](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-1-The-Armv8-0-architecture-extension?lang=en#feat_feat_pmu_pidr) is implemented, the Performance Monitors registers provide CoreSight compliance.
- When [FEAT\_CTI\_PIDR](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-1-The-Armv8-0-architecture-extension?lang=en#feat_feat_cti_pidr) is implemented, the Cross-trigger interface registers provide CoreSight compliance.
- When [FEAT\_AMU\_PIDR](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-5-The-Armv8-4-architecture-extension?lang=en#feat_feat_amu_pidr) is implemented, the Activity Monitors registers provide CoreSight compliance.
- When [FEAT\_TRC\_EXT](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-1-The-Armv8-0-architecture-extension?lang=en#feat_feat_trc_ext) is implemented, the external registers for [FEAT\_ETE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-1-The-Armv9-0-architecture-extension?lang=en#feat_feat_ete) always provide CoreSight compliance.
- When [FEAT\_TRBE\_EXT](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-5-The-Armv9-4-architecture-extension?lang=en#feat_feat_trbe_ext) is implemented, the external registers for [FEAT\_TRBE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-1-The-Armv9-0-architecture-extension?lang=en#feat_feat_trbe) always provide CoreSight compliance.

Arm recommends that CoreSight compliance is implemented.

The CoreSight architecture specification recommends that any integration test registers are implemented starting from offset `0xEFC` downwards. Each of the debug components has an IMPLEMENTATION DEFINED region from `0xE80` to `0xEFC` for this purpose.
