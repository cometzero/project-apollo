# ​D1.3.1 EL1 System register alias names

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-3-System-register-locking/-D1-3-1-EL1-System-register-alias-names>

##### D1.3.1 EL1 System register alias names

I QBPYD
:   For each of the EL1 System registers in [Table D1-4](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-3-System-register-locking?lang=en#tbl_system_register_masks), [FEAT\_SRMASK](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_srmask) provides an *EL1 alias name*, <System\_register>ALIAS\_EL1. These are listed in [System and Special-purpose register aliasing](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-13-Virtualization-Host-Extensions/-D8-13-3-System-and-Special-purpose-register-aliasing?lang=en#mdsec_system_and_special_purpose_register_aliasing).

    - EL1 software that is aware of the presence of the EL1 alias names can use them when it is also aware that fine-grained traps are trapping EL1 writes to EL1 System registers.

    For each of the EL2 System registers in [Table D1-4](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D1-The-AArch64-System-Level-Programmers--Model/-D1-3-System-register-locking?lang=en#tbl_system_register_masks), [FEAT\_SRMASK](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_srmask) does not provide an EL2 alias name.

    - A kernel executing at EL2 is expected to use the EL1 alias names.

I CWCFN
:   The EL1 mask registers mask the EL1 alias names in addition to masking the corresponding EL1 System registers. For example, if [TCRMASK\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-196-TCRMASK-EL1--Translation-Control-Masking-Register--EL1-?lang=en#reg_aarch64_tcrmask_el1) is programmed to mask a [TCR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-193-TCR-EL1--Translation-Control-Register--EL1-?lang=en#reg_aarch64_tcr_el1) control field, then EL1 `MSR` writes to TCRALIAS\_EL1 do not update that masked field.

R CSSSN
:   `MSR` and `MRS` accesses to the EL1 alias names are direct accesses to the corresponding EL1 System registers. However, without explicit synchronization, the accesses might be reordered relative to `MSR` and `MRS` accesses to the EL1 System registers.

I VPCLQ
:   The accessibility from EL1 to each EL1 alias name is the same as for the corresponding EL1 System register, except for the opcode, and that there is a separate fine-grained trap control for each of reads and writes for the EL1 alias name:

    - [HFGRTR2\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-71-HFGRTR2-EL2--Hypervisor-Fine-Grained-Read-Trap-Register-2?lang=en#reg_aarch64_hfgrtr2_el2) contains the fine-grained trap control for EL1 reads.
    - [HFGWTR2\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-73-HFGWTR2-EL2--Hypervisor-Fine-Grained-Write-Trap-Register-2?lang=en#reg_aarch64_hfgwtr2_el2) contains the fine-grained trap control for EL1 writes.
