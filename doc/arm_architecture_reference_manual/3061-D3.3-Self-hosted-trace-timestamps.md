# ​D3.3 Self-hosted trace timestamps

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D3-AArch64-Self-hosted-Trace/-D3-3-Self-hosted-trace-timestamps>

#### D3.3 Self-hosted trace timestamps

The trace timestamp is a value that represents the passage of time in real-time. It is calculated from a counter which increments all the time, when the PE is generating trace and when the PE is in a prohibited region.

While self-hosted trace is [disabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D3-AArch64-Self-hosted-Trace/-D3-1-About-self-hosted-trace/-D3-1-2-Register-controls-to-enable-self-hosted-trace?lang=en#sh_trace_disabled), the external trace provides the trace timestamp. If the external trace is a standard CoreSight system, the relationship between CoreSight time and the Generic Timer counter is IMPLEMENTATION DEFINED.

When self-hosted trace is [enabled](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D3-AArch64-Self-hosted-Trace/-D3-1-About-self-hosted-trace/-D3-1-2-Register-controls-to-enable-self-hosted-trace?lang=en#sh_trace_enabled), the trace timestamp is one of the following:

- Physical time, which is defined by the physical count value returned by [`PhysicalCountInt`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-631-PhysicalCountInt?lang=en#asl_func_physicalcountint_0)`()`.
- If [FEAT\_ECV](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-7-The-Armv8-6-architecture-extension?lang=en#feat_feat_ecv) is implemented, offset physical time, which is defined as the value of [`PhysicalCountInt`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-631-PhysicalCountInt?lang=en#asl_func_physicalcountint_0)`()` minus a physical offset.

  If any of the following are true, the value of physical offset is zero:

  - EL3 is using AArch32.
  - EL2 is not implemented.
  - [FEAT\_ECV\_POFF](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-7-The-Armv8-6-architecture-extension?lang=en#feat_feat_ecv_poff) is not implemented.
  - The [Effective value](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#effective_value) of [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).{NSE, NS, RW} is {0, 1, 0}.
  - [CNTHCTL\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-2-CNTHCTL-EL2--Counter-timer-Hypervisor-Control-Register?lang=en#reg_aarch64_cnthctl_el2).ECV is 0.
  - EL3 is implemented and using AArch64, and [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).ECVEn is 0.

  Otherwise the value of physical offset is the value of [CNTPOFF\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-18-CNTPOFF-EL2--Counter-timer-Physical-Offset-Register?lang=en#reg_aarch64_cntpoff_el2).
- Virtual time, which is defined as the value of [`PhysicalCountInt`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-4-Shared-pseudocode/-J1-4-631-PhysicalCountInt?lang=en#asl_func_physicalcountint_0)`()` minus a virtual offset.

  If any of the following are true, the virtual offset is zero:

  - EL2 is not implemented.

  Otherwise, the virtual offset is always [CNTVOFF\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-27-CNTVOFF-EL2--Counter-timer-Virtual-Offset-Register?lang=en#reg_aarch64_cntvoff_el2), including when a read of [CNTVCT\_EL0](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-10-Generic-Timer-registers/-D24-10-26-CNTVCT-EL0--Counter-timer-Virtual-Count-Register?lang=en#reg_aarch64_cntvct_el0) at the current Exception level would treat the virtual offset as zero.

The following fields control which counter is used for self-hosted trace:

- [TRFCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-74-TRFCR-EL2--Trace-Filter-Control-Register--EL2-?lang=en#reg_aarch64_trfcr_el2).TS.
- [TRFCR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-4-Trace-registers/-D24-4-73-TRFCR-EL1--Trace-Filter-Control-Register--EL1-?lang=en#reg_aarch64_trfcr_el1).TS.
- [HTRFCR](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-33-HTRFCR--Hyp-Trace-Filter-Control-Register?lang=en#reg_aarch32_htrfcr).TS.
- [TRFCR](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-37-TRFCR--Trace-Filter-Control-Register?lang=en#reg_aarch32_trfcr).TS.

The timestamp used for trace is shown in [Table D3-2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D3-AArch64-Self-hosted-Trace/-D3-3-Self-hosted-trace-timestamps?lang=en#tbl_babfdaeg).
