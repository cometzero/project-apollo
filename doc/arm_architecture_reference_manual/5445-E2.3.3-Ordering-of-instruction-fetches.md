# ​E2.3.3 Ordering of instruction fetches

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-E-The-AArch32-Application-Level-Architecture/-Chapter-E2-The-AArch32-Application-Level-Memory-Model/-E2-3-Definition-of-the-memory-model/-E2-3-3-Ordering-of-instruction-fetches>

##### E2.3.3 Ordering of instruction fetches

For two memory locations A and B, if A has been written to with an updated value and been made coherent with the instruction fetches of the shareability domain before B has been written to with an updated value by an observer in the same shareability domain, then where, for an observer in the shareability domain, an instruction read from B appears in program order before an instruction fetched from A, if the instruction read from B contains the updated value of B then the instruction read from A appearing later in program order will contain the updated value of A.

A write has been made coherent with an instruction fetch of a shareability domain when:

[CTR](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-2-General-system-control-registers/-G8-2-37-CTR--Cache-Type-Register?lang=en#reg_aarch32_ctr).{DIC, IDC} == {0, 0}
:   The location written to has been cleaned to the [Point of unification (PoU)](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#babjcbhb) from the data cache, and that clean is complete for the shareability domain. Subsequently the location has been invalidated to the [Point of unification (PoU)](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#babjcbhb) from the instruction cache, and that invalidation is complete for the shareability domain.

[CTR](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-2-General-system-control-registers/-G8-2-37-CTR--Cache-Type-Register?lang=en#reg_aarch32_ctr).{DIC, IDC} == {0, 1}
:   The write is complete for the shareability domain. Subsequently the location has been invalidated to the [Point of unification (PoU)](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#babjcbhb) from the instruction cache, and that invalidation is complete for the shareability domain.

[CTR](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-2-General-system-control-registers/-G8-2-37-CTR--Cache-Type-Register?lang=en#reg_aarch32_ctr).{DIC, IDC} == {1, 1}
:   The write is complete for the shareability domain.

> #### Note
>
> Microarchitecturally, this means that these situations cannot both be true in an implementation:
>
> - After delays in fetching from memory, the instruction queue can have entries written into it out of order.
> - For an implementation:
>
>   - When [CTR](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-2-General-system-control-registers/-G8-2-37-CTR--Cache-Type-Register?lang=en#reg_aarch32_ctr).DIC == 0, if there is an outstanding entry in the instruction queue, then later entries in the instruction queue are not impacted by the [ICIMVAU](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-2-General-system-control-registers/-G8-2-82-ICIMVAU--Instruction-Cache-line-Invalidate-by-VA-to-PoU?lang=en#reg_aarch32_icimvau) instructions of a different core.
>   - When [CTR](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-2-General-system-control-registers/-G8-2-37-CTR--Cache-Type-Register?lang=en#reg_aarch32_ctr).DIC == 1, if there is a write to the location that is held in the queue when there is an outstanding entry in the instruction queue for an older entry, then the instruction queue does not have entries invalidated from it.
