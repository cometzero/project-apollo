# ​D21.8 PE-side Maximum bandwidth limit injection control

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-8-PE-side-Maximum-bandwidth-limit-injection-control>

#### D21.8 PE-side Maximum bandwidth limit injection control

I CBQCG
:   If [FEAT\_MPAM\_PE\_BW\_CTRL](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_mpam_pe_bw_ctrl) is implemented, software can use [MPAMBWn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpambwn_elx) registers to impose a maximum limit on the bandwidth that requests from the MPAM PE use.

R VQNTY
:   When [MPAMBWn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpambwn_elx).ENABLED is 1 and either of the following is true, MPAM PE requests to the memory system are stalled until the bandwidth the MPAM PE is using drops below the limit configured in [MPAMBWn\_ELx.MAX](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpambwn_elx):

    - [MPAMBWIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-10-MPAMBWIDR-EL1--MPAM-PE-side-Bandwidth-Controls-ID-Register?lang=en#reg_aarch64_mpambwidr_el1).MAX\_LIM is `0b00` or `0b10` and [MPAMBWn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpambwn_elx).HARDLIM is set.
    - [MPAMBWIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-10-MPAMBWIDR-EL1--MPAM-PE-side-Bandwidth-Controls-ID-Register?lang=en#reg_aarch64_mpambwidr_el1).MAX\_LIM is `0b00` or `0b01`, [MPAMBWn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpambwn_elx).HARDLIM is not set, and an IMPLEMENTATION DEFINED mechanism has determined the MPAM PE downstream resources to be saturated.

    Otherwise, MPAM PE requests to the memory system are sent unregulated.

R RGLDT
:   [MPAMBWSM\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-11-MPAMBWSM-EL1--MPAM-Streaming-Mode-Bandwidth-Control-Register--EL1-?lang=en#reg_aarch64_mpambwsm_el1).MAX is used instead of [MPAMBWn\_ELx.MAX](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpambwn_elx) when:

    - The MPAM PE is in streaming mode, and:

      - Accessing from SVE load/store/prefetch.
      - Accessing from SIMD&FP load/store.
    - Accessing from SME load/store.

I DPMDJ
:   If [MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).HAS\_HCR is 1, meaning that the MPAM virtualization option is implemented, and [FEAT\_MPAM\_PE\_BW\_CTRL](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-7-The-Armv9-6-architecture-extension?lang=en#feat_feat_mpam_pe_bw_ctrl) is implemented, EL2 software can use [MPAMBWCAP\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-9-MPAMBWCAP-EL2--MPAM-PE-side-Maximum-Bandwidth-Limit-Virtualization-Register?lang=en#reg_aarch64_mpambwcap_el2) to cap a maximum bandwidth limit assigned by EL1&0 software.

R CMMQR
:   When [MPAMBWCAP\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-9-MPAMBWCAP-EL2--MPAM-PE-side-Maximum-Bandwidth-Limit-Virtualization-Register?lang=en#reg_aarch64_mpambwcap_el2).ENABLED is 1, EL1&0 requests to the memory system are regulated based on the limit calculated as MIN([MPAMBWCAP\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-9-MPAMBWCAP-EL2--MPAM-PE-side-Maximum-Bandwidth-Limit-Virtualization-Register?lang=en#reg_aarch64_mpambwcap_el2).CAP, MPAMx\_BW\_CTRL\_EL.MAX) and MIN([MPAMBWCAP\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-9-MPAMBWCAP-EL2--MPAM-PE-side-Maximum-Bandwidth-Limit-Virtualization-Register?lang=en#reg_aarch64_mpambwcap_el2).CAP, [MPAMBWSM\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-11-MPAMBWSM-EL1--MPAM-Streaming-Mode-Bandwidth-Control-Register--EL1-?lang=en#reg_aarch64_mpambwsm_el1).MAX).

I VVYKT
:   If {[MPAMBWn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpambwn_elx), [MPAMBWSM\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-11-MPAMBWSM-EL1--MPAM-Streaming-Mode-Bandwidth-Control-Register--EL1-?lang=en#reg_aarch64_mpambwsm_el1), [MPAMBWCAP\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-9-MPAMBWCAP-EL2--MPAM-PE-side-Maximum-Bandwidth-Limit-Virtualization-Register?lang=en#reg_aarch64_mpambwcap_el2)}.HW\_SCALE\_ENABLE is 1, then hardware is permitted to scale down the maximum limit configured in {[MPAMBWn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpambwn_elx), [MPAMBWSM\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-11-MPAMBWSM-EL1--MPAM-Streaming-Mode-Bandwidth-Control-Register--EL1-?lang=en#reg_aarch64_mpambwsm_el1)}.MAX or [MPAMBWCAP\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-9-MPAMBWCAP-EL2--MPAM-PE-side-Maximum-Bandwidth-Limit-Virtualization-Register?lang=en#reg_aarch64_mpambwcap_el2).CAP according to the number of PEs in a group that are all issuing the same specific PARTID\_D or PARTID\_I at the corresponding exception level.

R CRGFM
:   It is IMPLEMENTATION DEFINED how hardware determines the number of PEs that are all issuing the same specific PARTID\_D or PARTID\_I at any point in time.

I FYXGY
:   Memory bandwidth regulation relies on tracking bandwidth use by PARTIDs. Bandwidth measurements have a dependence on time, and that dependence is referred to as the *accounting window*. The accounting window tracks bandwidth use over a period of time.

R FZMPQ
:   The PE-side maximum bandwidth limit accounting window scheme and its software-discoverability are IMPLEMENTATION DEFINED.
