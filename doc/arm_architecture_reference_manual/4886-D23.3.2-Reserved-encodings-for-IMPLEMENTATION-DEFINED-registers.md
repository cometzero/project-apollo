# ​D23.3.2 Reserved encodings for IMPLEMENTATION DEFINED registers

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D23-AArch64-System-Register-Encoding/-D23-3-Moves-to-and-from-non-debug-System-registers--Special-purpose-registers/-D23-3-2-Reserved-encodings-for-IMPLEMENTATION-DEFINED-registers>

##### D23.3.2 Reserved encodings for IMPLEMENTATION DEFINED registers

The System register encoding space with `op0` == `0b11` reserves the following encodings for IMPLEMENTATION DEFINED registers:

![](images/4886-D23.3.2-Reserved-encodings-for-IMPLEMENTATION-DEFINED-registers-img01.svg)

The value of `L` defines the access type and the use of `Rt` as follows:

0
:   Write the value in `Rt` to the IMPLEMENTATION DEFINED register.

1
:   Read the value of the IMPLEMENTATION DEFINED register to `Rt`.

For more information about these encodings, see
[S3\_<op1>\_<Cn>\_<Cm>\_<op2>, IMPLEMENTATION DEFINED Registers](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-167-S3--op1---Cn---Cm---op2---IMPLEMENTATION-DEFINED-Registers?lang=en#reg_aarch64_s3_op1_cn_cm_op2).

As that section describes, any IMPLEMENTATION DEFINED registers are accessed in a similar way to architecturally-defined System registers, using `MRS`, `MRRS`, `MSR`, and `MSRR` instructions, see:

- [MRS](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-287-MRS?lang=en#isa_mrs).
- [MRRS](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-286-MRRS?lang=en#isa_mrrs).
- [MSR (immediate)](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-288-MSR--immediate-?lang=en#isa_msr_imm).
- [MSR (register)](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-289-MSR--register-?lang=en#isa_msr_reg).
- [MSRR](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-290-MSRR?lang=en#isa_msrr).

Accesses to these registers that are not trapped are permitted to be UNDEFINED. Arm recommends that IMPLEMENTATION DEFINED registers that are not UNDEFINED follow the principles in [Principles of the System instruction class encoding](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C5-The-A64-System-Instruction-Class/-C5-1-The-System-instruction-class-encoding-space/-C5-1-1-Principles-of-the-System-instruction-class-encoding?lang=en#babbicci).

The Arm architecture guarantees not to define any register name prefixed with *IMP\_* as part of the standard Arm architecture.

> #### Note
>
> Arm strongly recommends that any register names created in the IMPLEMENTATION DEFINED register spaces be prefixed with *IMP\_* and postfixed with *\_ELx*, where appropriate.
