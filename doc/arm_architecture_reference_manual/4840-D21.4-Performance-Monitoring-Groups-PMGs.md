# ​D21.4 Performance Monitoring Groups (PMGs)

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-4-Performance-Monitoring-Groups--PMGs->

#### D21.4 Performance Monitoring Groups (PMGs)

I NQQHK
:   An MPAM resource monitor measures how much of a shared partitionable resource a software execution environment is using. See [Memory system resource usage monitoring](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-1-About-MPAM/-D21-1-4-Memory-system-resource-usage-monitoring?lang=en#mpam_memory_system_resource_usage_monitoring). A *Performance Monitoring Group (PMG)* is an identifier used in the filter register of a monitor, MSMON\_CFG\_MBWU\_FLT or MSMON\_CFG\_CSU\_FLT.

    Filtering by PMG provides a way to group measurements, and a way to subdivide measurements. For example:

    - Multiple monitors, each measuring usage of a different shared resource, can be made sensitive to a single PMG and no PARTIDs, so that they create a group of measurements for usage of the different shared resources by one PMG value.
    - Monitors can be made sensitive to both a PARTID and a PMG, so that the PMG provides a subdivision of what is measured for the PARTID.

R BVQFD
:   The PMG that an MPAM PE Requester sends as part of an [MPAM information bundle](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-1-About-MPAM/-D21-1-2-MPAM-information-bundles?lang=en#mpam_mpam_information_bundles) is one of:

    - If any of the conditions for the [the Default PMG](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-4-Performance-Monitoring-Groups--PMGs-/-D21-4-2-The-Default-PMG?lang=en#mpam_default_pmg) are met, the Default PMG.
    - Otherwise, the PMG is determined as follows:

      - For an instruction fetch, [MPAMn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpamn_elx).PMG\_I is used.
      - For a data access, [MPAMn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpamn_elx).PMG\_D is used. However, if a data access is due to the execution of an SME load or store instruction, or of a [Streaming SVE mode](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B1-The-AArch64-Application-Level-Programmers--Model/-B1-4-The-Scalable-Vector-and-Scalable-Matrix-Extensions--SVE---SME-/-B1-4-6-Streaming-SVE-mode?lang=en#beigieigd1) load or store instruction, [MPAMSM\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-14-MPAMSM-EL1--MPAM-Streaming-Mode-Register?lang=en#reg_aarch64_mpamsm_el1).PMG\_D is used instead.

      Also see [Behavior when a PMG is out-of-range](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D21-MPAM-PE-Architecture/-D21-9-MPAM-errors/-D21-9-3-Behavior-when-a-PMG-is-out-of-range?lang=en#mpam_behavior_when_pmg_out_of_range).

I JYNXW
:   Software can set [MPAMn\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#mpamn_elx).{PMG\_D, PMG\_I} to the same or different PMG values.
