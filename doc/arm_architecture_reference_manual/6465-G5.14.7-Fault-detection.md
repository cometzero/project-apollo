##### G5.14.7 Fault detection

As soon as translation is invoked, a reserve FaultRecord accompanies the process, capturing the stage and level of translation as it proceeds. When a fault is detected, it is reflected in the FaultRecord and reported back as the result of translation with the most recent state to be reported already captured within. The following functions detect a certain type of fault, their outputs are all boolean with a TRUE value on detection:

- [`AArch32_S1LDHasPermissionsFault`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-192-AArch32-S1LDHasPermissionsFault?lang=en#asl_func_aarch32_s1ldhaspermissionsfault_6)`()` and [`AArch32_S2HasPermissionsFault`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-195-AArch32-S2HasPermissionsFault?lang=en#asl_func_aarch32_s2haspermissionsfault_4)`()` detect a permissions fault for stage 1 and stage 2 respectively for Long-descriptor format. [`AArch32_S1SDHasPermissionsFault`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-193-AArch32-S1SDHasPermissionsFault?lang=en#asl_func_aarch32_s1sdhaspermissionsfault_5)`()` detects a permissions fault for a translation in Short-descriptor format. Note that for atomic instructions introduced by [FEAT\_LSE](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-2-The-Armv8-1-architecture-extension?lang=en#feat_feat_lse), these functions are called twice, once to check for read permissions and another for write allowing the correct failure to be reported.
- [`AArch32_S1HasAlignmentFaultDueToMemType`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-191-AArch32-S1HasAlignmentFaultDueToMemType?lang=en#asl_func_aarch32_s1hasalignmentfaultduetomemtype_4)`()` and [`AArch32_S2HasAlignmentFaultDueToMemType`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-194-AArch32-S2HasAlignmentFaultDueToMemType?lang=en#asl_func_aarch32_s2hasalignmentfaultduetomemtype_3)`()` detect an alignment fault for stage 1 and stage 2 respectively.
- [`AArch32_S2InconsistentSL`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-196-AArch32-S2InconsistentSL?lang=en#asl_func_aarch32_s2inconsistentsl_1)`()` detects a stage 2 translation fault caused by erroneous configuration of the VTCR.SL0 field.
- [`AArch32_VAIsOutOfRange`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-197-AArch32-VAIsOutOfRange?lang=en#asl_func_aarch32_vaisoutofrange_3)`()` detects a stage 1 translation fault caused by virtual addresses larger than the address input size configured. Similarly, [`AArch32_IPAIsOutOfRange`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-190-AArch32-IPAIsOutOfRange?lang=en#asl_func_aarch32_ipaisoutofrange_2)`()` detects a stage 2 translation fault caused by the output of stage 1 being larger than the configured input size for stage 2. Both are solely part of Long-descriptor format translation.

> #### Note
>
> Domain faults are detected inline as part of [`AArch32_S1TranslateSD`](/documentation/ddi0487/mc/-Part-J-Architectural-Pseudocode/-Chapter-J1-A-profile-Architecture-Pseudocode/-J1-3-Pseudocode-for-AArch32-operation/-J1-3-209-AArch32-S1TranslateSD?lang=en#asl_func_aarch32_s1translatesd_5)`()` since they are a simple equality check.
