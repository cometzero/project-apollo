# ​K5.4.5 About the Component Identification scheme

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-5-About-the-Component-Identification-scheme>

##### K5.4.5 About the Component Identification scheme

The Component Identification Registers identify the processor as an Arm Debug Interface v5 component. For more information, see the *Arm® Debug Interface Architecture Specification* and the *Arm® CoreSight™ Architecture Specification*.

The Component Identification Registers indicate whether the component implements the Peripheral Identification registers and provides compliance with the CoreSight architecture. Where implementation of these registers is OPTIONAL and all Component Identification registers are RAZ, the Peripheral Identification registers for the component behave as RES0. Otherwise, the Component Identification registers return a nonzero value on a read, according to the definition of those registers, and the Peripheral Identification registers are implemented. [Management registers and CoreSight compliance](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance?lang=en#cihcdhda) provides further detail on where these registers are OPTIONAL.

The Component Identification Registers occupy the last four words of the 4KB block of debug registers.
