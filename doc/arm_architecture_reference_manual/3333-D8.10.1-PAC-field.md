# ​D8.10.1 PAC field

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-10-Pointer-authentication/-D8-10-1-PAC-field>

##### D8.10.1 PAC field

I KQZPC
:   The pointer authentication mechanism treats the upper bits of a pointer in a 64-bit general-purpose register as a PAC field.

I BSXBR
:   The [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).{T0SZ, T1SZ} fields are used to configure the size and location of the PAC field.

R FWYCF
:   If [FEAT\_CONSTPACFIELD](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_constpacfield) is not implemented, when a 64-bit general-purpose register, Xd, holds an address with a PAC field, the location of the PAC field is determined by all of the following:

    - The `bottom_PAC_bit` is 64-[TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ, and the value of *n* is determined as follows:

      - If inserting a PAC into an address and address tagging is not used, then the value of Xd[63] is the value of *n*.
      - Otherwise, the value of Xd[55] is the value of *n*.
    - If address tagging is used, then all of the following apply:

      - If `bottom_PAC_bit` is > 52 and the stage 1 translation supports a single VA range, then the PAC field is Xd[55:`bottom_PAC_bit`].
      - Otherwise, the PAC field is Xd[54:`bottom_PAC_bit`].
    - If address tagging is not used and logical address tagging is used, then all of the following apply:

      - If `bottom_PAC_bit` is > 52 and the stage 1 translation supports a single VA range, then the PAC field is Xd[63:60, 55:`bottom_PAC_bit`].
      - Otherwise, the PAC field is Xd[63:60, 54:`bottom_PAC_bit`].
    - If both address tagging and logical address tagging are not used, then all of the following apply:

      - If `bottom_PAC_bit` is > 52 and the stage 1 translation supports a single VA range, then the PAC field is Xd[63:`bottom_PAC_bit`].
      - Otherwise, the PAC field is Xd[63:56, 54:`bottom_PAC_bit`].

    For more information, see [Address tagging](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-8-Address-tagging?lang=en#mdsec_address_tagging) and [Logical Address Tagging](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-9-Logical-Address-Tagging?lang=en#mdsec_mte_tagging).

    > #### Note
    >
    > A [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ value less than 12 requires implementation of [FEAT\_LVA3](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-5-The-Armv9-4-architecture-extension?lang=en#feat_feat_lva3).
    >
    > If [FEAT\_LVA3](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-3-Armv9-A-architecture-extensions/-A2-3-5-The-Armv9-4-architecture-extension?lang=en#feat_feat_lva3) is implemented, and address tagging or logical address tagging are enabled, pointer authentication might provide software with little to no benefit due to the reduced PAC field size.

R XTGWV
:   If [FEAT\_CONSTPACFIELD](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_constpacfield) is implemented, when a 64-bit general-purpose register, Xd, holds an address, the location of the PAC field is determined by all of the following:

    - The `bottom_PAC_bit` is 64-[TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ.
    - The value of Xd[55] is the value of *n* used in T*n*SZ.
    - If address tagging is used, then all of the following apply:

      - If `bottom_PAC_bit` is > 52 and the stage 1 translation supports a single VA range, then the PAC field is Xd[55:`bottom_PAC_bit`].
      - Otherwise, the PAC field is Xd[54:`bottom_PAC_bit`].
    - If address tagging is not used and logical address tagging is used, then all of the following apply:

      - If `bottom_PAC_bit` is > 52 and the stage 1 translation supports a single VA range, then the PAC field is Xd[63:60, 55:`bottom_PAC_bit`].
      - Otherwise, the PAC field is Xd[63:60, 54:`bottom_PAC_bit`].
    - If both address tagging and logical address tagging are not used, then all of the following apply:

      - If `bottom_PAC_bit` is > 52 and the stage 1 translation supports a single VA range, then the PAC field is Xd[63:`bottom_PAC_bit`].
      - Otherwise, the PAC field is Xd[63:56, 54:`bottom_PAC_bit`].

R NQZWG
:   If [FEAT\_CONSTPACFIELD](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_constpacfield) is implemented, then an implementation is permitted to use the value in Xd[55] to determine the size of the PAC field when adding a PAC to Xd, even when address tagging is not used.

I VZRCW
:   In the case where address tagging is not used, then any use of a VA that has differing values of bit [63] and bit [55] is a non-canonical VA that will generate a fault. For this reason, the presence or absence of [FEAT\_CONSTPACFIELD](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_constpacfield) does not affect the use of pointer authentication when inserting a PAC into a canonical VA.

I HLQVM
:   If the [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).TBID{*n*} bit is used to restrict address tagging to data addresses, then instruction addresses can use Xd[63:56] bits to produce larger pointer authentication code fields.

I DJNGK
:   For all of the following reasons, if [FEAT\_PAuth2](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_pauth2) is implemented, [FEAT\_FPAC](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_fpac) is not implemented, and stage 1 translation is disabled, then Arm recommends not setting the [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ values to indicate an address range that is smaller than the PA size:

    - For some PAC values, if [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ is set to indicate an address range that is smaller than the PA size, the address generated by a failed PAC authentication might be an address within the PA size because the upper address bits, those between the PA size and the size indicated by the [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ field, are taken from the result of the authentication process.
    - Accessing memory using such an address that has failed PAC authentication does not generate an Address size fault.
    - The memory access is done using upper address bits, those between the PA size and the size indicated by the [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ field, taken from the result of the authentication process.

R VMZGK
:   If the value in [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ is outside the permitted range, then one of the following CONSTRAINED UNPREDICTABLE results occur:

    - The [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ value configures the `bottom_PAC_bit` value.
    - The minimum permitted [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ value configures the `bottom_PAC_bit` value.
    - The maximum permitted [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ value configures the `bottom_PAC_bit` value.

R FCMCH
:   If a PE treats an out of range [TCR\_ELx](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K14-Registers-Index/-K14-1-Introduction-and-register-disambiguation/-K14-1-2-Register-name-disambiguation-by-Exception-level?lang=en#tcr_elx).T*n*SZ value as the maximum permitted field value or the minimum permitted field value for all purposes except reading the field value, then that behavior also applies to determining `bottom_PAC_bit`.
