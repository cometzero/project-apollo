# ​H9.2.38 EDPIDR1, External Debug Peripheral Identification Register 1

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-38-EDPIDR1--External-Debug-Peripheral-Identification-Register-1>

##### H9.2.38 EDPIDR1, External Debug Peripheral Identification Register 1

The EDPIDR1 characteristics are:

Purpose
:   Provides information to identify an external debug component.

    For more information, see [‘About the Peripheral identification scheme’](/documentation/ddi0487/mc/-Part-K-Appendixes/-Appendix-K5-Recommended-External-Debug-Interface/-K5-4-Management-registers-and-CoreSight-compliance/-K5-4-4-About-the-Peripheral-identification-scheme?lang=en#babdfhah).

Configuration
:   When FEAT\_DoPD is implemented, EDPIDR1 is in the Core power domain. Otherwise, EDPIDR1 is in the Debug power domain

    This register is present only when FEAT\_ED\_PIDR is implemented. Otherwise, direct accesses to EDPIDR1 are RES0.

Attributes
:   EDPIDR1 is a 32-bit register.

###### Field descriptions

![](images/6988-H9.2.38-EDPIDR1-External-Debug-Peripheral-Identification-Register-1-img01.svg)

Bits [31:8]
:   Reserved, RES0.

DES\_0, bits [7:4]
:   Designer, JEP106 identification code, bits [3:0].

    The JEP106 identification and continuation codes are stored as follows:

    - [EDPIDR1](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-38-EDPIDR1--External-Debug-Peripheral-Identification-Register-1?lang=en#reg_ext_edpidr1).DES\_0: JEP106 identification code bits[3:0].
    - [EDPIDR2](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-39-EDPIDR2--External-Debug-Peripheral-Identification-Register-2?lang=en#reg_ext_edpidr2).DES\_1: JEP106 identification code bits[6:4].
    - [EDPIDR4](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-41-EDPIDR4--External-Debug-Peripheral-Identification-Register-4?lang=en#reg_ext_edpidr4).DES\_2: JEP106 continuation code.

    These codes indicate the designer of the component and not the implementer, except where the two are the same. To obtain a number, or to see the assignment of these codes, contact JEDEC http://www.jedec.org.

    A JEP106 identification and continuation code takes the following form:

    - A sequence of zero or more numbers, all having the value `0x7F`.
    - A following 8-bit number, that is not `0x7F`, and where bit[7] is an odd parity bit.

    The parity bit in the JEP106 identification code is not included.

    > #### Note
    >
    > For example, Arm Limited is assigned the code `0x7F` `0x7F` `0x7F` `0x7F` `0x3B`.
    >
    > - The continuation code is the number of times `0x7F` appears before the final number. For example, a component designed by Arm Limited has the code `0x4`.
    > - The identification code is bits[6:0] of the final number. For example, a component designed by Arm Limited has the code `0x3B`.

    This field has an IMPLEMENTATION DEFINED value.

    Access to this field is RO.

PART\_1, bits [3:0]
:   Part number, which is selected by the designer of the component and stored as follows:

    - For a component with a 12-bit part number:
      - [EDPIDR1](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-38-EDPIDR1--External-Debug-Peripheral-Identification-Register-1?lang=en#reg_ext_edpidr1).PART\_1 contains part number bits [11:8].
      - [EDPIDR0](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-37-EDPIDR0--External-Debug-Peripheral-Identification-Register-0?lang=en#reg_ext_edpidr0).PART\_0 contains part number bits [7:0].
    - For a component with a 16-bit part number:
      - [EDPIDR1](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-38-EDPIDR1--External-Debug-Peripheral-Identification-Register-1?lang=en#reg_ext_edpidr1).PART\_1 contains part number bits [15:12].
      - [EDPIDR0](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-37-EDPIDR0--External-Debug-Peripheral-Identification-Register-0?lang=en#reg_ext_edpidr0).PART\_0 contains part number bits [11:4].
      - [EDPIDR2](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-39-EDPIDR2--External-Debug-Peripheral-Identification-Register-2?lang=en#reg_ext_edpidr2).REVISION contains part number bits [3:0].

    When a 12-bit part number is used, [EDPIDR2](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H9-External-Debug-Register-Descriptions/-H9-2-External-debug-registers/-H9-2-39-EDPIDR2--External-Debug-Peripheral-Identification-Register-2?lang=en#reg_ext_edpidr2).REVISION indicates revision information.

    The choice of using a 12-bit part number or 16-bit part number is specific to the designer of the component.

    This field has an IMPLEMENTATION DEFINED value.

    Access to this field is RO.
