##### D17.6.6 Additional information for each profiled SVE and SME operation

I CKWPL
:   When [FEAT\_SPEv1p1](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-4-The-Armv8-3-architecture-extension?lang=en#feat_feat_spev1p1) is implemented, SVE and SME operations are sampled as described in this section.

D WRNLK
:   This section uses the following terms:

    Maximum implemented SVE vector length
    :   - The *Maximum implemented Streaming SVE vector length* means the implemented width of the SVE scalable vector registers in Streaming SVE mode.
        - The *Maximum implemented Non-streaming SVE vector length* means the implemented width of the SVE scalable vector registers in Non-streaming SVE mode.

        See [Maximum implemented SVE vector lengths](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B1-The-AArch64-Application-Level-Programmers--Model/-B1-4-The-Scalable-Vector-and-Scalable-Matrix-Extensions--SVE---SME-/-B1-4-1-Maximum-implemented-SVE-vector-lengths?lang=en#beiceffjj1).

    Effective SVE vector length (VL)
    :   Means the current SVE vector length, `SVL` or `NSVL`:

        - The *Effective Streaming SVE vector length (SVL)* is less than or equal to the [Maximum implemented Streaming SVE vector length](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacdjebd).
        - The *Effective Non-streaming SVE vector length (NSVL)* is less than or equal to the [Maximum implemented Non-streaming SVE vector length](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacdjebd).

        See [Configurable SVE vector lengths](/documentation/ddi0487/mc/-Part-B-The-AArch64-Application-Level-Architecture/-Chapter-B1-The-AArch64-Application-Level-Programmers--Model/-B1-4-The-Scalable-Vector-and-Scalable-Matrix-Extensions--SVE---SME-/-B1-4-2-Configurable-SVE-vector-lengths?lang=en#beijgdghi3).

    Effective tile size
    :   Means the tile size of the current instruction, determined by `SVL` and the element size used by the instruction. The Effective tile size is less than or equal to the square of the [Maximum implemented Streaming SVE vector length](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacdjebd), divided by the element size.

    Sampled SVE SIMD operation
    :   Means a sampled operation that reads from or writes to the SVE vector or predicate registers but not the SME ZA storage, and that is not a non-SIMD SVE instruction or operation. This includes instructions with scalar inputs or outputs. Non-SIMD SVE instructions are defined by [Definition of terms](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D14-PMU-Event-Descriptions/-D14-1-Definitions/-D14-1-1-Definition-of-terms?lang=en#babfgcgh). For example, the following instructions are in this category:

        - `ADD Z0.S, P7/M, Z0.S, Z1.S`.
        - `FMLALB Z2.S, Z3.H, Z4.H`.
        - `TBL Z5.H, { Z6.H }, Z7.H`.
        - `LASTA W0, P6, Z8.S`.
        - `LUTI4 {Z8.H-Z9.H}, ZT0, Z10[2]`.
        - `FMAX {Z0.H-Z1.H}, {Z2.H-Z3.H}, {Z4.H-Z5.H}`.

    Sampled SME vector SIMD operation
    :   Means a sampled operation reading from or writing to SME ZA array vectors or tile slices, which is not reading from or writing to a 2D ZA tile. For example, the following instructions are in this category:

        - `ADD ZA.S[W8, 3, VGx2], {Z0.S-Z1.S}, {Z2.S-Z3.S}`.
        - `FMLAL ZA.S[W9, 4:5, VGx4], {Z4.H-Z7.H}, {Z8.H-Z11.H}`.
        - `MOVA Z11.S, P3/M, ZA0H.S[W12,1]`.
        - `LD1W {ZA1V.S[W13,0]}, P4/Z, [X1,X2,LSL 2]`.

    Sampled SME tile SIMD operation
    :   Means a sampled operation reading from or writing to a 2D ZA tile or multiple ZA tiles. For example, the following instructions are in this category:

        - `SMOPA ZA0.S, P0/M, P1/M, Z2.B, Z3.B`.
        - `ZERO {ZA1.H}`.

    Sampled effective vector length
    :   Means the length in bits of the vector or vectors operated on by a [Sampled SVE SIMD operation](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#caccgfdfe0) or a [Sampled SME vector SIMD operation](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cachfgggb0). That is, the number of elements in the vector multiplied by the element size.

        In cases where the Sampled effective vector length for the input operands of the sampled operation and the Sampled effective vector length for the output operand of the sampled operation differ, the Sampled effective vector length of the output operand is used.

        For a [Sampled SVE SIMD operation](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#caccgfdfe0) or a [Sampled SME vector SIMD operation](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cachfgggb0) which reads or writes only SVE predicate registers, the Sampled effective vector length is:

        - The length in bits of the predicate operated on multiplied by 8, when predicate-as-mask encoding is used.
        - The [VL](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacbccjfh0), when predicate-as-counter encoding is used.

    Sampled effective tile size
    :   Means the size in bits of the ZA tile or tiles operated on by a [Sampled SME tile SIMD operation](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacjhdibd0). That is, the number of elements in the ZA tile or tiles multiplied by the element size.

    Sampled predicated operation
    :   Means a [Sampled SVE SIMD operation](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#caccgfdfe0), [Sampled SME vector SIMD operation](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cachfgggb0), or [Sampled SME tile SIMD operation](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacjhdibd0) that is one of:

        - An operation that writes to one or more SVE scalable vector registers or ZA tile slices under a Governing predicate or predicates using either zeroing or merging predication.
        - A predicated store of a one or more SVE scalable vector registers or ZA tile slices.

        For an implementation that samples micro-operations, an SVE or SME instruction might be split up into one or more micro-operations, some of which are predicated and some of which are not predicated.

> #### Note
>
> [Sampled predicated operation](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacedadi) excludes operations that do not write a vector register, or do so but not using zeroing or merging predication, and applies to machine instructions rather than aliases. For example, the following instructions are not predicated SVE instructions under this definition:
>
> - `CNTP`, `LASTA`, and `PTRUE` do not write to vector registers.
> - `FADDV` and `SMAXV` write scalar values to SIMD&FP registers.
> - `COMPACT` and `SEL` (vectors) write to vector registers, and have a predicate operand, but do not use that predicate as a Governing predicate for zeroing or merging predication.
> - `MOV` (vector, predicated) appears to be a predicated SVE instruction because it specifies merging predication through the `<PG>/M` operand, but it is actually an alias for the `SEL` (vectors) instruction. However, `MOV` (scalar, predicated) is an alias for the predicated SVE instruction, `CPY` (scalar).

I XYGNN
:   In some implementations, a SIMD instruction might be split into one or more micro-operations, each operating on only a part of the vector or tile specified by the instruction. When such an operation is sampled by the Statistical Profiling Unit (SPU), the [Sampled effective vector length](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacdachi) or [Sampled effective tile size](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#sampled_effective_tile_size) might be smaller than the Effective vector length or Effective tile size specified by `SVL` or `NSVL`.

    Furthermore, some instructions might not affect the whole vector or tile specified by the instruction. For example, a predicated operation or an instruction such as `ZERO` (tiles) that specifies a mask in the instruction. This might affect how an individual micro-operation functions, and, for an implementation that samples operations, how the micro-operation is described by the SPU when sampled.

    > Example D17-4 Vector length
    >
    > To support a vector length of 1024 bits, an implementation might split all instructions into four micro-operations on 256-bit vector paths. The implementation must, however, implement 1024-bit wide vector registers.
    >
    > This behavior might vary based on operation type. For example, an implementation that has a full-width data-path for most operations might choose to break certain complex operations, such as non-contiguous load or stores, into shorter vectors.

    > Example D17-5 Effective SVE vector length less-than the Maximum implemented
    >
    > To support an [Effective SVE vector length](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacbccjfh0) less-than the [Maximum implemented SVE vector length](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacdjebd), an implementation might choose to execute all operations at the [Maximum implemented SVE vector length](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacdjebd) and discard the results above the [Effective SVE vector length](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacbccjfh0). Discarded results, arising from difference between [Maximum implemented SVE vector length](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacdjebd) and [Effective vector length](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacbccjfh0), do not form part of the sampled operation and the [Sampled effective SVE vector length](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacdachi) does not include any discarded portions of the vector.
    >
    > Results discarded because of predication are part of the sampled operation.

This includes SIMD load and store operations.

    For example, when all of the following are true, a sampled micro-op generated by a SIMD SVE instruction might be recorded as a sampled Advanced SIMD operation:

    - The [Sampled effective vector length](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-6-Additional-information-for-each-profiled-SVE-and-SME-operation?lang=en#cacdachi) is 128 bits.
    - The operation is unpredicated, and does not have a predicate register as an input or output.
    - The operation has an equivalent Advanced SIMD operation.

    This might be because the properties of the instruction are not preserved in the micro-ops after the instruction has been decoded, and so the PE cannot determine the classification of the original instruction at the point where an operation is sampled.

    Arm recommends that a SIMD micro-op is sampled as a type appropriate for the SIMD instruction which generated the micro-op. See also [Information collected for micro-ops](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D17-The-Statistical-Profiling-Extension/-D17-6-The-profiling-data/-D17-6-2-Information-collected-for-micro-ops?lang=en#babdcifjd6).
