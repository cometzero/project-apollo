# ​D24.12.21 MPAMVPM6_EL2, MPAM Virtual PARTID Mapping Register 6

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-21-MPAMVPM6-EL2--MPAM-Virtual-PARTID-Mapping-Register-6>

##### D24.12.21 MPAMVPM6\_EL2, MPAM Virtual PARTID Mapping Register 6

The MPAMVPM6\_EL2 characteristics are:

Purpose
:   MPAMVPM6\_EL2 provides mappings from virtual PARTIDs 24 - 27 to physical PARTIDs.

    [MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).VPMR\_MAX field gives the index of the highest implemented MPAMVPM<n>\_EL2 registers. VPMR\_MAX can be as large as 7 (8 registers) or 32 virtual PARTIDs. If [MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).VPMR\_MAX == 0, there is only a single MPAMVPM<n>\_EL2 register, [MPAMVPM0\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-15-MPAMVPM0-EL2--MPAM-Virtual-PARTID-Mapping-Register-0?lang=en#reg_aarch64_mpamvpm0_el2).

    Virtual PARTID mapping is enabled by [MPAMHCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-12-MPAMHCR-EL2--MPAM-Hypervisor-Control-Register--EL2-?lang=en#reg_aarch64_mpamhcr_el2).EL1\_VPMEN for the PARTID in [MPAM1\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-2-MPAM1-EL1--MPAM1-Register--EL1-?lang=en#reg_aarch64_mpam1_el1) and by [MPAMHCR\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-12-MPAMHCR-EL2--MPAM-Hypervisor-Control-Register--EL2-?lang=en#reg_aarch64_mpamhcr_el2).EL0\_VPMEN for the PARTID in [MPAM0\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-1-MPAM0-EL1--MPAM0-Register--EL1-?lang=en#reg_aarch64_mpam0_el1).

    A virtual-to-physical PARTID mapping entry, PhyPARTID<n>, is valid only when the [MPAMVPMV\_EL2](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-23-MPAMVPMV-EL2--MPAM-Virtual-Partition-Mapping-Valid-Register?lang=en#reg_aarch64_mpamvpmv_el2).VPM\_V bit in bit position n is set to 1.

Configuration
:   This register has no effect if EL2 is not enabled in the current Security state.

    This register is present only when (((IsFeatureImplemented(FEAT\_MPAMv0p1) || IsFeatureImplemented(FEAT\_MPAMv1p0)) && IsFeatureImplemented(FEAT\_AA64EL2)) && ([MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).HAS\_HCR == ‘1’)) && (UInt([MPAMIDR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-12-MPAM-registers/-D24-12-13-MPAMIDR-EL1--MPAM-ID-Register--EL1-?lang=en#reg_aarch64_mpamidr_el1).VPMR\_MAX) > 5). Otherwise, direct accesses to MPAMVPM6\_EL2 are UNDEFINED.

Attributes
:   MPAMVPM6\_EL2 is a 64-bit register.

###### Field descriptions

![](images/5405-D24.12.21-MPAMVPM6_EL2-MPAM-Virtual-PARTID-Mapping-Register-6-img01.svg)

PhyPARTID27, bits [63:48]
:   Virtual PARTID Mapping Entry for virtual PARTID 27. PhyPARTID27 gives the mapping of virtual PARTID 27 to a physical PARTID.

    The reset behavior of this field is:

    - On a Warm reset, this field resets to an architecturally UNKNOWN value.

PhyPARTID26, bits [47:32]
:   Virtual PARTID Mapping Entry for virtual PARTID 26. PhyPARTID26 gives the mapping of virtual PARTID 26 to a physical PARTID.

    The reset behavior of this field is:

    - On a Warm reset, this field resets to an architecturally UNKNOWN value.

PhyPARTID25, bits [31:16]
:   Virtual PARTID Mapping Entry for virtual PARTID 25. PhyPARTID25 gives the mapping of virtual PARTID 25 to a physical PARTID.

    The reset behavior of this field is:

    - On a Warm reset, this field resets to an architecturally UNKNOWN value.

PhyPARTID24, bits [15:0]
:   Virtual PARTID Mapping Entry for virtual PARTID 24. PhyPARTID24 gives the mapping of virtual PARTID 24 to a physical PARTID.

    The reset behavior of this field is:

    - On a Warm reset, this field resets to an architecturally UNKNOWN value.
