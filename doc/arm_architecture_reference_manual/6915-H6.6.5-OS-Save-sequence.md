# ​H6.6.5 OS Save sequence

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H6-Debug-Reset-and-Powerdown-Support/-H6-6-Debug-OS-Save-and-Restore-sequences/-H6-6-5-OS-Save-sequence>

##### H6.6.5 OS Save sequence

To preserve the debug logic state over a powerdown, the state must be saved to nonvolatile storage. This means the OS Save sequence must:

1. Lock the OS Lock by:

   - Writing the key value `0xC5ACCE55` to the [DBGOSLAR](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-22-DBGOSLAR--Debug-OS-Lock-Access-Register?lang=en#reg_aarch32_dbgoslar) in AArch32 state.
   - Writing 1 to [OSLAR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-27-OSLAR-EL1--OS-Lock-Access-Register?lang=en#reg_aarch64_oslar_el1).OSLK in AArch64 state.
2. Execute an `ISB` instruction.
3. Walk through the debug registers listed in [Debug registers to save over powerdown](/documentation/ddi0487/mc/-Part-H-External-Debug/-Chapter-H6-Debug-Reset-and-Powerdown-Support/-H6-6-Debug-OS-Save-and-Restore-sequences/-H6-6-4-Debug-registers-to-save-over-powerdown?lang=en#chdchjga) and save the values to the nonvolatile storage.

If the [FEAT\_DoubleLock](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-1-The-Armv8-0-architecture-extension?lang=en#feat_feat_doublelock) is implemented, before removing power from the Core power domain, software must:

1. Lock the OS Double Lock by:

   - Writing 1 to [DBGOSDLR](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-20-DBGOSDLR--Debug-OS-Double-Lock-Register?lang=en#reg_aarch32_dbgosdlr).DLK in AArch32 state.
   - Writing 1 to [OSDLR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-23-OSDLR-EL1--OS-Double-Lock-Register?lang=en#reg_aarch64_osdlr_el1).DLK in AArch64 state.

   If [FEAT\_DoubleLock](/documentation/ddi0487/mc/-Part-A-Arm-Architecture-Introduction-and-Overview/-Chapter-A2-A-profile-Architecture-Extensions/-A2-2-Armv8-A-architecture-extensions/-A2-2-1-The-Armv8-0-architecture-extension?lang=en#feat_feat_doublelock) is not implemented, [OSDLR\_EL1](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-3-Debug-System-registers/-D24-3-23-OSDLR-EL1--OS-Double-Lock-Register?lang=en#reg_aarch64_osdlr_el1) and [DBGOSDLR](/documentation/ddi0487/mc/-Part-G-The-AArch32-System-Level-Architecture/-Chapter-G8-AArch32-System-Register-Descriptions/-G8-3-Debug-System-registers/-G8-3-20-DBGOSDLR--Debug-OS-Double-Lock-Register?lang=en#reg_aarch32_dbgosdlr) ignore writes.
2. Execute a [Context Synchronization event](/documentation/ddi0487/mc/-Part-K-Appendixes/Glossary?lang=en#babdjfhg).
