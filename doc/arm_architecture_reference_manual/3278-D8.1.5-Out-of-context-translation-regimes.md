# ​D8.1.5 Out-of-context translation regimes

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D8-The-AArch64-Virtual-Memory-System-Architecture/-D8-1-Address-translation/-D8-1-5-Out-of-context-translation-regimes>

##### D8.1.5 Out-of-context translation regimes

I PTDBT
:   Software is required to consider the effects on registers and translation tables when a context switch is made from one translation regime to another.

###### D8.1.5.1 Speculative memory accesses from out-of-context translation regimes

R FKCKH
:   A PE is not permitted to use the registers or TLB entries associated with an out-of-context translation regime to speculatively access memory or translation tables.

R NRJPP
:   If an implementation is executing at EL3 or EL2, the EL1&0 translation regime is out-of-context.

R FCZXS
:   If an implementation is executing at EL3, the EL2 and EL2&0 translation regimes are out-of-context.

R NXZKN
:   If an implementation is executing at any Exception level, the EL2, EL2&0, and EL1&0 translation regimes for Security states not selected by the Effective value of [SCR\_EL3](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D24-AArch64-System-Register-Descriptions/-D24-2-General-system-control-registers/-D24-2-168-SCR-EL3--Secure-Configuration-Register?lang=en#reg_aarch64_scr_el3).{NS, NSE} are out-of-context.

R LFHQG
:   When an exception to a higher Exception level occurs, memory accesses caused by the translation table walk for an out-of-context translation regime can continue speculatively after the higher Exception level is entered.

I QVPYJ
:   When an exception to a higher Exception level occurs, executing a [DSB](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-152-DSB?lang=en#isa_dsb) instruction that applies to both loads and stores after entering that higher Exception level ensures that memory accesses caused by a translation table walk for any out-of-context translation regime are completed.

I GFKHK
:   If the *Statistical Profiling Unit* (SPU) is not in use at a lower Exception level, when a [DSB](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-152-DSB?lang=en#isa_dsb) instruction is executed and completed after entering a higher Exception level, all of the following apply regarding memory accesses caused by speculative translation table walks from the lower Exception level:

    - All of the speculative memory accesses are observed as required by the Shareability and Cacheability attributes of the lower Exception level translation table entries.
    - If it is impossible to determine that the speculative memory accesses have been observed by the observers, then these speculative memory accesses can still occur.
    - No new memory accesses using the lower Exception level translation table entries occur.

I JZRDG
:   If the SPU is in use at a lower Exception level, when a [PSB](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-319-PSB?lang=en#isa_psb) instruction and a subsequent [DSB](/documentation/ddi0487/mc/-Part-C-The-AArch64-Instruction-Set/-Chapter-C6-A64-Base-Instruction-Descriptions/-C6-2-Alphabetical-list-of-A64-base-instructions/-C6-2-152-DSB?lang=en#isa_dsb) instruction are executed after entering a higher Exception level, all of the following apply regarding memory accesses caused by speculative translation table walks from a lower Exception level:

    - All of the speculative memory accesses are observed as required by the Shareability and Cacheability attributes of the lower Exception level translation table entries.
    - If it is impossible to determine that the speculative memory accesses have been observed by the observers, then these speculative memory accesses can still occur.
    - No new memory accesses using the lower Exception level translation table entries occur.

I MTHPL
:   For exceptions to the rules in this section when the Trace Buffer Unit is enabled, see [RSJFRQ](/documentation/ddi0487/mc/-Part-D-The-AArch64-System-Level-Architecture/-Chapter-D6-The-Trace-Buffer-Extension/-D6-3-Trace-buffer-Self-hosted-mode/-D6-3-1-Behavior-when-address-translation-is-enabled?lang=en#sjfrq).

###### D8.1.5.2 Register changes when changing virtual machine

I XHBRX
:   If EL2 is enabled, when a switch from one virtual machine to another occurs, software executing at EL0 or EL1 expects register fields controlling or affecting the EL1&0 regime are modified consistently before the next virtual machine starts execution.

I SFZVV
:   If the registers fields controlling or affecting the EL1&0 translation regime are modified when changing a virtual machine, then all of the following apply:

    - Software executing at EL2 does the modification.
    - The registers are modified out-of-context from software executing at EL1 or EL0.
    - When modifying the registers, no synchronization precautions are required until the exception return to EL1 or EL0.
