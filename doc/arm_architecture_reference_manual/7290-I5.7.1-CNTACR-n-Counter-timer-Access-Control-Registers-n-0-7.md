# ​I5.7.1 CNTACR<n>, Counter-timer Access Control Registers, n = 0 - 7

Source: <https://developer.arm.com/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-7-Generic-Timer-memory-mapped-register-descriptions/-I5-7-1-CNTACR-n---Counter-timer-Access-Control-Registers--n---0---7>

##### I5.7.1 CNTACR<n>, Counter-timer Access Control Registers, n = 0 - 7

The CNTACR<n> characteristics are:

Purpose
:   Provides top-level access controls for the elements of a timer frame. CNTACR<n> provides the controls for frame CNTBaseN.

    In addition to the CNTACR<n> control:

    - [CNTNSAR](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-7-Generic-Timer-memory-mapped-register-descriptions/-I5-7-9-CNTNSAR--Counter-timer-Non-secure-Access-Register?lang=en#reg_ext_cntnsar) controls whether CNTACR<n> is accessible by Non-secure accesses.
    - If frame CNTEL0BaseN is implemented, the [CNTEL0ACR](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-7-Generic-Timer-memory-mapped-register-descriptions/-I5-7-4-CNTEL0ACR--Counter-timer-EL0-Access-Control-Register?lang=en#reg_ext_cntel0acr) in frame CNTBaseN provides additional control of accesses to frame CNTEL0BaseN.

Configuration
:   It is IMPLEMENTATION DEFINED whether CNTACR<n> is implemented in the Core power domain or in the Debug power domain

    For more information, see [‘Power and reset domains for the system level implementation of the Generic Timer’](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I2-System-Level-Implementation-of-the-Generic-Timer/-I2-1-About-the-Generic-Timer-specification/-I2-1-1-Registers-in-the-system-level-implementation-of-the-Generic-Timer?lang=en#ceghaiaf).

    Implemented only if the value of [CNTTIDR](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-7-Generic-Timer-memory-mapped-register-descriptions/-I5-7-16-CNTTIDR--Counter-timer-Timer-ID-Register?lang=en#reg_ext_cnttidr).Frame<n> is 1.

    An implementation of the counters might not provide configurable access to some or all of the features. In this case, the associated field in the CNTACR<n> register is:

    - RAZ/WI if access is always denied.
    - RAO/WI if access is always permitted.

Attributes
:   CNTACR<n> is a 32-bit register.

###### Accessing CNTACR<n>

In a system that supports the Realm Management Extension, [CNTNSAR](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-7-Generic-Timer-memory-mapped-register-descriptions/-I5-7-9-CNTNSAR--Counter-timer-Non-secure-Access-Register?lang=en#reg_ext_cntnsar).NS<n> describes how these registers can be accessed by Root or Realm accesses.

In a system that recognizes two Security states:

- CNTACR<n> is always accessible by Secure accesses.
- [CNTNSAR](/documentation/ddi0487/mc/-Part-I-Memory-mapped-Components-of-the-Arm-Architecture/-Chapter-I5-External-System-Control-Register-Descriptions/-I5-7-Generic-Timer-memory-mapped-register-descriptions/-I5-7-9-CNTNSAR--Counter-timer-Non-secure-Access-Register?lang=en#reg_ext_cntnsar).NS<n> determines whether CNTACR<n> is accessible by Non-secure accesses.
