# TPS6594-Q1 board component

Apollo QVP의 I2C0에 TPS6594 SystemC 모델을 연결하고 Linux의 기존
`tps6594`, `tps6594-regulator`, `tps6594-pinctrl`, `tps6594-rtc` 드라이버를
사용한다. Register와 프로토콜의 기준은 [TI TPS6594-Q1 datasheet,
SLVSEA7B Rev. B](https://www.ti.com/lit/ds/symlink/tps6594-q1.pdf)다.
이번 보드 모델의 NVM 초기 설정은 검증용이며 특정 주문형 부품 번호의
전원 시퀀스를 재현한다는 의미는 아니다.

## 배선과 Linux 구성

| 항목 | 연결 |
| --- | --- |
| I2C | DW APB I2C0, base address `0x48`, page aliases `0x49–0x4c` |
| 기존 I2C0 장치 | EEPROM `0x50`, PCA9539 `0x74` |
| nINT | TPS6594 → SMD PL061 GPIO2, active-low, pull-up |
| GPIO loopback | Linux offset 0 → 1, 8 → 9 |
| BUCK1 시험 부하 | `regulator-output`, 900000 µV |
| LDO1 시험 부하 | `regulator-output`, 1800000 µV |

PMIC에 별도 AP MMIO를 할당하지 않는다. PL061은 기존 AP alias
`0x40750000`, GIC SPI 193 (INTID 225)를 사용한다. Linux IRQ 번호와
gpiochip/RTC 번호는 실행 시 탐색하며 고정하지 않는다.

Loopback 출력 0/8에는 외부 pull-up을 적용한다. 검증용 NVM 설정에서
GPIO edge interrupt는 모두 mask하고 RTC alarm interrupt를 사용한다.
현재 Linux pinctrl/GPIO driver는 GPIO edge IRQ 요청 경로를 제공하지 않는다.
CRC는 Linux I2C driver의 기본값인 비활성 상태로 검증한다.

검증용 NVM 초기값에서 LDO1–3 voltage selector는 `0x08` (600 mV),
LDO4는 `0x20` (1.2 V)다. LDO1은 Linux가 DT 제약에 맞춰 1.8 V로 변경한다.
이는 특정 부품의 NVM 기본값에 대한 주장이 아니라 QVP 보드 설정이다.
기존 PL031 RTC는 `rtc0` alias로 유지한다.

보드 배선은 [tps6594.lua](../../hsoc-stack/tools/qbox-platform/platforms/apollo/board/tps6594.lua),
Linux 설명은 [apollo-qvp-board.dtsi](../../hsoc-stack/components/primary_compute/linux/arch/arm64/boot/dts/arm/apollo-qvp-board.dtsi)에 있다.
모델 구현은 [tps6594.cc](../../hsoc-stack/tools/qbox/systemc-components/i2c/tps6594/src/tps6594.cc),
단위 시험은 [tps6594-tests.cc](../../hsoc-stack/tools/qbox/tests/components/i2c/tps6594-tests.cc),
guest 시험은 [verify_qbox_tps6594.sh](../../scripts/test/verify_qbox_tps6594.sh)에 있다.
Kernel 설정은 [apollo_qvp_defconfig](../../hsoc-stack/components/primary_compute/linux/arch/arm64/configs/apollo_qvp_defconfig)를 갱신했다.
QBox core/overlay CMake에 새 module target을 연결했으며 기존 Linux driver 소스는 수정하지 않았다.
BUCK1/LDO1의 `regulator-output` 노드는 기존 userspace consumer 드라이버를
통해 regulator API를 호출한다. 시스템 전원과 연결하지 않은 시험용 출력이다.

사용하는 kernel 옵션은 `MFD_TPS6594_I2C`, `REGULATOR_TPS6594`,
`REGULATOR_USERSPACE_CONSUMER`, `PINCTRL`, `PINCTRL_TPS6594`,
`RTC_DRV_TPS6594`다. PFSM·ESM 드라이버는 이번 검증에 포함하지 않는다.

## 재현

Workspace root에서 실행한다. 다른 QBox가 실행 중이면 기존 SSH port 사용
여부를 확인하고 launcher에 별도 `SSH_PORT`와 `--multi-session`을 지정한다.

```bash
./yocto_build.sh --keep-conf --bsp
./run_qbox_yocto.sh --bsp --headless --keep-running-after-pass \
  --timeout 600 --copy-disks --no-persistent-rse-state \
  --out-dir build/qbox-apollo-qvp/tps6594-runtime
```

`NEXIOS_BSP_INITRAMFS_READY` 이후 다른 터미널에서:

```bash
./scripts/run/ssh_run.sh scripts/test/verify_qbox_tps6594.sh
```

시험은 기존 driver binding을 확인하고 regulator on/off, GPIO loopback,
RTC 시간 설정·진행·alarm interrupt를 검사한다. RTC는 PMIC에 속한 장치만
선택한다. 실행 후 시험용 regulator 상태와 alarm을 정리한다.
전용 시험 guest에서 실행한다. PMIC RTC 시간을 guest 시스템 시간으로
설정하며 해당 RTC의 기존 alarm은 초기화한다.

| Kernel/DTB compile | PASS | `kernel-build.log`, 최종 BSP build |
| BSP rootfs | PASS | `bsp-rootfs.log` |
| BSP image build | PASS | `bsp-nvm-fix-build.log` |

| PCA9539/EEPROM shared-bus regression | PASS | `pca9539-regression.log` |
| TPS6594 after PCA9539 traffic | PASS | `guest-after-pca9539.log` |

실제 guest에서 I2C client `0-0048`이 `tps6594`에 bind됐고 GPIO 11개,
regulator 9개, `tps6594-rtc`를 확인했다. BUCK1은 900000 µV,
LDO1은 1800000 µV에서 각각 enable/disable을 확인했다. 나머지 7개
regulator는 등록과 읽기 interface를 확인했으며 개별 on/off 시험은 하지 않았다.

GPIO 0→1과 8→9에서 high=`1 1`, low=`0 0`을 읽었다. RTC 시간은
`1788852359→1788852361`로 진행했다. Alarm을 두 번 발생시켜 Linux alarm
IRQ 120의 counter `0→1→2`와 PL061 GPIO2 parent IRQ 33 증가를 확인했다.
PCA9539 시험 이후 TPS6594를 다시 시험하여 alarm counter `2→3→4`도
확인했다. 이 IRQ 번호는 이번 실행의 관측값이며 스크립트에서는 동적으로 찾는다.
Alarm clear와 regulator 초기 상태 복원도 PASS다.

첫 실행에서 LDO selector `0`이 유효하지 않아 regulator probe가 실패했다.
이를 유효한 QVP NVM 초기 selector로 수정하고 단위 시험·BSP·guest 시험을
다시 실행했다. 첫 실행의 PFDI/RPMsg marker 누락은 최종 실행에서 재현되지
않았으며 최종 boot gate는 통과했다. 초기 실패 증거도 보존했다.

DT schema 검사는 설치된 `dtschema` 버전 부족으로 실행하지 못했다.
전체 coverage audit는 `ap_9_1_1_memory_map: not_available`, `G1: not_run`으로
FAIL이다(`full-coverage-audit.json`). 따라서 위 PASS는 PMIC 기능 및 실행한
회귀 범위이며 전체 FVP 동등성 검증을 의미하지 않는다.

전압은 기능적 출력 값이며 아날로그 ripple·부하 과도 응답·전력 소모를
검증하지 않는다. NVM 프로그래밍, PFSM 전원 시퀀스, ESM, watchdog,
SPMI 다중 PMIC 동기화, SPI 접속, CRC wire protocol은 지원/검증 범위 밖이다.
Rail 출력은 `rail_enabled[0..8]`와 `rail_voltage_uv[0..8]`이며 순서는
BUCK1–5, LDO1–4다. Disable이면 물리 전압 출력은 0으로 표시한다.
